Broker 配置文件：`/home/busizeshi/docker/rocketmq/broker/conf/broker.conf`，关键项：
```
brokerIP1 = 192.168.1.14   # 对外注册地址，远程客户端依赖此地址连 Broker
```

> **重要修复记录（2026-08-21）**：
> 1. 原 Broker 以容器内网 IP（172.18.0.x）注册到 NameServer，导致开发机等远程客户端无法投递消息。已通过 `broker.conf` 设置 `brokerIP1=192.168.1.14` 并重建容器修复。
> 2. 清理了一个误启动的重复 Broker 容器（exciting_darwin，无挂载卷），它曾与正式 Broker 同时注册在同一集群，会造成消息路由到无持久化节点。
> 3. Dashboard 无法访问的根因：`apacherocketmq/rocketmq-dashboard:latest` 新版镜像容器内监听 **8082**，而 compose 映射的是 `8080:8080`（指向容器内不存在的端口）。已把映射改为 `8080:8082` 并重建容器，浏览器访问 `http://192.168.1.14:8080` 即可（无需登录）。

> **注意**：RocketMQ Dashboard 占用了服务器 **8080** 端口。fafa-java 在开发机本地使用 8080 无冲突；后续若把 fafa-java 部署到该服务器，需先停掉 Dashboard 或调整 fafa-java 端口。
