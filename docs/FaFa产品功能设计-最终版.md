## 〇、产品定位与核心原则

### 一句话定位

> **记录它的一生，也让 AI 记住它的一生。**

FaFa 不是宠物社区，不是宠物医疗平台，也不是单纯的「宠物版 ChatGPT」。它的核心是：

> **长期记录宠物数据 → 建立宠物数字档案 → AI 理解这些数据 → 帮助主人查询、分析、守护、回忆和创作。**

整个产品围绕一个核心资产展开：**一只宠物长期积累下来的私人数据**。随着使用时间增加，产品应该越来越「懂这只宠物」。

### 三条核心原则

1. **宠物是核心，不是社交关系**
   数据结构围绕「用户 → 宠物 → 宠物数据」展开，而非「用户 → 用户 → 社交关系」。用户上传的内容默认仅自己可见。

2. **AI 不是独立聊天页，而是贯穿所有页面的智能层**
   AI 是能力，不是一个孤立页面。用户在体重页、照片页、喂食页、报告页都能自然调用 AI。

3. **记录成本决定产品生死**
   任何每日记录 ≤2 次点击完成。数据密度取决于日活记录成本，记录越轻松，AI 越有价值，闭环越快。

### 产品边界（红线）

| 明确不做 | 原因 |
|----------|------|
| 社区/广场/动态/评论/点赞/关注/私信/附近宠友 | 产品定位排除，合规成本高 |
| 商城/电商/二手交易 | 非核心能力 |
| 在线问诊/AI 诊断/处方建议 | 医疗合规红线。AI 负责「数据分析」，兽医负责「医疗诊断」 |
| 智能硬件/IoT 联动 | 明确排除 |
| 宠物交易/领养/配种 | 非产品方向 |
| 寄养/上门服务撮合 | 涉及服务交易与社交属性 |
| 自动发布社交媒体内容 | 只生成内容，不负责发布，用户复制后自行发布 |

## 一、用户系统

### 1.1 登录

- 微信一键登录：小程序获取微信 code → 后端换取 openid → 登录
- 首次进入自动注册并返回，**不强制填写资料**
- 再次进入直接跳转主界面，不重复弹登录

### 1.2 用户信息管理

只记录必要信息：**昵称、手机号、性别、年龄、头像、城市**。

- 头像可上传；修改时必须清理上一张头像（数据库 + OSS 双清理）后重新上传

### 1.3 会员体系

会员是商业化的核心抓手，权益差异贯穿所有模块：

| 权益项 | 普通用户 | 会员用户 |
|--------|----------|----------|
| 宠物数量上限 | 2 只 | 不限 |
| OSS 存储空间 | 2 GB | 20 GB（后期可推按量存储包） |
| AI 语义检索 | 每月 10 次 | 不限 |
| 食品包装 AI 识别 | 每月 5 次 | 每月 50 次 |
| 报告/分享笔记生成 | 每月 3 次 | 每月 10 次 |
| 家庭协同成员 | —（第三批开放） | 多成员 |

**交互**：
- 触达限额时温和提示（如「本月 AI 检索次数已用完，升级会员解锁不限次」），不打断当前操作
- 存储空间不足时提前提醒，而非写满才报错
- 「我的」页常驻会员入口，展示当前权益与用量进度条

## 二、宠物档案

宠物档案是所有功能的数据基础，应逐渐成长为「宠物数字主页」而非静态表单。

### 2.1 宠物创建

记录字段：
- 宠物名称
- 宠物类型（猫 / 狗，其他类型复用猫的记录项配置）
- 宠物年龄（用户选「几年几个月」，**数据库外推出生日期**，后续自动计算年龄）
- 宠物性别
- 宠物照片（3 张）：1 张头像 + 1 张正面照 + 1 张侧面照
- 宠物品种（按猫/狗提供绝大多数品种供选择，也可手动输入）
- 是否绝育
- 到家时间

**关键后端逻辑**：
- 三张照片（头像/正面/侧面）用 **qwen3-vl-embedding** 嵌入，存入 **Qdrant**，用于后续素材的宠物个体识别
- 创建完成后，**自动以宠物名称为用户 tags 增加一个标签**，方便后期检索

**交互**：
- 首次创建只要求最少字段（名称+类型+性别+年龄+照片），几十秒完成
- 品种用「选择为主、输入为辅」的下拉 + 搜索组件
- 支持创建多只宠物，受会员数量上限约束

### 2.2 宠物编辑

- 所有字段可编辑
- 照片更新时，必须清理旧 OSS 数据 + Qdrant 向量，重新向量化存储
- 支持调整多只宠物的排序

### 2.3 宠物查询

- 列表查询 + 单宠详情查询
- 详情页即「宠物数字主页」：基础信息 + 最近动态 + AI 最近发现

### 2.4 宠物数字主页（详情页设计）

```
豆包
英短 · 公 · 3岁2个月 · 已绝育
5.2 kg · 来到你身边 873 天

──── 最近动态 ────
8月16日  体重 5.2kg
8月15日  上传照片 3 张
8月14日  完成驱虫

──── AI 最近发现 ────
最近 30 天体重基本稳定。
```

**交互**：主页顶部展示核心信息卡，下方时间轴式动态流，AI 发现卡片置顶突出，让用户一打开就有价值感。

## 三、素材管理（图片 / 视频）

### 3.1 上传

- 用户可选择已有 tag 打标签，或新建 tag（输入文字即可）
- 支持批量上传，**批量时复用同一组 tags**
- 上传后自动触发宠物个体识别：

> 将素材与用户各宠物创建时的三视图向量做相似度匹配，达到阈值则判定为该宠物的素材，并自动用宠物名称打 tag。

**交互**：
- 上传页顶部选 tags（多选 chips + 「新建标签」输入框）
- 批量上传时 tags 区只出现一次，应用到全部
- 识别结果以「疑似属于：豆包」形式展示，用户可确认或修正

### 3.2 检索

- 支持一段自然语言 + LLM 语义检索
- 可叠加确定性条件：宠物名称、tags、时间范围
- 普通检索不限次，AI 语义检索受会员次数限制

**交互**：
- 搜索框支持自然语言（如「找豆包去年夏天在阳台睡觉的照片」）
- 下方筛选 chips：宠物 / 标签 / 时间范围
- 结果按相关度 + 时间排序，返回照片 + 拍摄日期，并可附 AI 归纳（如「这些照片多拍摄于去年 7-8 月」）

### 3.3 存储与限额

- OSS 存储受会员空间限制，不足时提醒
- 检索也受限制（AI 检索次数）

## 四、日常记录系统（每日打卡）

这是产品最重要的数据来源，核心设计公理：**任何每日记录 ≤2 次点击完成**。

### 4.1 三类记录（不得混放）

| 类别 | 定义 | 例子 | 形态 |
|------|------|------|------|
| **状态观察** | 它表现如何 | 食欲、精神、饮水程度、便便质量 | 主观量表，一天一格，upsert |
| **照护动作** | 我做了什么 | 喂食、换水、给药、驱虫 | 事件流，几点几分发生 |
| **周期测量** | 精确数值 | 体重、克数、毫升 | 独立流程 + 温和提醒，绝不进每日打卡 |

### 4.2 记录维度

| 维度 | 形态 | 选项 | 核心价值 |
|------|------|------|---------|
| 食欲 | 量表 | 很好 / 正常 / 下降 / 拒食 | 几乎所有疾病的共同首发信号；猫拒食 >2 天有肝脂沉积风险 |
| 精神/活动 | 量表 | 活跃 / 正常 / 低迷 | 措辞必须是「比平时」而非绝对档位 |
| 饮水程度 | 量表 | 正常 / 偏多 / 偏少 / 没注意 | 猫多饮多尿 = 肾病/糖尿病/甲亢早期信号；必须有「没注意」逃生口 |
| 排便 | 量表 | 正常 / 偏软 / 腹泻 / 便秘 / 没看到 | 特权数据（每天铲屎/捡屎一目了然） |
| 呕吐 | 症状开关 | 无（默认）/ 一次 / 多次 | 拒食+呕吐 = 急症组合信号 |
| 排尿 | 症状开关 | 正常 / 异常 / 没看到 | 公猫排尿困难是按小时计的急症 |

**附加记录项**（非每日打卡，独立入口）：
- 体重
- 毛发健康程度
- 体型特征

**字段规则**：
- 食欲、饮水等可附**选填**的克数/毫升数
- 每个记录项后必须有**备注**，供用户补充信息

### 4.3 物种差异（配置，非两套代码）

| | 猫默认面 | 狗默认面 |
|--|---------|---------|
| 维度 | 食欲、精神、饮水（加权提示多饮多尿）、呕吐、排便、排尿 | 食欲、精神、排便、饮水、呕吐（排尿降权） |
| 依据 | 猫肾病/糖尿病早期信号靠多饮多尿捕捉；猫砂盆排尿可见 | 狗捡屎是每日特权数据；排尿观察难 |

按宠物类型配置不同记录项，主要为猫狗，其他复用猫配置。

### 4.4 关键交互

- **「同上次」按钮**：用户可看到上次记录，点击后直接复用上次的记录作为本次记录
- **「今天一切正常」一键完成**：95% 的日子是平淡的，必须让平淡日成本最低
- **漏记不惩罚**：漏一天标「未记录」，绝不做愧疚式 UI
- **记录提醒**：首页按记录项配置每日提醒和周期提醒，用户可自定义
- **记录检索**：支持确定性检索（宠物名称、时间范围、记录类型）+ AI 自然语言检索
- 记录可修改、可删除

### 4.5 自定义事件记录

用户可自定义想记录的其他事件（见第七章成长档案）。

### 4.6 数据模型建议

推荐新增 **daily_status 宽表**：一行 = 一宠物一天全维度，upsert 语义（当天可改）。喂食保留为动作日志，water_record 废弃并入。对 AI 侧是完美形态：查趋势 = 单表单列。

## 五、健康管理（新增模块）

这是市场调研中发现的最高价值缺口——医疗信息不对称是宠主最大痛点。本模块让「数据→AI→用户获益」闭环最直接兑现。

### 5.1 就医档案

**痛点**：宠物看病贵且不透明，宠主需要完整病史避免重复检查、辅助医生判断。

**功能**：
- 每次就诊记录：医院、医生、日期、主诉、诊断、处方、费用、票据照片
- 与事件记录打通——就诊是一种事件，但增加医疗专属字段
- 疫苗/驱虫记录自动归入就医档案时间线
- AI 辅助：上传检查报告照片 → OCR + LLM 提取结构化指标（血常规、生化等）

**交互**：
- 「记一次就诊」表单：医院/医生/日期/主诉/诊断/费用 + 票据拍照上传
- 就医档案时间线：按时间倒序展示所有就诊、疫苗、驱虫
- 检查报告上传后，AI 提取指标供用户确认，确认后存入

### 5.2 就诊摘要导出

**痛点**：宠主到院后想不起「它到底哪天开始不吃」「上次用的什么药」。

**功能**：就医前一键生成「近 N 天症状时间线 + 历史诊断 + 用药记录」，可复制/生成图片带给医生。

**交互**：
- 就医档案页顶部「生成就诊摘要」按钮
- 选择时间范围（近 7 天 / 近 30 天 / 自定义）
- AI 汇总打卡数据 + 就诊记录 + 用药记录，生成结构化摘要
- 支持复制文本 / 生成长图保存

**依赖**：AI Agent 数据查询能力（第二批）。

### 5.3 用药管理

**痛点**：慢性病需长期用药，宠主容易漏喂、重喂、记错剂量。

**功能**：
- 药品档案：名称、规格、用途、开始日期、疗程
- 用药计划：每日几次、每次剂量、饭前/饭后
- 用药提醒：接入现有提醒系统
- 用药记录：每次实际用药打卡（可合并到每日打卡）
- 与就医档案关联：处方 → 自动生成用药计划

**交互**：
- 「添加药品」→ 填写名称/剂量/频次 → 自动生成提醒
- 用药日历视图：展示每天该喂什么、喂没喂
- 从就诊档案的处方「一键生成用药计划」

### 5.4 健康预警引擎

**定位**：纯规则引擎先行，不依赖 AI，后续 AI 增强。

**规则示例**：
- 拒食 + 呕吐 → 红色：建议尽快就医
- 连续 2 天食欲下降 + 精神低迷 → 黄色提醒
- 猫饮水偏多 ≥3 天 → 提示查肾指标/血糖
- 腹泻 ≥2 天 / 呕吐多次 → 黄色提醒

**表述边界**：说「数据出现变化」，不说「宠物生病了」。AI 负责数据分析，兽医负责医疗诊断。

**交互**：预警以卡片形式出现在首页「AI 发现」区，红色预警强提醒（推送 + 首页置顶）。

## 六、食品与饮食

### 6.1 食品管理卡

- 每张食品管理卡挂在一个宠物下（如为某个猫条建一张卡）
- 记录：营养成分、品牌、价格、类型（主粮/罐头/零食/营养品/自制）、规格、开封日期等
- 可创建多张卡

### 6.2 AI 包装识别

- 上传食品包装/营养成分表图片 → AI 解析营养成分
- 用户确认后保存
- 受会员识别次数限制（普通 5 次/月，会员 50 次/月）
- 初期用科学公式计算，数据量足后考虑机器学习

### 6.3 食品安全评分（增强）

在包装识别基础上增加评分维度：
- 蛋白质来源是否清晰（鲜肉 vs 肉粉）
- 是否含争议添加剂（BHA/BHT/人工色素）
- 钙磷比是否合理
- 与宠物年龄/品种的适配度

**交互**：识别结果页展示「安全评分」雷达图 + 逐项说明，帮宠主看懂成分表。

### 6.4 换粮过渡记录

- 记录新旧粮比例、过渡天数、宠物反应（软便/拒食/正常）
- 与每日打卡的排便、食欲数据联动

### 6.5 喂食计划

- 将多张食品卡挂到宠物下，设置每种食品的喂食周期和喂食量
- AI 根据宠物信息（年龄/体重/品种/绝育/活动量）+ 营养成分，自动推荐喂食计划
- 估算每只宠物每日应摄取的各类营养量
- **用户是最终决策者**：可调整每日总量、次数、时间、每次数量、食品组合

**交互**：
- 「生成喂食计划」→ AI 给出建议方案（每日总量 + 分餐时间表）
- 用户可逐项调整后「接受计划」
- 接受后每天展示「今日计划」清单，可逐项勾选完成，与喂食记录打通

### 6.6 动态喂养分析

有历史数据后，分析实际喂食量与体重变化的关系，提示「可结合包装建议、活动量重新评估喂食量」，而非简单说「减少 10g」。

## 七、成长档案

### 7.1 事件记录

记录宠物的重要事件，类似小红书笔记：

```
第一次出门 / 去了宠物医院 / 换了猫粮 / 剪指甲
换了新的猫砂 / 搬家 / 第一次洗澡
```

- 每条事件支持：文字描述、素材、日期、标签
- 用户可自定义想记录的任何事件

### 7.2 向量化存储

- 以日期、宠物 id、标签作为 metadata
- 对文字记录和素材分别选择合适的嵌入模型向量化，存入 Qdrant

### 7.3 时间轴

- 前端维护时间轴，自动聚合所有内容（照片、日记、记录、事件、提醒完成）
- 用户无需手工维护，系统自动生成
- 可按时间浏览宠物的日常

**交互**：
```
2026年8月
8月17日  📷 上传了 4 张照片 「今天在阳台晒了一下午太阳」
8月14日  💊 完成本季度驱虫
8月10日  ⚖️ 体重 5.2kg
8月3日   🍚 更换新的猫粮
```

## 八、提醒系统

### 8.1 提醒类型

- 疫苗、驱虫、洗澡、剪指甲、体检、药物、生日、自定义提醒
- 记录项提醒（每日/周期，用户按记录项配置）
- 用药提醒（来自用药管理）

### 8.2 周期支持

```
一次性 / 每周 / 每月 / 每N天 / 每N个月 / 每年
```

### 8.3 完成闭环

- 点击「已完成」→ 自动生成一条事件记录 + 自动计算下一次时间
- **提醒系统与成长档案天然连接**

**交互**：首页「今日提醒」区展示待办，完成后划线并归档到时间轴。

## 九、养宠记账（新增模块）

**痛点**：单犬年均消费 3006 元、单猫 2085 元，但多数宠主对钱花在哪没概念。

### 9.1 功能

- 支出分类：食品 / 医疗 / 用品 / 美容 / 保险 / 其他
- 快速记账：金额 + 分类 + 备注（可选照片），≤3 秒完成
- 月度/年度统计：分类饼图 + 趋势折线
- 与就医档案联动：就诊费用自动归入医疗支出
- 与食品管理联动：食品购买可关联价格

### 9.2 交互

- 首页/我的页「记一笔」快捷入口
- 记账表单极简：金额大键盘 + 分类 chips + 备注
- 统计页：本月/本年支出总览 + 分类占比 + 趋势
- AI 年报素材：「今年你在豆包身上花了 XX 元，其中医疗占 XX%」

**为什么优先**：一张表 + CRUD + 统计，实现成本极低，但年底「花了多少钱养猫」的情绪价值很高，且为 AI 年报提供关键数据维度。

## 十、报告与内容创作

### 10.1 宠物报告（按周期）

- 周报：看最近发生了什么
- 月报：最核心
- 季度报告：看长期趋势
- 年度报告：数据价值 + 情绪价值 + 分享价值

**月报内容**：本月概览（记录天数/照片数/喂食次数/体重记录/完成提醒）+ 体重变化 + 饮食 + 饮水 + 排便 + 健康事件 + 成长记忆（本月代表照片）。

**AI 总结原则**：信息密度高于语言修饰。分「本月总体状态（一句话）/ 数据变化（2-4 个）/ 值得关注（最多 3 项）/ 下月提醒」。

### 10.2 分享笔记生成

- AI 根据用户的记录和素材生成图文并茂的分享笔记
- 可手动生成，也可周期生成（默认半月一次，周期可改）
- 受会员次数限制（普通 3 次/月，会员 10 次/月）
- **只生成，不负责发布**，用户复制/保存后自行发布

### 10.3 内容创作能力

- 小红书文案：选主题（成长记录/生日/第一次到家/月度总结/旅行/搞笑日常/纪念日/自定义）→ 读取宠物资料 + 最近照片 + 时间轴 + 数据 + 日记 → 生成标题/正文/Emoji/推荐话题
- 短视频文案：视频标题/描述/开场/字幕/结尾/话题
- 照片智能挑选：「帮我做一篇豆包三岁生日的小红书」→ 搜索过去三年照片 → 找关键时期 → 选代表照片 → 建议排列顺序

## 十一、AI 助手

### 11.1 入口形态

- **悬浮球**：各页面都能找到，点击唤起 AI 助手
- AI 助手主页统一入口：「问问关于豆包的任何事情」

### 11.2 动态推荐问题

主页不是空输入框，而是根据用户真实数据动态推荐：
```
豆包最近体重怎么样？
这个月吃了多少猫粮？
帮我找去年夏天在阳台的照片
这个月有什么值得注意的变化？
生成一份 8 月宠物月报
帮我写一篇豆包三岁生日的小红书
```

### 11.3 AI 助手记录信息

- 用户用自然语言记录（如「记录一下日常，今日饮食正常，精神正常」）
- AI 处理后返回相关信息 + 跳转页面 url
- 用户确认后跳转到对应页面，自行确认保存
- **最终确认保存必须由用户在对应页面完成**，AI 不越权直接写入

### 11.4 AI 助手生成分享笔记

- 直接调用分享笔记生成接口

### 11.5 图文并茂回答

- 根据用户不同类型的问题，自动返回图文并茂的回答

### 11.6 AI 数据查询工具链

Agent 可调用的工具：
```
getPetProfile / getWeightHistory / getFeedingHistory
getWaterHistory / getDefecationHistory / getEventHistory
getVaccineHistory / getDewormingHistory / searchPetPhotos
getFoodInfo / getReminderHistory / getPetReports
getMedicalHistory / getMedicationHistory / getExpenseHistory
```

AI 助手真正成为「宠物数据库的自然语言入口」。

## 十二、异常信息推送

- AI 不等用户主动问，系统周期性分析体重/饮食/饮水/排便/活动/事件
- 发现明显趋势后提示：
  > 最近 14 天平均每日喂食量比此前 14 天减少约 12%。
  > 最近一个月体重连续下降。
- **表述边界**：说「数据出现变化」，不说「宠物生病了」
- AI 负责数据分析，兽医负责医疗诊断

## 十三、家庭协同（第三批，新增）

**痛点**：多宠家庭、情侣/夫妻共养、请人代喂时，「谁喂了」「谁该驱虫了」信息不同步。

> 注意：这不是社交——没有公开动态、评论、点赞、陌生人发现。纯粹是私密家庭协作工具，类似共享日历/共享备忘录。

### 13.1 功能

- 宠物空间邀请：生成邀请码/链接，家人扫码加入
- 角色权限：主人（全部权限）/ 成员（记录+查看）/ 临时照护者（限时查看+记录）
- 操作留痕：每条记录标注「谁记的」，避免重复喂食
- 提醒共享：驱虫/疫苗提醒推送给所有成员
- 临时授权：出差时给宠物店/朋友开限时权限

### 13.2 架构影响

- 新增 pet_member 关联表（pet_id, user_id, role）
- 现有 Sa-Token 鉴权体系扩展
- 记录表增加 operator_id 字段
- **架构改动最大**，需用户基数支撑后再做

## 十四、应急信息卡（新增，低成本高价值）

- 可生成图片保存到手机，紧急时出示
- 成本极低，情绪价值高，可随时插入开发

## 十六、数据闭环（产品最核心逻辑）

```
                    用户
                     │
                     ↓
                  日常记录
                     │
     ┌───────────────┼───────────────┐
     ↓               ↓               ↓
   数据记录          照片            日记
     │               │               │
     └───────────────┼───────────────┘
                     ↓
               宠物数字档案
                     │
                     ↓
                 AI 理解层
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
      查询           分析           记忆
       │             │             │
       └─────────────┼─────────────┘
                     ↓
                个性化服务
                     │
       ┌─────────────┼─────────────┐
```

> **记录 → 数据 → AI 价值 → 用户获得收益 → 更愿意记录 → 数据越来越完整 → AI 越来越有价值。**

## 十七、三个核心竞争力

1. **宠物长期数据**：用户使用越久，数据越丰富。这是普通通用 AI 没有的。
2. **宠物长期记忆**：AI 不只知道「猫一般喜欢什么」，而是知道「豆包过去三年发生过什么」。
3. **AI 对私人数据的理解能力**：用户不用翻记录、翻照片、看表格、自己计算，直接问「豆包去年夏天是不是也瘦过一次？」
