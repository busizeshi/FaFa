## 2. 实现链路

1. 当前账号写锁 → 活动宠物主人校验 → 幂等创建回执 → StorageQuota.reserve → 会话同事务提交。
2. 独立签发短期 POST 表单，不将签名保存在通用幂等结果。限制对象键、MIME、精确字节数及原始期限；重新签发不续期。
3. 客户端向私有 bucket 的 staging 隔离区直传，不把业务 Bearer 发给对象存储。
4. 完成时重新锁账号、验宠物，HEAD 核验大小、有界读取、校验 SHA-256、真实图片格式和像素上限，保存正式原文件/PNG 预览，再同事务结算原文件字节并生成 READY 素材。
5. 正式对象从已核验的内存字节写入，不能被隔离区重传覆盖。只签 PNG 预览地址，不开放原始文件下载。预览重编码移除 EXIF；本批不按 EXIF 方向旋转，透明区域合成黑色背景。
6. 头像绑定要求同主人、同宠物、READY、活动状态与宠物 version；引用替换及宠物版本同事务更新，旧媒体保留。
7. 重复 complete 按 sessionId 幂等，只结算一次。对象写成功但数据库失败，原会话可重试，到期未完成则清理遗留正式对象。
8. 取消/失败不立即释放预占：签名未到期仍能重传。到期后清理 staging，非 READY 再清遗留正式对象，确认删除后释放预占。失败保留 cleaned=false 待重试；READY 只清 staging、不释放已用额度。
9. 清理每轮最多 50 项，多实例通过用户行锁和 cleaned 防重。默认图片 20 MiB、1600 万像素、预览最长边 1024、上传 300 秒、预览访问 60 秒；预览成本为平台开销。
10. 单图处理在受限 HTTP 链路中执行，SDK 单次调用总超时 15 秒；没有在 HTTP 内转码视频，也没有使用不持久化的内存异步任务。后续根据处理耗时及并发指标决定图片任务异步化。

## 3. 环境与配置

docs/nacos/fafa-biz.properties 已新增 fafa.media.*，远端 Nacos 尚未发布。

| 环境变量 | 用途 |
|---|---|
| FAFA_MEDIA_ENDPOINT | 服务端存储地址 |
| FAFA_MEDIA_PUBLIC_ENDPOINT | API 客户端/安卓可访问的签名地址；省略沿用服务端地址，不能填客户端不可解析的 Docker 主机名 |
| FAFA_MEDIA_BUCKET | 默认 fafa-media，须预先创建独立私有桶 |
| FAFA_MEDIA_ACCESS_KEY / FAFA_MEDIA_SECRET_KEY | 应用专用最小权限账号，通过运行环境注入，无默认值 |

生产必须 TLS、禁止匿名访问。应用账号仅授权本桶 staging/private，不使用 root。隔离区应有生命周期兜底；正式对象不能配置随意过期策略。若启用版本控制，须另配历史版本清理与计量；本批只清当前对象，不承诺清除历史版本。已签访问 URL 有最长 60 秒撤权窗口。

本批执行图片格式/像素核验，未接独立杀毒引擎，不宣称已完成病毒扫描。Compose 模板固定 MinIO 为现有记录对应 RELEASE，管理凭证改为必填环境变量；未重建现有服务器 MinIO，不改 FileHub bucket/密码。原中间件记录中的开发凭证仍需按受控密钥迁移安排处理。

## 4. 验证与重跑

本地在 fafa-java 执行 mvnw.cmd -q verify；根目录执行：
- python -X utf8 deploy/verification/export_contracts.py
- python -X utf8 deploy/verification/document_api.py
- python -X utf8 deploy/verification/check_api_docs.py
- git diff --check

真实依赖：设置 FAFA_VERIFY_DB_HOST、FAFA_VERIFY_DB_ROOT_PASSWORD、FAFA_MEDIA_TEST_ENDPOINT、FAFA_MEDIA_TEST_ACCESS_KEY、FAFA_MEDIA_TEST_SECRET_KEY，执行 python -X utf8 deploy/verification/verify_wp04.py。

脚本只创建固定白名单库 fafa_wp04_biz_suite 与专用验收账号，不删除库、不覆盖共享旧库；重跑会轮换本测试账号密码。套件会清理该 schema 内的测试表，因此严禁放入真实业务数据。存储测试只创建随机前缀 fafa-wp04-* / fafa-live-* 测试桶，finally 删除本次对象/桶，不清其他桶。

验证分层：
- 本地 H2/MockMvc/替身存储：创建幂等、并发完成、越权、格式/摘要错误、超限/额度不足、对象写故障重试、取消清理失败及重试。
- 真实 MySQL：独立库重跑同一媒体事务套件，覆盖原生约束、锁、时间映射。
- 真实 MinIO：POST 签名上传、读取、匿名 403、签名下载、删除；组合真实 MySQL/MinIO 的 HTTP 用例验证服务端核验与额度结算。
- HTTP 仍使用 MockMvc；移动会话和邮件为测试适配器，不代表真实 Gateway、Redis、SMTP 或安卓验收。
- 原始日志与结果保留在 Git 忽略的 fafa-java/target/wp04-verification；脱敏汇总放入 docs/dev/验收记录。

## 6. 实现依据

[MinIO Java SDK 官方 API](https://github.com/minio/minio-java/blob/master/docs/API.md)：POST Policy、签名访问、有界对象操作。SDK 固定 8.6.0；部署镜像沿用已验收的 MinIO RELEASE，不通过浮动 latest 重建。

过期判断使用 expiresAt：即使扫描尚未把 INITIATED 改为 EXPIRED，到期后也拒绝签名和完成。创建幂等重放是原始回执，实时状态必须用查询接口读取。

对象存储上传示例（参数必须取自本次 upload-policy 的 formFields；file 字段最后，以下变量不是真实凭证）：

~~~bash
curl -X POST "$UPLOAD_URL" -F "key=$OBJECT_KEY" -F "Content-Type=image/png" -F "policy=$POLICY" -F "x-amz-algorithm=$ALGORITHM" -F "x-amz-credential=$CREDENTIAL" -F "x-amz-date=$SIGN_DATE" -F "x-amz-signature=$SIGNATURE" -F "file=@cat.png"
~~~

最终结果：完整 Maven verify 共 47 项，45 项通过、2 项真实 MinIO 条件测试在本地跳过；真实 MySQL/MinIO 定向验收 8 项通过；最终媒体 HTTP/APP 契约 7 项回归通过；49 个业务接口文档校验通过。脱敏结果见[WP04-A-2026-10-22.json](验收记录/WP04-A-2026-10-22.json)。
