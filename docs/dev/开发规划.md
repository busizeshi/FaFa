### 1.2 产品定位与首期用户

服务猫狗主人和共同照护者，解决“今天谁喂过了、下次何时照护、资料在哪里、这段时间有什么变化”。首期不做交易平台、兽医诊断或设备平台。

用户价值闭环：

1. 记录一次真实照护，保留操作者、时间、来源和素材。
2. 家人能看到同一事实，减少重复喂食和遗漏。
3. 用户确认的计划生成可处理待办，通知只负责提醒。
4. 历史可以按宠物、日期、类型和图片描述找回。
5. AI 基于已有资料整理草稿和报告，原始记录随时可查。

### 1.3 分期不等于删需求

| 阶段 | 必须交付 | 进入下一阶段的条件 |
|---|---|---|
| P0 基础闭环 | 邮箱账号、宠物、全部基础记录、食品卡与手动喂食计划、笔记、简单自定义类型、待办与提醒、私密相册、个人设置、额度与管理端基础运营、数据导出/删除 | 不启用 AI 也能正常使用；权限、重复提交、提醒时区和删除测试通过 |
| P1 共同照护与 AI | 家庭权限、临时照护、AI 问答/草稿、包装识别、语义相册、成长小记、结构化报告与周期计划 | 数据隔离、用户确认、用量结算、失败恢复和引用核对通过 |
| P2 社区 | 关注/发现、发帖、互动、搜索、举报/审核/申诉、AI 辅助帖子 | 有实际审核运营人和治理后台；完成渠道审核要求核对 |
| P3 实验能力 | 3D 形象、Unity 互动和可下载动作资源 | 独立验证性能、生成效果、资源安全和成本后再承诺上线 |

P0 可按第 20 章继续拆小里程碑，不能为了“一次做全”同时启动所有模块。社区私信、机器学习推荐、任意 HTML 报告模板不放入首期。

## 2. 对原方案的调整与理由

下表中的“采用”是本规划建议执行的默认设计；涉及商业或地区的事项另列第 21 章，不在实现时自行扩展。

| 原设想或冲突 | 采用的方案 | 理由与实现影响 |
|---|---|---|
| 每个模块可能拆微服务 | 三个 Java 应用加一个 Python 应用；Biz 内按领域分包 | 已有工程可复用，避免跨服务事务、环境和 RPC 膨胀；数据所有权先清楚再考虑拆分 |
| 首次建档头像、性别、品种、年龄均必填 | 必填昵称和物种；照片、品种、性别、生日可后补；支持“未知/混种” | 降低首次使用成本，避免用户猜填；猫狗之外可保存 OTHER 基础资料，关闭猫狗专属计算 |
| 三视图作为第二个建档步骤 | 建档完成后提供“补充照片”，三视图为可选资料 | 记录功能不依赖未来 3D；首次只用系统选图，后续可复用自己有权使用的素材 |
| 归档 15 天后自动删除 | 归档长期保留；明确“申请删除”才进入 15 天等待期 | 归档是收起历史，不是销毁；拆出 ACTIVE、ARCHIVED、DELETION_PENDING 状态 |
| 原型删除页称不可恢复 | 改为展示删除范围、恢复截止时间、归档替代 | 15 天等待期内可撤销；实际清理开始后不能承诺恢复 |
| 相册默认公开 | 全部素材和相册默认私密；公开通过独立帖子发布 | 防止新增照片意外进入社区；相册是整理容器，帖子是经过审核的发布快照 |
| 删除相册连带删除照片 | 只移除相册及成员关系，照片留在“全部素材” | 与 Pen G12 当前文案一致，也避免误删其他记录的附件；永久删除素材是另一操作 |
| 照片必须先选相册 | 未选相册进入“全部素材”；相册和标题可选 | 减少上传步骤；系统生成展示标题，用户随时补充 |
| 家庭成员可写即能删除所有内容 | VIEWER / CONTRIBUTOR 加资料范围；贡献者只改自己的记录 | 主人保留宠物、计划、食品卡、他人内容的管理权；权限不是简单布尔值 |
| 首页“复用昨日”可直接记今天 | “按上次填写”只打开预填草稿，确认后保存 | 复制事实容易造成虚假健康数据；体重、医疗数值不复用，30 天限制见第 9 章 |
| 一个定时任务对应一个提醒 | 一个扫描器推进所有规则与实例 | 数据驱动，比创建海量 PowerJob 任务更容易编辑、撤销和排错 |
| 提醒发出就算完成 | 规则、待办实例、通知投递、实际记录四层分开 | 发通知不代表用户做了事；两人完成同一实例时只允许一人成功 |
| Chat 用 ReAct 但每轮一次模型调用 | Chat 以只读检索回答为主；复杂问题允许受限工具循环 | ReAct 可能有多次模型调用；用步数、时间、Token 上限约束，不做不成立的“一次”保证 |
| 全部业务查询都套 MCP | Biz 内部 HTTP 为稳定契约；Python 本地工具适配这些契约 | MCP 是可选工具协议，不承担业务授权和数据库写入；首期少一个运行组件 |
| 报告照搬通用编程 Agent harness | Java 确定性统计 + Python 结构化叙述 + 固定模板渲染 | 更可测试、更便宜，禁止执行模型生成的程序或任意网页代码 |
| Qdrant 同时做精准检索、聚类和推荐 | MySQL 做过滤/关系/首期文本搜索；Qdrant 只做语义召回 | 向量库不替代事务库和社区排序器；首期用时间游标流和简单话题热度 |
| 自动每周生成成长时间线 | 主人开启后生成待确认周小记；无新事实不生成 | 节约额度，避免编造；用户确认后才成为正式成长条目 |
| 用 Token 直接当用户积分 | 模型实际 Token 记成本账，用户点数按版本化规则扣费 | 不同模型与图片/语音计费口径不同；用户看到预计点数和实际消费 |
| 为审核把社区藏在二级入口 | 社区按真实成熟度分期，提交审核时如实披露 | 入口层级不能替代治理，也不作为规避审核方案 |
| 直接发邮件附件导出所有资料 | 邮件通知导出完成，登录后领取短时下载地址 | 大附件不可靠且易泄露；下载前重新验证身份和资源权限 |

参考取舍：11pets 官方强调记录、照护提醒和资料共享；DogLog 官方围绕家庭协同记录活动展开。本文据此优先解决家庭事实同步，**不是**对这些产品完成了实机体验或认定其方案适用于全部用户。[11pets 功能](https://www.11pets.com/en/feature)、[DogLog](https://www.doglogapp.com/)。

### 3.3 原型缺页与明确补齐项

以下不是已存在页面，接口的消费方用拟定 pageKey 标注：

- nutrition.foods / foodEdit / plans / planEdit / calculator：食品卡、计划、计算器；从喂食类型页进入，不另加一级 Tab。
- care.expenses / expenseEdit：花费列表、汇总与记录；从记录分类进入。
- reminder.edit / detail：新建规则、重复规则预览、实例详情和延期。

### 4.3 Biz 领域模块

保留现有七个包，按真实需求增加 nutrition、journal、ai、report、usage；home、inbox 是查询组合和通知模块。未到相应阶段不先生成全部空类。

| 模块 | 事实所有权 | 同步依赖 / 通知 |
|---|---|---|
| identity | 账号、认证挑战、资料、用户偏好、同意记录 | 供其他模块读取用户状态；不反向依赖宠物 |

| report | 报告配置、来源清单、版本、导出任务 | 调用各领域只读查询、media、usage；不反向修改事实 |

授权公共门面由 sharing.application 暴露 AccessPolicy；它只依赖用户状态、pet 的 PetOwnershipQuery 和授权表。pet 的基础所有权查询不再调用 AccessPolicy，避免 pet ↔ sharing 循环。媒体领域只接收已校验的 attach/detach 命令及引用标识，不回调 care 查权限。

DDD 四层：interfaces 适配 HTTP/RPC，application 编排与事务，domain 规则与值对象，infrastructure 存储和外部服务。跨领域调用 application 的窄接口，禁止跨模块 Repository 和表写入。首期同一数据库事务可跨应用服务，但事务协调放用例层，不藏在 MQ 或多个 Controller 中。

该做法借鉴 Spring Modulith 的显式模块边界思想，不要求立刻引入整套框架；真实模块成形后用架构测试检查循环依赖。[Spring Modulith fundamentals](https://docs.spring.io/spring-modulith/reference/fundamentals.html)。

### 4.4 什么时候才拆更多微服务

有独立扩缩容压力、独立团队和发布周期、明确故障隔离需求，并已经能证明数据归属与跨服务一致性时再拆。优先候选是媒体处理 Worker、报告 Worker、公开社区；不按页面数或表数拆服务。拆分顺序：公开应用接口 → 独立存储所有权 → 事件契约 → 双读核对/迁移 → 切换流量。

## 5. 所有功能共用的接口和前端契约

### 5.1 路径与兼容迁移

新业务对外统一：

- APP：/api/v1/** → Biz /v1/**。
- 管理端：/api/admin/v1/** → Admin /v1/**。
- 内部 Java API：/internal/v1/**；Python：/internal/ai/v1/**，不经公网 Gateway。
- 私人分享：/s/{opaqueToken} 进入轻量 H5；取内容仍调用受限分享 API。

现有 Gateway 使用 /api/biz/**、/api/admin/**、/api/ai/** 且 stripPrefix(2)，Python 健康路由为 /api/v1/health。上述统一路径是**需要实施的路由变更**：新增明确 v1 路由并按正确前缀转发；保留现有健康检查供开发使用，生产只暴露最小探活。APP 业务流量不再经 /api/ai 直接抵达 Python，旧路由必须在上线前限制为内网或移除。不要通过多个同名 api 前缀凑合路径。

### 5.2 请求、响应与错误

~~~json
{
  "code": "0",
  "message": "OK",
  "data": {
    "items": [],
    "nextCursor": null,
    "hasMore": false
  },
  "requestId": "req_example"
}
~~~

- 沿用现有响应包装 R：code 为字符串，成功为 "0"；HTTP 状态和业务 code 同时准确表达，不把所有异常包装成 200。
- 字段 camelCase；ID 对外用字符串；金额、体重、克数等十进制量用十进制字符串，服务端用 BigDecimal / Decimal，禁止浮点直接记账。
- 时间点 RFC3339 带偏移或 Z；数据库存 UTC DATETIME(6)。仅日期用 YYYY-MM-DD，另存所属 IANA 时区；不能把生日变成 UTC 午夜时间戳。
- 列表游标以 occurredAt/createdAt + id 稳定排序，默认 20、上限 100；游标绑定筛选条件。Admin 可用 page/size；APP 不强依赖每次 COUNT(*)。
- 所有写入取服务端认证身份，忽略或拒绝客户端 ownerUserId、createdBy、billToUserId。
- 详情返回 version；PATCH 和状态转换提交 version，冲突 409 并提供最新版本；不做静默覆盖。
- 跨资源不存在或无权读取统一 404；已知协作资源但缺操作能力返回 403，避免通过 ID 探测资料。

| HTTP | code 示例 | APP 处理 |
|---|---|---|
| 400/422 | VALIDATION_ERROR / FIELD_REQUIRED | 定位 fieldErrors，保留其他输入 |
| 401 | AUTH_REQUIRED / SESSION_REPLACED | 登录/提示另一设备登录；恢复原目标，草稿仍留在原账号空间 |
| 403 | CAPABILITY_DENIED / AI_CONSENT_REQUIRED | 说明缺少哪项已知权限，提供申请或设置入口 |
| 404 | RESOURCE_NOT_FOUND | 返回列表并刷新，不泄露资源归属 |
| 409 | VERSION_CONFLICT / TASK_ALREADY_COMPLETED / IDEMPOTENCY_CONFLICT | 显示最新结果或让用户核对，禁止无限重试 |
| 410 | SHARE_EXPIRED / CHALLENGE_EXPIRED | 失效说明、重新申请 |
| 422 | QUOTA_INSUFFICIENT | 显示所需/剩余额度及申请入口，停止提交 |
| 429 | RATE_LIMITED | 按 Retry-After 倒计时 |
| 502/503/504 | DEPENDENCY_UNAVAILABLE / AI_TIMEOUT | 保留草稿；有任务 ID 时查原任务，不重复新建 |

错误 data 使用 fieldErrors[{field,code,message}] 或 resource/action/currentVersion 等安全字段，不能返回 SQL、堆栈、供应商原始密钥错误。

### 5.3 幂等、并发与草稿

创建记录、完成待办、上传初始化、AI run、确认草稿、发帖、额度调整均要求 Idempotency-Key。服务端保存 actorId + operation + key + requestHash + response，唯一索引兜底；相同键不同请求返回 409。普通业务键保存至少 24 小时，任务确认和账务依靠持久唯一业务键长期防重。成功结果丢失后重放原响应；执行中返回原资源 ID 和进行中状态。

APP 本地草稿按 userId + petId + formType + draftId 隔离；登录其他账号不能读到旧草稿。保存按钮禁止连点只是交互优化，不替代服务端幂等。离开页面提供继续编辑、保存本地草稿、放弃；云端成功后才删除本地草稿。

P0 支持弱网保留与重试，不承诺完整离线多端同步。离线保存显示“待提交”，不出现云端已完成标记。

### 5.4 当前宠物和路由上下文

bootstrap 返回当前账号、偏好、可用功能、当前宠物候选和有效权限。APP 维护唯一 currentPetId；默认宠物偏好和本次切换分开：切换不必每次修改服务端默认值。每个表单锁定自己的 petId，不能在后台切换全局宠物后悄悄改归属。

归档/删除/授权撤回使当前宠物失效时，优先选择有权访问的活跃默认宠物，再选列表第一只，无候选进入无宠物状态。只有协作宠物也可以完整进入首页；不强迫创建自己的宠物。

详情深链接使用资源类型和 ID，例如 /pets/{id}/records/{recordId}；打开时重验权限。API 返回 nextActions/capabilities 帮助 APP 展示可用操作，但服务端每次仍校验。

## 6. 数据模型、所有权与授权

### 6.1 统一字段和数据库规则

所有业务实体具备 id、createdAt、updatedAt、version；可审计内容具备 ownerUserId、createdBy、updatedBy。petId 指宠物，ownerUserId 指资料空间的主人，createdBy 指实际操作者，三者不能混用。协作者新增记录/媒体属于主人的宠物空间，并保留作者。

MySQL 是权威业务库；Redis 只做会话、短期挑战、限流和可重建缓存；Qdrant 只存可重建索引；OSS 存文件。业务库迁移用 Flyway 版本脚本，新环境从空库可构建；不手工改表再补 ORM。

| 聚合/表族 | 核心字段与约束 | 主要索引 |

| auth_challenge、user_session | purpose、target、codeHash、expiresAt、attempts、consumedAt；会话代际 | challengeId；userId+deviceClass |

### 6.3 权限模型

授权以宠物为单位，不建设多层组织、团队、租户和家庭主账号体系。“家庭”是一个主人管理的宠物授权集合，成员接受邀请后按宠物和资料范围生效。

| 能力 | OWNER | VIEWER | CONTRIBUTOR |
|---|---|---|---|
| 查看宠物基础摘要 | 是 | 是 | 是 |
| 修改档案、归档、删除、邀请成员 | 是 | 否 | 否 |
| 查看已授权记录/媒体/计划 | 是 | 是 | 是 |
| 新增已授权类型记录和上传媒体 | 是 | 否 | 是 |
| 编辑/删除自己创建的记录 | 是 | 否 | 是，且当前授权仍有效 |
| 编辑/删除主人或其他成员记录 | 是 | 否 | 否 |
| 修改食品卡、喂食计划、提醒规则 | 是 | 否 | 否 |
| 完成已授权待办 | 是 | 否 | 是，产生真实记录时仍按记录权限校验 |
| 修改他人素材元数据/永久删除素材 | 是 | 否 | 否 |
| 管理相册容器、公开发帖、导出全部档案 | 是 | 否 | 否 |
| AI 查询 | 本人已同意 | 主人允许 AI 处理共享资料且本人同意 | 同左；写入只限自身贡献能力 |

scopes 首期枚举：DAILY_CARE、HEALTH_CARE、MEDIA、FEEDING_PLAN_VIEW、TASKS。花费、私人笔记、报告与完整档案导出默认不共享，首期不给泛化“全资料”权限。DAILY_CARE 包含喂食、饮水、日常观察、洗护和主人主动开放的自定义类型；不包括疫苗、用药、就医。

每次访问先检查账号、宠物状态、有效授权，再检查资源所属宠物与操作能力；AI 工具和向量搜索同样适用。撤权后提高 grantVersion，使缓存和未完成 AI 授权失效；正在执行的写入在提交前锁定/重验授权。已签名 OSS 链接不能凭空立即作废，首期私有下载有效期建议 60 秒，撤权窗口需在 UI/隐私说明中如实表达；严格即时撤回场景走鉴权代理。

用户 A 可访问 petA 并不代表可以读取任意 recordId 或 mediaId；要验证资源本身归属。此规则对应 OWASP 对对象级授权漏洞的要求。[OWASP API1](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)。

## 7. 账号、首次使用与用户中心

### 7.1 邮箱账号的完整链路

采用邮箱加密码登录、邮箱验证码注册/找回，保留 Sa-Token 单设备登录要求。APP 同类移动会话只能一个，Admin 身份独立，不能互踢。家庭成员各用自己的账号，不能通过共享密码协作。

1. 匿名可读取用户协议/隐私政策的当前版本和历史版本，不预勾选同意。
2. 注册表单校验邮箱、两次密码和协议版本；密码默认 8—128 个字符且包含字母数字，允许粘贴、密码管理器和 Unicode，不截断密码。原需求“超过 8”与页面“至少 8”统一为**至少 8**。
3. 申请 REGISTER challenge 时提交邮箱；服务端限流并发送验证码，不立即创建正式用户，不持久化明文密码。密码留在 APP 内存，验证阶段提交。
4. 验证接口提交 challengeId、验证码、邮箱、密码、确认同意的文档版本，重新校验后在事务中消费 challenge 并创建唯一账号；冲突按唯一索引处理。
5. 生成“铲屎官 + 4 位随机后缀”昵称；昵称允许重复，userId 与规范化邮箱唯一。
6. 创建会话，bootstrap → 可跳过的简短功能介绍 → 可选建档 → 首页。功能介绍可关闭且可在帮助中重看，不强制逐页滑完。

邮箱去除首尾空白、域名小写；本产品账号查询使用大小写不敏感的规范化邮箱，保留原始展示值；不删除 Gmail 点号或加号后缀。SMTP 由 MailSender 适配，替换 DirectMail 时不改领域用例；发送失败不能显示已发送。

验证码基线：6 位数字、10 分钟有效、60 秒重发间隔、单 challenge 最多 5 次尝试；按邮箱/IP/设备设置速率与日配额，值进入服务端策略配置。purpose 隔离 REGISTER、RESET_PASSWORD、VERIFY_OLD_EMAIL、VERIFY_NEW_EMAIL、DELETE_ACCOUNT；旧码重发后失效；只保存服务端密钥参与的 HMAC，不记明文日志。校验、失败计数和一次消费必须原子化。

密码使用经评估的 Argon2id 实现、随机盐与可升级参数，不用 MD5、SHA256 直接存密码。找回密码始终返回一致的申请提示；验证后签发仅能重置密码的短时 resetTicket，不作为普通登录 Token。重置/修改成功使全部旧会话和未完成敏感验证失效，要求重新登录。[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

### 7.2 单设备会话

登录成功在 Redis/Sa-Token 原子替换该用户移动会话代际。旧设备下次请求返回 SESSION_REPLACED，并显示“账号已在另一设备登录”；可主动通知，但不能只靠推送踢人。上传中的旧凭证最多按其短有效期存在，完成业务绑定时仍需有效登录；登录失效不能提交旧 AI 草稿。

Token 放移动安全存储；Admin Web 优先 HttpOnly Secure Cookie 并设置 CSRF 防护，不把后台长期 Token 存普通 localStorage。设备显示来自已登记信息，不根据 IP 猜测并展示确定的所在城市。

### 7.3 修改资料与敏感操作

| 功能 | 规则与实现 |
|---|---|
| 昵称/签名/头像 | 昵称 1—30、签名 0—150 字符；头像先上传再关联；公开主页只展示明确公开字段 |
| 默认宠物 | 只能设为当前可访问的活跃宠物，协作宠物也可；失权后自动清空 |
| 修改邮箱 | 先当前密码或旧邮箱验证取得 reauthTicket，再验证新邮箱；事务中检查唯一性并替换；通知旧邮箱并撤销旧会话 |
| 修改密码 | 校验当前密码，两次新密码一致、不能与当前相同；P0 不做模糊的“最近用过”密码历史，页面文案同步 |
| 时区 | IANA 标识，例如 Asia/Hong_Kong；修改个人显示时区不自动迁移已有计划时区，提供单独预览/确认 |
| AI 隐私 | 分开配置 PERSONAL_CONTEXT、MEDIA_INDEX、PACKAGING_OCR、SCHEDULED_SUMMARY、HISTORY_RETENTION；关闭后不影响手动功能 |
| 反馈 | 300 字正文、可选截图、可查看处理状态和站内回复；普通反馈不能充当医疗咨询 |
| 用量 | 展示账户额度、已用、预占、剩余、周期、账单规则版本；余额更新以服务端为准 |

隐私政策需覆盖实际数据流、第三方处理商、保存期、删除和撤回入口；中国内地上线以适用法律及实际部署核对，不把“勾选同意”当作所有处理的通行证。最小必要和删除/撤回设计参考[《个人信息保护法》官方文本](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2022/art_04a0f1fb5df244e39688fd5372623a8d.html)；本节是工程约束，不等于已完成法律审查。

### 7.4 导出与账号注销

导出链路：重新验证身份 → 创建 DATA_EXPORT job → 冻结数据范围快照 → 生成 JSON/CSV/Markdown 和附件清单（需要原文件时分卷 ZIP）→ OSS 私有文件 → 信箱/邮件通知 → 登录后签发短时下载。导出任务有可配置有效期，超期清理；协作者不能导出主人完整空间。

账号注销与宠物删除分开：重新验证 → 读取影响清单 → 提交 → DELETION_PENDING，默认 15 天等待期 → 到期锁定为 PURGING → 分批清理 → DELETED。等待期只允许受限登录查看进度、导出和撤回，不能继续创建新业务；用户登录不等于自动撤回，必须明确点击撤回。注销撤销全部家庭授权、分享链接和有效会话，停止周期任务。

清理顺序与失败恢复见第 17 章。保留账务/安全日志时最小化、去标识化并明确保存政策；备份有固定滚动保留期，恢复备份后必须重放删除墓碑，防止已删除资料复活。

## 8. 宠物与成长时间线

### 8.1 档案字段

| 字段 | 规则 |
|---|---|
| nickname | 必填，1—30 字符，可重复 |
| species | CAT / DOG / OTHER，必填；OTHER 不支持猫狗营养计算 |
| avatarMediaId | 可选，自己上传或有权使用的媒体，不能填任意外链 |
| breedId | 服务端字典，与 species 一致；允许 UNKNOWN / MIXED；停用品种不影响旧档案显示 |
| sex / neuteredStatus | MALE / FEMALE / UNKNOWN；YES / NO / UNKNOWN，不强迫猜测 |
| birthDate 或 estimatedBirthMonth | 精确生日、估算出生月份二选一；估算年龄输入时折算锚点，并标 estimated；年龄动态计算，不每年更新整数 |
| arrivedOn | 可选日期，不晚于今天；与出生日期不合理时提示核对 |
| weight | 档案不保存可随意覆盖的“当前体重”；初次填写时创建一条体重记录，保留时间和来源 |
| front/left/rightMediaId | 可选，三视图是独立角色绑定；不会触发默认 3D 上传或推理 |

品种字典由 Admin 管理，查询按物种、关键词、游标；APP 可缓存版本并使用 ETag，不能硬编码全量品种数组。所有者列表区分“我的”“共同照护”，归档区域折叠并显示数量；详情显示主人与当前角色。

### 8.2 生命周期与关联动作

~~~mermaid
stateDiagram-v2
  [*] --> ACTIVE
  ACTIVE --> ARCHIVED: 主人归档
  ARCHIVED --> ACTIVE: 主人恢复
  ACTIVE --> DELETION_PENDING: 明确申请删除
  ARCHIVED --> DELETION_PENDING: 明确申请删除
  DELETION_PENDING --> ACTIVE: 等待期撤回且原状态活跃
  DELETION_PENDING --> ARCHIVED: 等待期撤回且原状态归档
  DELETION_PENDING --> PURGING: 到期并取得清理锁
  PURGING --> DELETED: 各类数据清理成功
~~~

- 归档停止新的任务展开、默认选择和周期 AI 任务；未完成实例取消但保留历史。归档资料只读，已有家庭授权仅允许原范围只读，临时链接撤销。
- 恢复只恢复档案；规则保持暂停，主人预览后选择恢复，不能突然补发几个月的通知。
- 删除申请立即隐藏普通查询结果、撤销共享与待发通知；撤回恢复旧档案状态，但不复活已撤销的分享链接和邀请，需重新授权。
- 删除影响预览返回记录数、媒体数、共享成员、报告和帖子引用等。对多处引用的媒体不能一刀切物理删除。

### 8.3 成长时刻

手动时刻字段：petId、occurredOn、title、subtitle、description、orderedMediaIds、source=MANUAL。支持零到若干媒体，列表只展示前三张，详情分页展示全部；视频播放使用媒体模块。

AI 周小记：用户在设置中开启 → 每周固定宠物时区运行 → 查询本周新增/更新记录、笔记和媒体 → 无新事实则 SKIPPED_NO_DATA → 预占点数 → Python 生成结构化候选，保留 sourceRefs → 通知“有一份小记待核对” → 主人修改确认 → growth_moment 入库。默认不直接生成正式时刻。唯一键 petId+weekStart+generationPolicyVersion 防止调度重复；重新生成创建新草稿而非多条正式时刻。

开启配置需包含 weekday、localTime、timezone、perRunPointCap 和月度总预算，展示预计调用频率；免费测试也不默认无限自动生成。媒体自动索引同样需要单独开启和预算上限，额度不足只暂停索引，不让已成功上传的素材不可用。

成长时间线与照护时间线分开：前者是精选回忆，后者是原始事实。报告、相册引用原始资源 ID，不复制为新的健康事实。

## 9. 记录、笔记与营养

### 9.1 所有记录共享的保存链路

页面取得记录类型定义和可用能力 → 锁定 petId、默认发生时间 → 上传附件并取得可绑定 mediaId → 提交类型化请求 → Biz 检查账号/宠物/角色、幂等键、版本、字段和媒体权限 → 本地事务写原始记录、指标投影、附件绑定、已确认提醒规则和 Outbox → 返回详情和关联 taskId → APP 刷新记录、首页和趋势。

附件上传失败不丢文字；用户可移除失败项再保存，不能把上传中 mediaId 当成 READY。删除记录先预览关联影响，删除记录和取消其仍有效的来源提醒在同一 Biz 事务内完成，媒体按引用规则保留。

来源字段：MANUAL、MEASURED、VET_DOCUMENT、AI_CONFIRMED，另存 originDraftId / sourceDocumentId；AI_CONFIRMED 说明整理方式，不能把口述估计变成 MEASURED。title/summary 从有效字段派生，不让前后端各实现一套拼接；列表响应给统一展示模型和结构化 metric。

### 9.2 类型字段与列表/趋势规则

所有类型共有 occurredAt、petId、note、mediaIds、source、version。

| type | 必填与可选字段 | 展示和关键校验 |
|---|---|---|
| FEEDING | mealType；foodItems 至少一项或自由食品描述；offeredGrams 可选，intakeMode=EXACT/ESTIMATED/UNKNOWN；consumedGrams/remainingPercent 条件字段；planOccurrenceId 可选 | 标题“早餐 · 主食干粮 32 g”；摘要明确投喂/实食/估计。克数非负；精确食用不大于投喂，特殊情形需改投喂量 |
| WATER | mode=MEASURED/OBSERVED；实测 amountMl>0 或 observation=LOW/MODERATE/HIGH/UNKNOWN | 标题“饮水 · 120 ml”或“饮水 · 主人观察”；模式互斥，观察等级不进 ml 曲线 |
| WEIGHT | weightKg>0、measurementSource；bcsScale=9、bcs 1—9 可选；mcs 枚举可选 | 标题“体重 · 4.2 kg”，摘要与按时间前一条比较。插入历史记录后动态重算差值，不能用创建顺序 |
| VACCINE | vaccineName、vaccinatedAt；purpose、institution、batchNo、evidenceMediaIds、nextDate 可选 | 标题“疫苗名 · 日期”，摘要机构/凭证；nextDate 不是自动推导周期 |
| DEWORMING | productName、usedAt、method；institution、instructionsOriginal、nextDate 可选 | 标题“驱虫 · 日期”；保留使用来源，不让模型生成剂量 |
| MEDICATION | drugName、takenAt、instructionsOriginal；courseStart/End、prescriptionSource 可选 | 标题“药名 · 时间”；疗程资料与本次服药分开，可缺频次保存原文，不能凭空生成完整用药规则 |
| VET_VISIT | visitedAt、institution、reason；ownerObservation、vetDiagnosisOriginal、examinationMediaIds、followUpDate 可选 | 标题“机构 · 日期”，摘要主人主诉；诊断原文与主人观察分字段 |
| OBSERVATION | topic、description；severityByOwner 可选 | 标题可用主题 + 描述短句；标主人观察，不推导疾病状态 |
| GROOMING | itemName、performedAt；performer、institution、nextDate 可选 | 标题护理项目，摘要执行人/机构 |
| EXPENSE | spentAt、amount>0、currency、category、itemName；relatedRecordId 可选 | 标题“疫苗 · ¥180.00”；总花费单独聚合，不把“今年累计”固化在每条历史摘要 |
| CUSTOM | customTypeId、schemaVersion、typedValues | 标题按类型配置生成；字段校验见 9.4 |
| NOTE | journal 模块维护的笔记 ID | 全部记录列表可联合显示 NOTE 摘要；笔记正文与标签仍由 journal 拥有，不双份存储 |

金额首期支持配置的币种，默认 CNY；不同币种分开汇总，不无汇率换算成一个总额。统计返回 sumByCurrency、recordCount、period；查询范围由用户时区日期换算为 UTC 半开区间 [start,end)。

混合食品的投喂/食用字段以 foodItems 每项为准，每项可填 offeredGrams、intakeMode、consumedGrams 或 remainingPercent；顶层数量与整条记录的摄入状态是服务端派生的只读合计，不接受客户端重复提交。只有每项均有可比较数量时才给完整总食用量，每项能量已知且摄入量有效时才给完整摄入热量；只有整碗剩余比例时只能按混合比例估计，并明确显示此假设，不能标为精确实食。

体重记录允许补录与编辑；“最新体重”取发生时间最近的有效记录。BCS/MCS 使用有版本的图文说明，允许“不知道”，不只提供 4/5/6 三个值；参考 WSAVA 的体况与肌肉评分区分，不把两者混成一个健康分数。[WSAVA Nutrition Toolkit](https://wsava.org/global-guidelines/global-nutrition-guidelines/)。

### 9.3 复用上次

服务端返回 reusePolicy 与可预填字段：

- 可复用：喂食的食品/餐次/计划份量、洗护项目、日常观察主题、自定义类型允许的默认字段。
- 不复用：体重实测值、饮水实测值、疫苗/驱虫执行、用药执行、就医内容、花费金额、上次已完成状态。
- 允许预填的上次记录距今天超过 30 个本地自然日时禁用，说明“记录较久，请重新填写”。医疗类始终禁用，不受 30 天规则豁免。
- 发生时间重置为当前，媒体不自动复制，来源标记 copiedFromRecordId；保存前仍需确认实际发生的事实。计划量不直接写 actualConsumedGrams。

### 9.4 自定义记录类型

主人创建名称、说明、最多 10 个字段；支持 TEXT、DECIMAL、BOOLEAN、SINGLE_SELECT、DATE。每个字段有稳定 fieldId、label、type、required、defaultValue、unit、options；不执行公式、脚本或动态 SQL。

未被引用时可编辑；有历史后新增 schemaVersion，旧记录仍按旧版本显示。删类型实际停用，只从新建入口隐藏，历史可查。字段默认值只预填，不等于已测量。复用使用白名单字段，任务规则使用统一 reminder 模型，不能在动态字段里再藏一套 scheduler。

### 9.5 笔记编辑器与待办

以 CommonMark + 选定 GFM 扩展为存储约定：H1—H5、正文、粗体、斜体、有/无序列表、引用、链接、表格、待办。移动端可用富文本操作栏，但 round-trip 必须稳定，不能每次保存丢表格、媒体和待办 ID。原文 Markdown 为真相，不存任意可执行 HTML。

媒体以应用受控标记引用 mediaId，渲染时鉴权换临时地址，不把过期 URL 写进正文。链接只允许 http/https 等批准协议，打开外链提示来源；移除 javascript、iframe、script 和原始 HTML 执行。标签账号内管理，只新增/删除；删除标签解除关系，不删笔记。

笔记待办不能只保存在 Markdown 的勾选字符中：

1. 编辑器插入待办 block，赋稳定 blockId；输入 title、可选 dueDate/dueAt。
2. 笔记保存提交 markdown + taskBlocks；Biz 同事务建立 note_task_link 和任务，重复保存按 noteId+blockId 更新，不新建重复任务。
3. 无截止时间的待办进入“未定日期”，不发定时通知；勾选完成同步任务状态。
4. 删除带任务 block，显示将取消几个未完成待办；已完成历史保留。修改日期只改该任务，不重新识别全文生成新任务。
5. AI 识别待办只产出候选，用户可取消/改日期；相对时间按输入时间+时区解释，“下次”“有空”不得自行推定日期。

AI 小记输入“观察、背景变化、想留住的瞬间、主题、素材”，允许部分为空但至少有有效内容。返回 draft.note、candidateTasks、uncertainFields、sourceRefs；预览确认通过 journal 用例保存，失败保留输入。

### 9.6 食品卡与包装识别

食品卡为主人私有可复用资料，不建首期全球商品库。名称必填；单包净重 grams、品牌、食品类别、价格/币种、图片、营养成分、备注可选。价格与食品净重不作为宠物实际摄入来源。

能量保存原值、原单位、normalizedKcalPer100g、source=LABEL/MANUAL/OCR_CONFIRMED、sourceMediaId；无值时为 null，不能算 0。接受 kcal/100g、kcal/kg、kcal/can（要求每罐克数）；kJ 必须明确单位后按版本化确定性换算，疑似单位不自动纠正。

包装识别：上传包装 → AI 授权+预占 → OCR/视觉提取字段和原图位置 → APP 并列展示原图、读到的数值/单位、缺失项 → 用户确认 → 保存食品新版本。识别失败可手填；不从包装推断完整配方和适宠性。

食品修改形成 food_card_version；计划引用确定版本，提示“食品信息已更新，是否更新计划”。历史记录保存食品名、类别、能量与份量的快照，不能因改卡改变历史热量。被计划引用的食品只停用，不删除历史版本；CONTRIBUTOR 可读取授权计划中食品摘要，不能浏览主人食品库或创建/修改食品卡。

### 9.7 喂食计划与实际记录

计划字段：petId、name、timezone、startDate/endDate、frequency、interval、weekdays、times[]、items[{foodVersionId,gramsPerOccurrence}]、note、status。一次含多种食物用 item 逐项配量，总份量派生，不额外保存可冲突的“每顿量”。

支持一次性、每天多时段、每 N 天指定时段、每周指定星期；例如每天 08:00/18:00，或每 7 天 10:00。不能同时用“天/次”模糊表达频率和份数。保存前预览未来 5 次执行时间与热量；计划改动生成版本并指定从哪个未来日期生效。

如果所有 items 能量已知：estimatedKcal = Σ(grams × kcalPer100g / 100)；部分未知返回 knownKcal + hasMissingEnergy，页面写“部分能量未知”，不展示假总值。人工热量覆盖需字段 overrideKcal、reason、source，不能掩盖计算值。

计划保存调用 reminder 建规则并生成任务实例；“记一次”打开预填表单，用户填实际投喂/食用后记录与任务完成同事务提交。计划更新仅替换生效点之后未完成实例，过去完成记录保持原计划版本快照。

食用量：精确量来自用户确认；若用剩余比例，只能计算 estimatedConsumedGrams=offeredGrams×(1-ratio)，标估计。多人/多宠共碗时无法确定个体摄入，可只保存投喂和备注；不把倒进水碗的 ml 当饮水量。

推荐量小工具为用户主动打开的独立计算器：输入物种、年龄阶段、体重、绝育、活动/体况等，展示公式/系数版本和缺失信息；仅在有经复核的营养规则包时启用。原文提供的 ChatGPT 分享链接本次仅返回登录壳，未读取到计算逻辑，因此**不能声称已复用或验证其公式**。先实现克数/包装能量换算，RER/DER 推荐规则须单独复核后上线；不让 AI 自选医学系数。未支持物种和特殊生理/疾病状态转向兽医确认。

## 10. 提醒、待办、信箱与首页

### 10.1 四层对象

| 对象 | 回答的问题 | 状态 |
|---|---|---|
| reminder_rule | 以后按什么时间重复做什么 | ACTIVE / PAUSED / ENDED / CANCELLED |
| task_occurrence | 某一次具体事项何时应完成 | PENDING / COMPLETED / SKIPPED / CANCELLED |
| notification/delivery | 这条消息是否已送到某个渠道 | QUEUED / SENT / FAILED / SUPPRESSED；阅读另记 readAt |
| care_record | 实际发生了什么 | 有发生时间与事实，不随通知成功自动生成 |

逾期是“PENDING 且 dueAt<now”的查询条件，不单独持久化一个不断变化的状态。延期保留 originalDueAt 并修改该实例 dueAt，不移动整条周期计划；暂停规则只影响未来未完成实例。

### 10.2 规则、时区与调度

规则存 recurrenceSpec、timezone、localStart、times、interval、weekdays/monthDays、endCondition、leadOffsets、nextExpandAt、version。首期实现受限重复规则子集并返回预览，不让客户端直接提交任意 RRULE。可借鉴 iCalendar 的时间/重复概念，但使用成熟库处理边界，不自己手写完整标准。[RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html)。

默认策略作为可配置产品值：喂食/饮水到点提醒；疫苗和驱虫可默认提前 7 天、1 天和当天，用户保存前确认；用药按确认的处方时段；笔记/自定义按用户所填。策略不自动推导医疗执行日期。

PowerJob 定期执行少数扫描任务，不为每个用户建立 PowerJob Job：

1. 展开扫描：每 5 分钟读取有效规则，生成未来 7 天实例和 notificationTrigger；唯一键确保多节点不重复。
2. 到期扫描：每 30 秒按 nextTriggerAt 抢占一批，事务写 notification + Outbox，提交后再发送。
3. 失败重试与对账：重试投递、检查漏展开规则、释放过期租约、记录延迟。
4. 初始化/修改规则立即展开，不等扫描周期，返回未来实例预览。

月 31 日首期必须让用户选“仅有该日月份”或“当月最后一天”；不隐式改成 30。夏令时不存在时间默认顺延到首个有效时间，重叠时间只触发一次；页面预览说明。用户旅行改显示时区，原计划仍按原时区运行，迁移计划时必须预览确认。

免打扰对普通通知延后到下一允许时间，站内待办一直可见。P0 不承诺“紧急健康通知绕过免打扰”，原型文案删除；只有用户主动配置、系统渠道允许的时效级别才能特别处理。

### 10.3 完成、跳过、延期的事务

- 完成照护类实例：传 occurrenceId、version 和本次记录字段 → 校验任务/记录权限 → 条件更新 PENDING → 写实际记录并绑定 → 取消未发送通知 → 返回 recordId。默认不能空勾出一条虚构医疗或体重记录。
- 普通待办可直接 complete，保存 completedBy/completedAt；不自动创建照护事实。
- 两个家庭成员并发完成：锁或乐观条件更新保证一次成功，另一方收到 TASK_ALREADY_COMPLETED 和完成者摘要；不能重复记两次早餐。
- 跳过保存 skippedBy/reason；不生成记录；延期只变一项时间；未来重复实例仍按原规则推进。
- 删除已绑定的事实记录时展示“完成状态是否撤销”；默认同时将该实例恢复 PENDING 并暂停补发，用户可选择取消任务。不能保留一个没有事实来源的“已完成喂药”。

### 10.4 通知投递与信箱

站内信箱是权威消息列表；移动推送在上线前选定适合目标平台/地区的通道，保存设备 Token、权限状态和最近活跃时间。iOS 按 APNs 能力，Android 按所用供应商/系统；Token 失效后停发。SMTP 首期只承担验证码、安全通知和导出通知，不替代高频喂食推送。

本地通知可作为短期离线补充，但需用 occurrenceId+recipientId+triggerVersion 同步调度/取消，避免和远程推送双响。首期建议只用服务端推送 + 站内信箱，后续再加本地补偿。Apple 区分本地通知的内容与触发条件，不能认为服务端记录成功等于系统通知必达。[Apple 本地通知说明](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)。

投递按 recipientId+occurrenceId+triggerVersion+channel 去重。MQ/供应商接受只能显示“已提交发送”，不等于用户阅读；供应商不支持幂等时，重试仍可能重复，需限制重试窗口和折叠键。社区点赞/收藏可聚合，提醒不淹没在互动消息中。家庭任务默认通知主人和明确选择订阅的执行成员，避免邀请后所有提醒都轰炸全家。

### 10.5 首页聚合

GET home?petId 返回 petSummary、capabilities、todayTasks、overdueCount、quickRecordTypes、reuseCandidates、photoWall、growthMoments、inboxUnreadCount。首页只组合查询，不生成任务或调用模型。

首屏顺序：当前宠物/协作标识 → 今天要做/已完成摘要 → 快速记录 → 照片墙 → 成长时间线。宠物封面可以保留，但不能挡住“是否已喂”信息。无任务写“今天没有安排”，无记录写“尚未记录”，不能写“今天未喂食”。

“今日待记录”来源于用户自选习惯清单，不把所有记录类型默认变成每日义务；完成与否只影响记事提示。今日待办来自正式规则，两者在 UI 上说明差异。首页快捷配置存用户偏好；无宠物也允许进入我的、协议、邀请接受和帮助。

## 11. 媒体、相册与检索

### 11.1 文件、素材、引用、相册分离

- 文件是 OSS 对象；media_asset 保存元数据和状态。
- 素材只上传一次，业务 media_binding 说明用于头像、记录、笔记、成长、报告等；复用不重复计原文件空间。
- 相册 album_item 只组织媒体，可以多相册引用同一素材；全部素材是查询视图，不是必须存在的“系统相册行”。
- 宠物记录中新增附件可复用当前宠物媒体；首次建档/首次三视图从系统选择器上传；后续允许有权访问的素材，不为同一文件重复造上传限制。
- 记录附件包含照片/视频/PDF 等，但“相册浏览”默认只查照片和视频，文件在资料列表展示。

### 11.2 可靠上传链路

1. APP 选文件，读取可用尺寸/时长/大小，展示待上传列表并可删除。
2. POST upload-sessions，传文件大小、MIME、用途和目标 petId；Biz 鉴权并原子预占存储，生成服务端 objectKey 与上传会话。
3. 返回短期 OSS POST Policy/凭证，限制 objectKey、有效期、Content-Type、最大长度；不接受客户端任意覆盖旧对象。
4. APP 直传 OSS；分片上传在视频阶段接入，绑定 uploadId 和已上传分片，不重复申请额度。
5. APP complete 或可信 OSS 回调触发检查；Biz 校验对象存在、size、实际格式、checksum 可用性及会话归属，不能相信 APP 的“成功”。
6. 隔离区处理：病毒/内容类型扫描、图像缩略图、视频封面/转码，照片派生文件去定位等 EXIF；状态 PROCESSING，普通列表不当作可用素材。
7. READY 后结算存储，绑定业务；处理失败保留可重试状态并释放未实际占用部分，清理孤立对象。

状态：INITIATED → UPLOADING → VERIFYING → PROCESSING → READY；失败到 FAILED，过期到 EXPIRED；删除到 DELETION_PENDING → DELETED。上传链路属于媒体基础设施，不因图片 AI 索引失败回滚原文件。

首期可配置限制建议：图片 20 MiB、单视频 200 MiB / 3 分钟、文档 20 MiB，每批最多 20 项；百炼处理使用符合所选模型限制的派生图/抽帧，不能假设模型接受 APP 全尺寸原文件。OSS Policy 限制和服务端完成验证都要做。[阿里云上传大小/类型限制](https://help.aliyun.com/en/oss/how-do-i-limit-object-formats-and-sizes-when-i-upload-objects-to-oss)。

### 11.3 删除和存储计量

删除相册仅解除 album_item。记录删除解除记录绑定，媒体仍保留在素材库；素材库明确删除媒体时先返回 impacts，主人可选择解除所有私人引用再删除，公开帖子引用需先撤回或删除其公开派生副本。CONTRIBUTOR 只允许移除自己记录中的绑定，不允许全局删除主人空间文件。

媒体物理清理必须确认无剩余有效绑定、无保留期、无进行中任务租约；同一宠物删除只解除该宠物引用，不清掉主人其他资料仍使用的对象。首期可以不用跨用户内容寻址去重，避免通过哈希泄露别人是否上传过同图。

用户逻辑空间按原文件加明确列出的生成成品计量；系统缩略图/索引成本计入平台开销并设置比例上限。待删除但尚未物理清理的原文件仍占额度，页面显示“待释放”；清理完成后记负流水，不能点击删除立刻返还又让 OSS 长期占满。

### 11.4 普通筛选与语义筛选

P0：MySQL 按 owner/pet/album、capturedAt、mediaType、tag 和 title/description 筛选，优先索引和受限 LIKE；仅在数据规模确有需要时增加全文检索。捕获日期来源为用户/可信 EXIF/上传时间，带 source 和时间精度，不猜成拍摄日期。

P1：用户开启 MEDIA_INDEX → MediaReady 触发低优先级向量任务 → Python 调所选多模态模型 → 保存 embeddingModel/version/dimension、assetVersion、ownerId、petId、state 等 payload → Qdrant upsert。模型升级新建 collection/命名向量版本，重建后切换 alias；不混不同维度或语义空间。

自然语言查找分两步：

1. Python 只解析白名单条件 {petCandidates, dateRange, tags, sceneText}，把“上个月”按请求时区和时间解析；有歧义展示解析结果可改。
2. Biz 解析实际允许的 owner/pet 范围；Python 用不可省略的权限过滤做向量召回；Biz 对返回 assetIds 二次鉴权、版本/READY 状态校验后提供媒体卡片与临时地址。

不能用用户描述中的 ownerId 替代授权条件。共享宠物搜索使用经过授权的 ownerId+petId 组合 OR 过滤，不能只用“当前用户 ownerId”导致搜不到家人资料，也不能只 petId 不验授权。结果分页用有期限的 searchSession 固定排序并逐页重验权限。

Qdrant 与 MySQL 的职责及租户过滤参考[Qdrant multitenancy](https://qdrant.tech/documentation/manage-data/multitenancy/)；多模态模型输入、维度与视频限制以实际接入版本为准，参考[百炼 Multimodal Embedding API](https://help.aliyun.com/zh/model-studio/multimodal-embedding-api-reference)。

图片索引状态单独返回 NOT_REQUESTED / QUEUED / INDEXING / READY / FAILED / DISABLED。索引关闭或失败可继续普通筛选；不把“索引不可用”渲染为“没有照片”。同图相似不证明识别出某只宠物、情绪或疾病。

## 12. 家庭协作与临时照护

### 12.1 邀请和接受

主人选择宠物、角色、资料范围、授权到期时间 → 生成 7 天有效邀请 → 分享链接/码或明确点击发送至邮箱 → 对方登录 → 预览主人、宠物、权限和期限 → 接受 → 事务生成授权并标记邀请已使用 → 双方信箱通知。

邀请 token 使用高熵随机值，数据库只存 hash；短展示码须足够随机并限流，不能用连续 ID。指定邮箱邀请仅允许该已验证邮箱接受；通用邀请链接默认只接受一次。不能靠“知道邀请码”直接查看资料；接受前预览仅显示必要摘要。

邀请状态 PENDING / ACCEPTED / REVOKED / EXPIRED / DECLINED。权限调整使用 version，支持读权限降级、范围收紧、到期；撤销后 APP 清理受限缓存、通知不再带隐私正文、AI 任务中止后续取数。

### 12.2 协作写入与费用归属

CONTRIBUTOR 新增记录保存 ownerUserId=主人、createdBy=贡献者；任务完成显示“林阿姨 08:05 已记录早餐”。贡献者不能把主人的宠物转移到自己账号、编辑主人食品卡，或通过 AI 绕过限制。

共享空间上传占主人的存储额度，邀请摘要和上传前说明；上传者有单日限额且不能看到主人全部账单。AI 按发起者的点数扣费，周期任务按配置主人扣费。所有账单主体由 Biz 推导，不能由 APP 指定。

主人可以删除共享空间中的贡献内容；成员撤销/退出不删除其曾经完成的事实记录，保留最小作者标识。成员账号注销时作者显示“已注销成员”，宠物主人空间的数据按告知的共同照护归属政策保留。

### 12.3 访问日志

主人可看成员、操作类型、资源摘要、时间与结果；记录读取以一次明确页面访问或导出为单位聚合，不能记录每个缩略图请求把日志刷满。日志不记私人对话正文、密码、完整下载链接；建议默认保留 90 天并配置。

### 12.4 临时照护清单

从授权资料生成**用户选定内容的只读快照**，字段包含宠物摘要、喂食时段、份量/原文、饮水/散步说明、注意事项、可选联系人和 expiresAt。默认不带地址、定位、完整医疗材料。处方内容必须原文复制并明确来源。

生成前预览 → 确认分享 → 不可猜 token → 有效期内鉴权访问（默认要求接收者登录；用户选择匿名链接时提示持链接者可看）→ 主人可撤销。匿名链接是 bearer capability，应限制访问次数/速率，不索引、不公开缓存。

清单不自动随着主人的原记录变化；详情显示生成时间及“如需更新请重新分享”。需要实时变更的长期照护使用正式成员授权。过期、撤销、源宠物删除均返回失效态，不能继续签发附件链接；已下载副本无法远程收回。

## 13. AI 问答、工具、草稿与知识库

### 13.1 用户侧模式

界面保留 Chat / Agent 可识别切换，但加中文解释：

- **问一问（Chat）**：只读查询个人已授权资料和通用知识，输出说明、来源和可验证图表。
- **帮我整理（Agent）**：在前者基础上生成记录/笔记/待办/帖子草稿，用户核对后再保存。

推荐问题点击只进入输入框，不立即发送或消耗额度。会话固定 petScope；切换宠物提示新建或明确改变后续范围，不能把上一只宠物体重当作新宠物事实。

### 13.2 Chat 执行

APP 创建 session → 提交 message 和选定 mediaIds → Biz 校验会话/授权/隐私同意/额度，创建 run 并预占 → Python 领取受限上下文 → 判断是否需要业务数据/公共知识 → 调只读工具 → 验证来源 → 模型生成 → 流式输出 → Biz 持久化最终结果和结算 → APP 展示引用。

简单问题可先确定性查数据再一次生成；需要工具循环时默认最多 4 次工具阶段、总墙钟 60 秒、输出 Token 上限由模型配置控制，复杂报告走异步任务。超限返回已完成的有效部分和明确停止原因，不编造“已查完”。

工具白名单首期：

| 工具 | 输入 | 输出与限制 |
|---|---|---|
| get_pet_profile | petId | 允许范围基础资料、日期与来源，过滤无关个人信息 |
| list_care_records | petId、type、dateRange、cursor | 已授权记录摘要和版本，不无限拉全库 |
| get_record_detail | recordId | 正文与引用信息，重新验证归属 |
| query_weight_series | petId、dateRange | Java 统计的数据点和计量单位 |
| list_tasks | petId、range、states | 待办与已完成事实，不能修改 |
| search_media | sceneText、allowedFilters | 授权素材 ID，不把私有 objectKey 给模型 |
| retrieve_knowledge | question、species | 资料片段、来源 URL、发布时间/复核日期 |
| propose_record_draft | typedCandidates | 草稿，不触发正式写入 |

不提供任意 SQL、任意 HTTP 请求、shell、文件系统、删除宠物、修改药量或直接发帖工具。工具参数和输出经 JSON Schema/Pydantic 校验；Qwen 支持的结构化输出模式因模型而异，启动时根据已验证模型配置选择并做契约测试，不能把 JSON 字符串“能解析”等同于业务正确。[百炼结构化输出](https://help.aliyun.com/en/model-studio/qwen-structured-output)。

### 13.3 AI 写入的唯一正式入口

~~~mermaid
sequenceDiagram
  participant U as 用户/APP
  participant J as Biz
  participant P as Python
  U->>J: 提交整理请求
  J->>J: 权限/同意/额度预占，创建 run
  J->>P: 输入清单和受限授权
  P-->>J: 类型化候选与来源
  J->>J: 校验并保存 draft
  J-->>U: 草稿、缺失字段、预期动作
  U->>J: 确认 draftId+version+修改字段
  J->>J: 重新鉴权、校验版本、事务写入
  J-->>U: 正式 resourceIds 和任务链接
~~~

草稿包含 draftId、draftVersion、expiresAt、sourceRefs、requiredConfirmations、actions[]、uncertainFields、inputResourceVersions。状态 PENDING_REVIEW / CONFIRMED / DISCARDED / EXPIRED / INVALIDATED。

确认时检查草稿归属、是否过期、source 版本是否改变、当前能力和目标宠物状态。过期/撤权不能确认。多条动作在同一 Biz 事务内全成功或全失败，首期最多 10 条、同一 owner 空间；不通过分散 HTTP 请求产生一半记录。用户可删去不想确认的动作，重新核对动作摘要。

重复确认返回原 recordIds，不重复写入或重复创建待办。用户修改的值标 USER_EDITED，保留 AI 原候选用于有限期审计，不覆盖原始输入。AI 草稿生成已消耗的点数不会因为用户选择不保存而自动退回；UI 生成前说明。

LangGraph 如需用于长流程，可利用 checkpoint 与 interrupt 机制实现暂停/恢复；**最终业务确认仍由 Java 草稿确认接口执行**，不能把 Python 图恢复当作业务授权。[LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)。

### 13.4 RAG 与私人资料分开

公共知识库由 Admin 上传/导入有使用权的来源 → 清洗 Markdown → 记录 sourceUrl、版权/授权、物种、reviewedAt、适用范围 → 分块 → 嵌入 → 人工审核后发布知识版本。不是抓到网页就永久存储并当权威资料。

私人记录首期直接用 Biz 结构化工具查询；长笔记需要语义索引时另建私有 collection，不和公共知识/社区内容混用。引用返回 {sourceType,sourceId,version,title,occurredAt,excerpt}；APP 点击回业务详情，权限变化后显示资料不可见。

外部文档、用户笔记、图片 OCR 均作为不可信数据，不让其中“忽略规则”等文字改变工具权限。统计计算由 Java 完成，图表由结构化 series 渲染，模型只解释，不让模型制造数据点。

### 13.5 隐私、历史和失败

用户关闭个人上下文后，只允许当前主动提交的输入与公共知识；关闭图片索引停止新任务并排队删除已有私人向量；关闭会话历史保存不删除已确认记录。没有历史保存时，仍需最小任务状态和用量账务，但不长期保留正文；保留期由上线政策明确。

网络中断不自动重发新消息：有 runId 则查状态或重连事件；Python 故障返回可重试原因；无来源明确说“现有资料中没有”。AI 可解释严重症状需联系动物诊疗机构，但不提供诊断/处方/自动用药调整。

## 14. 报告、导出与周期总结

### 14.1 两类报告共用一套后台

| 类型 | 用户价值 | 实现 |
|---|---|---|
| DATA_EXPORT | 给兽医/家人看原始资料、备份、核对 | Java 确定性汇总、表格、附件清单，无模型点数 |
| AI_SUMMARY | 帮用户读懂一段已记录的历史 | Java 算指标，Python 整理带来源叙述，需 AI 授权和点数 |

“记录 → 导出报告”和“AI → 周期报告”只是默认 kind 不同，不各做一个历史库。报告详情展示数据范围、生成时间、记录覆盖、缺失项、估算与实测、引用入口。

### 14.2 生成链路

1. 输入 title/topic、petIds、periodStart/End、timezone、includeTypes、selectedMediaIds、templateId、kind、说明；选择“全部宠物”时冻结本次实际 petIds。
2. Java 检查权限，按同一 dataCutoff 读取事实和版本，生成 sourceManifest 与指标快照。协作权限不足不能把多宠混进导出。
3. Java 计算体重首末/变化、每类次数、按币种花费、已知能量与缺失比例；饮水平均必须说明是“已记录日”还是“整个周期”。未记录不等于 0，不把缺失天补 0。
4. DATA_EXPORT 直接渲染；AI_SUMMARY 预占后 Python 从指标与来源生成 sections，不重新计算指标，不补造“日均活动 68 分钟”等无字段来源数据。
5. 校验引用、数值和字段完整性，输出结构化 ReportDocument → 固定 HTML 模板 → 私有报告版本；可编辑叙述，保留来源清单。
6. 用户点击 PDF/长图导出时创建 exportJob；渲染 Worker 使用固定模板与受控资源输出 PDF/分段长图，完成后签发下载。

报告状态 QUEUED / SNAPSHOTTING / GENERATING / VALIDATING / RENDERING / READY / FAILED / CANCELLED。生成页显示真实阶段，不显示模型随口编的 64% 或虚假 ETA。

### 14.3 模板与安全

系统模板首期提供“照护汇总”“就医资料”“成长回顾”；用户自定义只允许章节开关、排序、标题、封面、图表类型等 JSON 配置，不能输入 JS、任意 HTML/CSS、网络资源或模板执行代码。

APP 内查看使用原生结构化页面或受控 WebView；渲染模板禁任意脚本、白名单网络资源，外部 URL 不由服务端自动抓取。图表来自指标快照，PDF/HTML 来源链接指向已鉴权详情，不嵌长期 OSS 地址。图片大量时分卷导出，长图超尺寸则拆页。

报告保存 sourceVersions 与生成时快照。原记录修改后显示“来源有更新，可重新生成”，不静默改旧报告；权限收紧/源宠物删除导致报告不再可见时必须撤销在线访问，并按清理政策删源敏感片段。已导出的离线文件不能撤回。

### 14.4 周期任务

用户明确开启、选择每 N 天/每周/每月、生成时间和时区；周/月摘要默认生成上一个完整周期，首次预览实际范围。按 scheduleId+periodStart+periodEnd 唯一防重，记录 missedPolicy=SKIP（首期停机后只处理最近完整周期，不补跑所有历史账单）。

无新数据跳过；无额度进入 WAITING_QUOTA/暂停并信箱提醒一次，补额后由用户重试同一周期，不每分钟烧重试。计划编辑从下一周期生效；删除计划不删除历史报告；删除报告不停止计划，UI 明确区分。

## 15. 社区、运营与 3D 实验

### 15.1 社区发布的内容模型

公开帖子是主人主动选择文字/媒体的独立快照，私人笔记和相册不会因勾选“公开”自动成为帖子。首期可见性统一 PRIVATE / FOLLOWERS / PUBLIC，含义分别为仅作者、当前已关注作者的人、任何允许访问者；不做“家庭成员帖子”，家人交流用授权记录与清单。

发帖链路：选择媒体并排序 → 填标题/正文/话题 → 检查隐私与 AI 标识 → 选范围并预览 → 提交 revision → 审核 → 通过后发布。PRIVATE 草稿不进入公开审核/发现；FOLLOWERS/PUBLIC 均需治理。

post_revision 状态 DRAFT / PENDING_REVIEW / APPROVED / REJECTED / WITHDRAWN。post 发布状态 UNPUBLISHED / PUBLISHED / HIDDEN / DELETED，visibility 独立字段。编辑已发布内容创建新修订，旧审核版本可继续显示，拒绝新修订不删除旧版本；主动收紧可见性、撤回和安全下架立即生效，放宽范围必须重新审核。

### 15.2 Feed、搜索与互动

关注流按 approvedPublishedAt+postId 倒序；发现首期按最近通过的公开内容分页，过滤双向屏蔽、下架、作者限制，可插入有明确规则的精选位。**不每次随机 ORDER BY RAND()**，不在初期训练推荐模型。

搜索拆用户、帖子、话题；品种是已确认的公开宠物标签。P2 首期 MySQL 关键词/话题关系即可；中文数据增大再评估支持中文分析器的搜索服务。Qdrant 可做后续语义召回，但排序与权限仍由业务负责。热门话题用近 7 天有效公开帖数量及互动计数的简单公式，策略版本可查，不用“向量库自动聚类”替代业务。

点赞、收藏、关注用 PUT 表示存在、DELETE 表示取消，唯一关系键确保幂等；计数可异步更新，但用户自己的状态即时返回。评论先支持一级评论加回复目标，游标按最近排序；编辑/删除/举报均鉴权。帖不可见时收藏和通知只显示“内容已不可见”，不能继续露出缓存封面。

双向屏蔽：双方不能通过登录态访问彼此帖子、评论和主页详情，Feed/搜索过滤；不能保证对方退出登录后看不到你公开面向公众的内容，设置说明需诚实。

### 15.3 审核、举报、申诉和后台

审核对象是具体 revision，管理员决策提交 version 和理由；社区文本/图片审核供应商可作为辅助，人工保留最终处置与申诉。后台记录操作者、目标、前后状态、理由和 requestId；不能记录“管理员点了通过”却未实际改变发布状态。

举报包含 targetType/id、reasonCode、description、evidenceMediaIds，状态 RECEIVED / TRIAGING / RESOLVED / REJECTED；举报者可看状态，但被举报人只收到处置及规则，不知道举报者身份。处置包含隐藏内容、移除评论、限制发布、停用账号；申诉独立记录，不能管理员随意覆盖旧理由。

社区放二级入口不改变 UGC 管理责任。公开上线前核对目标商店的 UGC、举报/屏蔽、隐私和功能披露要求；不把未审核功能藏起来待审核后开启。[Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)。

### 15.4 Admin 最小能力

| 阶段 | 后台能力 | 写操作经由 Biz |
|---|---|---|
| P0 | 管理员登录/RBAC；用户状态、邮箱验证状态；赠送额度/申请；字典；反馈回复；上传/任务排错；导出/删除进度 | 专用 RPC，附 operatorId、reason、幂等键；读私人资料额外授权 |
| P1 | 模型/限额策略、知识库审核发布、AI run 成本和错误、报告任务重试、索引对账 | 不展示用户完整私人对话作为默认列表，不提供任意提示词执行入口 |
| P2 | 待审队列、举报、申诉、下架、账号限制、话题治理 | 版本化处置与不可变审计 |

额度后台只能通过赠送/冲正流水修改，不直接改 used；支持原因、有效期、申请单关联。管理员重试 AI 任务不能无提示另扣用户一次费用，使用同 operationId / 明确新任务策略。

### 15.5 3D 与 Unity（P3）

先独立验证“照片能否生成用户愿意采用的风格化形象”，不承诺三视图可恢复精确宠物模型。优先用固定骨骼/动作和可配置外观原型；模型生成失败或设备不支持时保留静态头像。

链路：选择可选参考照 → 明示第三方处理与预计点数 → AI 任务 → 安全处理模型资源 → glTF/受控 Unity 资源包 → 预览 → 用户采用 → 配置当前宠物形象。生成资源仍私密，绑定/删除走 media。

动作包清单包含 assetVersion、engineVersion、platform、hash、signature、minAppVersion、size、animationStateMap；只分发已审核资源和预编译动作，不远程下发可执行脚本/原生代码。下载原子替换、校验失败回滚；支持断网与资源额度。

喂食动作只根据用户真实记录/计划演示“已记录/到时间”，不宣称探测现实宠物正在吃饭。Unity 容器嵌入、包体、内存、电量、前后台生命周期和商店资源规则需单独验收，本轮不新增 Unity 工程。

## 16. Java 与 Python 的通信、任务和额度

### 16.1 通信选择和边界

| 场景 | 通信方式 | 选择原因 |
|---|---|---|
| Admin → Biz | Dubbo Triple，DTO 在 common | 复用已建工程，后台不跨库改数据 |
| APP → Biz | HTTPS JSON / SSE | 一个鉴权和业务入口，统一页面状态 |
| Biz → Python 即时对话 | 内网 HTTP 流式 POST | 易调试、支持 Token 流和取消，不跨语言绑定 Java RPC |
| Python → Biz 查询上下文/工具 | 内网 HTTPS JSON，受限 delegation | Java 判定可读范围，Python 没有数据库权限 |
| 报告/识别/索引/成长等长任务 | MySQL 任务 + Outbox + RabbitMQ | durable 排队、重试、独立 Worker；不占用户 HTTP 连接 |
| Worker → Biz 状态/结果 | 内部 HTTP 幂等回调 | Java 保持任务/用量权威，便于对账 |

不同时引入 HTTP、Dubbo、gRPC、MCP 四套 Java/Python 正式契约。首期 HTTP+JSON Schema/OpenAPI 即可；量测证明瓶颈后再考虑 gRPC。MCP 适配器仅在确有外部客户端复用需求时增加。

### 16.2 内部身份与授权委托

部署网络隔离不能代替鉴权。服务调用使用轮换的服务身份（首期可用 TLS + 非对称签名 JWT，校验 iss/aud/exp/jti；具备条件再加 mTLS），APP 用户 Token 不能原样转发给 Python。

Gateway 去掉客户端伪造的 X-User-Id、X-Operator-Id、内部授权头，再注入可信请求上下文；Biz 自己验证 Token/服务身份。requestId 需要字符与长度限制，不能直接把任意输入写入日志。Admin→Biz 除服务身份还要携带可验证的操作员权限上下文，不能仅凭一个 operatorId 接受额度赠送或社区处置。

Biz 另签短时 delegation，绑定 runId、actorId、allowedPetIds、scopes、grantVersions、inputManifestHash、maxToolCalls、expiresAt。它只在对应内部工具 API 有效，不能登录 APP 或调用业务写接口；每次工具请求仍由 Biz 查实际授权和资源状态。过期任务由 Worker 用服务身份按 runId 申请续租，不能自己延长 Token；撤权或取消时拒绝续租。

回调必须同时验证服务身份、runId、当前 attemptId、leaseToken、resultHash 和状态版本。不能因为某字段带 userId 就接受 Python 的结果归属，也不能由 Python 直接指定扣款者。

### 16.3 内部任务接口

| 方法与内部路径 | 调用者 → 接收方 | 核心输入 | 核心输出/约束 |
|---|---|---|---|
| POST /internal/ai/v1/chat-runs:stream | Biz → FastAPI | runId、attemptId、message、contextManifest、delegation、modelPolicy、budget | SSE 的 delta/tool/citation/result/usage/error；Python 不直接面向 APP |
| POST /internal/v1/ai-runs/{id}/leases | Worker → Biz | workerId、attemptId、expectedVersion | leaseToken、leaseUntil、受限上下文授权；只有有效排队状态可领取 |
| POST /internal/v1/ai-runs/{id}/heartbeat | Worker → Biz | leaseToken、stage、progressInfo | 延长租约/取消标志；阶段真实，不伪造百分比 |
| GET /internal/v1/ai-runs/{id}/context | Python → Biz | delegation；分页/资源版本 | 最小数据包、sourceRefs、授权范围；私有媒体仅短时处理地址 |
| POST /internal/v1/ai-tools/{toolName}:invoke | Python → Biz | runId、toolCallId、typedArguments、delegation | 类型化只读结果；白名单、次数、窗口与权限检查 |
| POST /internal/v1/ai-runs/{id}/results | Worker → Biz | attemptId、leaseToken、resultSchemaVersion、result/assetManifest、providerUsage、resultHash | 幂等接受结果；创建 draft/report/index 结果，记录 FINALIZING |
| POST /internal/v1/ai-runs/{id}/failures | Worker → Biz | attemptId、leaseToken、safeErrorCode、retryable、providerRequestId、knownUsage | 失败策略、是否释放预占；不上传供应商完整敏感报错 |
| POST /internal/v1/ai-runs/{id}/generated-assets | Worker → Biz | leaseToken、purpose、mime、declaredMaxBytes | 受限输出 objectKey、短期上传许可与存储预占；仅对应 run 产物 |
| POST /internal/v1/ai-runs/{id}/provider-calls | Python → Biz | callId、modelVersion、maxInput/output、pricingPolicyVersion | 调用账务登记/分配预算片段；每次模型调用前获得许可 |
| POST /internal/v1/ai-runs/{id}/provider-calls/{callId}:settle | Python → Biz | actualUsage、providerRequestId、outcome | 幂等记录实际成本；超时未知进入待对账 |

provider-calls 端点只承担用量/预算登记，不让 Python 通过它任意增加用户额度。P0 没有模型调用不用接入。

Worker 生成 PDF/图片/3D 等成品时先调用 generated-assets，由 Biz 推导存储账单主体并预占空间；上传到独立输出路径，经媒体校验后才可在 results 中引用 READY assetId。取消或失败清理孤立输出，不把 Worker 自报的任意 OSS URL 作为可访问成品。

}
~~~

消息只含标识和必要调度信息，不带完整病历、提示词、长期 OSS 链接或 delegation Token。Worker 消费后从 Biz 领取任务及上下文。业务库持久状态，不用 Redis 内存 Task 字典假装可恢复。

run 状态：

~~~text
QUEUED -> RUNNING -> FINALIZING -> SUCCEEDED
             |          |
             +-> RETRY_WAIT -> QUEUED
             +-> FAILED / CANCELLED / TIMED_OUT
QUEUED -> CANCELLED
~~~

SUCCEEDED 表示生成成功；草稿待用户核对使用独立 draft.state=PENDING_REVIEW，不让 run 持续占租约等用户。周期计划 WAITING_QUOTA 属于调度状态，尚未分配 run，不混进正在运行任务。

即时 Chat 同样有 attempt/lease：Biz 发起内部流前登记本次执行租约，Python 按同一内部心跳和结果回调接口执行。文本流只是实时展示通道；最终结果通过幂等结果回调落 Biz，不能仅存在一条代理连接里。Biz/Gateway 断线时 Python 在租约有效期内可继续并回调；失联超过租约停止后续付费调用，恢复后查 provider call 状态再决定重试。首期若无法确认供应商是否已执行，返回可恢复失败并对账，不自动重复生成。

Worker 通过短租约领取，心跳续期；宕机后到期由 Biz 恢复扫描生成新 attempt。旧 attempt 即使迟到也不能提交结果。RabbitMQ durable 队列、持久消息、publisher confirm、mandatory return；消费者领取任务并确认成功受理后 ACK，长执行可靠性由任务租约承担。不能 ACK 后只存在 Worker 内存且没有租约恢复。

瞬时错误用指数退避加抖动，默认最多 3 次；参数/权限/内容限制/额度错误不重试。DLQ 记录并告警，后台可查原 run 和重试原因。RabbitMQ 提供的确认与消费者应答并不等于端到端只执行一次，因此最终结果和账务必须幂等。[RabbitMQ Confirms](https://www.rabbitmq.com/docs/confirms)、[Reliability Guide](https://www.rabbitmq.com/docs/reliability)。

### 16.5 SSE 与取消

APP 使用支持 fetch streaming 的客户端：POST 创建 run，再 GET /ai/runs/{runId}/events 建流，避免原生 EventSource 无法方便传鉴权/POST 的问题。

事件含 id、type、runId、seq、data；对外类型为 status、text_delta、tool_status、citation、chart、draft_ready、usage、done、error。chart 仅结构化图表 JSON，draft_ready 只带已存储 draftId；不把模型输出直接作为 HTML 注入页面。

- Biz 从 Python 接流并代理，经 Gateway 禁用响应缓存/缓冲，配置心跳和合理读超时。
- 最近事件按 runId 保留短期可重放日志（例如 24 小时的持久化 run_event，按需压缩批量落盘）；Last-Event-ID 断点续读，不重复创建模型请求。
- 最终 message、draft、usage 必须落 MySQL，短期流日志清理不影响最终详情。
- 断线不等于取消：APP 重连查同 run；用户主动“停止”发 cancel，Biz 标记 cancelRequested，Python 在工具/模型边界检查并终止后续工作。
- 已提交的最终结果与取消并发，以服务器条件状态更新的先后为准；取消不回滚用户此前已确认的其他记录。
- Gateway/Biz 长连接数量有限制；为慢客户端设置背压/断开与可恢复结果，不能无限堆 Token。

### 16.6 额度、Token、点数、存储

用量需要区分：

1. **供应商用量**：模型、输入/输出/缓存 Token、图像/视频/语音量、providerRequestId、成本价版本，供成本核对。
2. **用户 AI 点数**：按公开可解释、版本化规则计算，生成前显示预计值和本次上限。
3. **存储 bytes**：已占用、上传预占、待释放，按真实媒体空间记。

用户点数不是原始 Token，不能把 1 Token 固定叫 1 积分。每个 bucket 有 granted、used、reserved，available=granted-used-reserved；变动只能记账本并更新账户，所有写入锁行/条件更新。关系：预占和结算同 operationId 唯一，取消释放剩余，不允许重复赠送或重复退款。

~~~text
提交请求
 -> 计算本次最大可接受消费并告知用户
 -> Java 原子预占，失败则不排队/不签上传凭证
 -> 每次供应商调用前检查 run 剩余预算
 -> 得到实际 usage 后增量结算
 -> 成功/失败/取消释放未使用预占
 -> 账务未知进入 RECONCILING，禁止直接当零消费
~~~

预占估计不等于严格上限：Python 设置 maxOutputTokens，工具循环共享总预算；下一次调用可能超出时先向 Biz 申请追加，available 不足就停止，返回部分结果和停止原因，不透支。请求超时但供应商可能已计费时，保存 callId 做核对；供应商不支持幂等时不能盲目立即重跑同一生成。

“额度不足终止任务”解释为不再发起新的付费调用，已经花掉的额度不能抹掉。平台故障是否返还用户点数由补偿策略决定，通过 CREDIT_ADJUSTMENT 流水实现，供应商成本账仍真实保留。

P0/P1 不做支付和订阅：用户在 me.usage 提交免费额度申请 → Admin 批准并选择点数/bytes、有效期、原因 → ledger 发放 → 信箱通知。到期处理不删除用户资料；存储不足只禁止新上传，可继续查看/下载/删除。

## 17. 跨模块事件、一致性与删除链路

### 17.1 事务与 Outbox

必须同步成功的事情放同一 Biz 事务：记录+指标+附件绑定+用户确认的提醒，待办完成+事实记录，AI 多动作确认+正式对象，额度预占+任务创建。

非关键后续副作用异步：推送/邮件、缩略图/转码、向量索引、报告渲染、计数、清理。业务事务同时写 outbox_event；发布器 confirm 后标记已投递；重复投递由消费者 UNIQUE(consumer,eventId) 去重。单靠 @Async 或 afterCommit 回调不是可靠事件队列。

| 事件 | 生产模块 | 消费者与动作 | 一致性要求 |
|---|---|---|---|
| care.record.created/updated/deleted.v1 | care | 首页缓存失效、报告来源标旧、可选私有索引更新 | 读事实立即可见；搜索/缓存允许短延迟 |
| task.completed.v1 | reminder | 取消后续投递、家庭信箱聚合 | 重复完成不再产生事件 |
| media.ready.v1 | media | 语义索引（有同意才执行）、业务列表刷新 | 原素材可用与 AI 索引独立 |
| media.deleted.v1 | media | 删除向量、派生文件、无效链接清理 | 在线读取先受状态拦截，不等索引删除 |
| pet.archived/deletion_requested.v1 | pet | 暂停规则/周期任务、撤分享、清缓存 | 状态和访问检查立即生效 |

### 17.2 数据删除的分步作业

宠物/账号删除是可恢复进度的批处理，不在 HTTP 请求中递归删除几万个文件：

1. **冻结**：到期条件检查并 CAS 取得 PURGING；和撤销操作竞争时只有一方成功。
2. **阻断访问**：墓碑、授权/分享撤销、取消任务/通知和未完成 run；签名链接按短 TTL 收敛。
3. **业务清理**：分批删除记录、笔记、成长、计划、任务引用，保留依法/按政策必须保留的最小审计；删除游标存 job。
4. **报告/社区**：识别含目标宠物资料的在线报告并删除/重建受影响版本；主人帖子先下架，清理相关媒体和私人引用；不能只删档案留公开下载。
5. **媒体引用核对**：只解除目标空间引用；有其他有效引用的对象保留，去掉已删除宠物标签；没有引用则排对象删除。
6. **向量与生成物**：按资源 ID/owner/pet 删除，清理派生图、PDF、3D、AI 处理临时文件。
7. **账务结算**：实际删除确认后释放存储；关闭新任务，处理在途费用，不删除账本导致无法对账。
8. **完成**：逐阶段对账、失败可重试；记录 completedAt。备份保留期到期再自然淘汰并保留删除墓碑。

等待期、清理重试、失败和最终完成是不同状态。UI 显示“已提交删除”“清理中”“已完成”，不能 HTTP 202 后立即承诺“所有服务器文件已永久删除”。

### 17.3 四个端到端实现例子

**例 A：家人完成早餐**

home.tasks → GET occurrence → 看到 08:00、计划 32g → CONTRIBUTOR 填实际 30g、食用未知 → POST completion → Biz 锁任务/重验授权 → care 保存投喂 30g、不编食用热量 → task completedBy=家人 → 主人首页显示“08:05 家人已记录早餐” → 通知取消。两人同时点击只保留一条完成记录。

**例 B：就医记录附带下次提醒**

care.form.vet → 上传 PDF READY → 提交就医原文和用户确认复诊日期 → Biz 写 record+binding+rule+occurrence+outbox → 详情展示 PDF 与复诊任务 → 当日站内/推送 → 用户补录实际复诊并完成任务。模型不推导复诊日期。

**例 C：找上个月晒太阳的照片**

album.semantic → 创建 search run/预占 → 解析“上个月”为明确范围 → Biz 生成授权过滤 → Python 查向量 → Biz 二次校验 → 返回 searchSession 与真实 mediaIds → APP 卡片可改筛选 → 点图签临时地址。索引失败可切精准筛选，不启动无边界 Agent。

**例 D：AI 整理笔记与一个复查待办**

note.ai 输入文字 → Java run+预占 → Python 返回 Markdown、候选待办和日期歧义 → 草稿页让用户补齐日期 → confirm draft → 同事务写 note、blockLink、rule/occurrence → 响应 noteId、taskId → 跳转笔记详情。拒绝候选待办时只保存笔记。

### 18.11 三个可直接用于契约测试的请求例子

**创建一次真实喂食：**

~~~json
{
  "petId": "pet_example",
  "type": "FEEDING",
  "occurredAt": "2026-10-21T08:05:00+08:00",
  "source": "MANUAL",
  "payload": {
    "mealType": "BREAKFAST",
    "foodItems": [
      {
        "foodVersionId": "food_v1_example",
        "offeredGrams": "30.00",
        "intakeMode": "UNKNOWN",
        "consumedGrams": null,
        "remainingPercent": null
      }
    ],
    "note": "先记录投喂，尚未确认吃了多少"
  },
  "mediaIds": []
}
~~~

请求头需 Token、Idempotency-Key、X-Request-Id。成功 201 返回 recordId/version、typedPayload、title/summary、source 和 linkedTasks；重复键返回原结果。若从计划待办发起，则走 task completion 接口，携带同一 RecordWrite，不再单独调用 records 两次。

**确认 AI 草稿：**

~~~json
{
  "version": 3,
  "acknowledgements": {
    "petAndTimeChecked": true,
    "uncertainFieldsResolved": true,
    "writeActionsReviewed": true
  }
}
~~~

草稿修改先 PATCH 并递增 version，再确认；confirm 不接受隐藏的自由文本覆盖。成功返回 confirmedDraftId、resources[{type,id}]、tasks[]；权限已撤销 403、源版本变化 409、过期 410，均不创建任何正式对象。

**预览一个每日两次提醒：**

~~~json
{
  "petId": "pet_example",
  "title": "喂食",
  "timezone": "Asia/Hong_Kong",
  "recurrence": {
    "frequency": "DAILY",
    "interval": 1,
    "startDate": "2026-10-22",
    "times": ["08:00", "18:00"],
    "endDate": null
  },
  "leadOffsetsMinutes": [0]
}
~~~

preview 只返回未来时间/warnings，不建规则或扣费；保存由 POST reminder-rules 完成。生产 DTO 使用字段约束并拒绝未知字段，Schema 测试覆盖条件必填和版本变化。

现有 pom.xml 和 uv.lock 是版本真相；不把旧文档中版本号当成永远兼容的承诺。实施相应阶段时核对 BOM、Sa-Token、数据库驱动、模型 SDK、供应商接口与安全修复，CI 锁定经验证版本。不要为本次规划顺便升级工程依赖。

### 19.3 部署和运维基线

Docker Compose 满足首期；数据库、Redis、Nacos、RabbitMQ、Qdrant、内部 AI 端口不上公网。生产 Nacos 开启认证与最小授权，不能直接沿用当前 dev compose 的关闭认证设置；生产密钥经部署配置注入，日志和仓库不包含密钥。

健康检查分 liveness（进程存活）与 readiness（关键依赖可服务）。AI 不可用不使整个手动记录服务不就绪；公开社区关闭不影响私人档案。OSS/百炼同地域优先，不能把模型/存储费用混进固定服务器成本。

MySQL 定期全量+增量/托管备份，OSS 采用与删除政策一致的生命周期和备份，Redis 会话丢失可重新登录；Qdrant 可从源数据重建。首期目标可设 RPO≤24 小时、RTO≤4 小时，但必须通过恢复演练证明后才能承诺；需要更严格指标时配置相应数据库/对象恢复能力。

定期对账：孤立 OSS 对象、缺失元数据、超时上传预占、过期 AI 租约、未知模型账单、漏展开提醒、MySQL 与向量版本差异、删除失败队列。所有清理先 dry-run 输出范围再限批执行，生产有审计。

### 19.4 指标、日志和成本

requestId 贯穿 Gateway → Biz/Admin → Python；traceId 标识分布式链路，runId/jobId 标识任务。日志只输出必要资源 ID、安全错误与阶段，不输出密码、验证码、Token、完整医疗文档、提示词、分享链接和完整邮箱。

| 维度 | 指标 | 告警/处理 |
|---|---|---|
| HTTP | 请求率、4xx/5xx、P95/P99、限流、连接数 | 区分参数错误、权限拒绝与依赖故障 |
| 异步 | Outbox 积压、队列年龄、DLQ、租约超时、重试率 | 告警定位到具体 job/run，支持安全重放 |
| 提醒 | 展开延迟、触发延迟、投递失败、重复键冲突 | 触发延迟不等于推送最终到达延迟 |
| AI | 首字延迟、总时长、成功率、工具次数、Schema 失败、引用失效 | 按模型/用例/版本观测，超预算主动熔断 |
| 用量 | 预占年龄、账本差异、单用户成本、实际/估算偏差 | 负余额/重复扣费立即告警 |
| 媒体 | 失败率、处理时长、待清理 bytes、索引延迟 | 私密浏览可在索引故障时降级 |
| 产品 | 建档完成率、首次记录耗时、7 日记录留存、家庭任务冲突次数 | 事件匿名/最小化，不采集正文代替行为指标 |

性能验收是测量目标而非当前事实：非媒体普通查询 P95≤500ms、写入≤800ms（明确测试环境与数据量）；到期扫描通常 60 秒内创建站内通知；AI 生成不设未经验证的固定完成秒数，显示真实排队与阶段。无 AI 时手动链路必须仍可用。

### 19.5 自动化检查的范围

后端核心领域与契约做测试，页面低风险文案/样式不为测试而堆镜像实现。重点是权限矩阵、幂等、并发完成、时区、账务和取消。Java/Python 内部契约在 CI 用示例和 Schema 做双向检查；报告使用固定数据集比较结构化指标，不用断言模型每次逐字相同。

### 20.2 每个模块的 Definition of Done

1. 页面入口、返回目标、空态/加载/失败/无权/额度不足状态可运行。
2. OpenAPI 有请求、返回、错误和真实示例，operationId 与 pageKey 映射明确。
3. Flyway 能从空库迁移，索引/唯一键/版本/所有权齐全，无手工建表依赖。
4. 真实业务写入、幂等、权限和事务成立，无 mock 成功冒充后端。
5. 异步副作用可追踪、可重试、有幂等键，不丢失或重复收费。
6. 附件/分享/向量/报告的读取和删除路径均在权限范围内。
7. 必要自动化测试通过，并留下本地联调或真实供应商沙盒验证记录；未验证的推送/邮件/模型能力如实列出。
8. 更新相关页面和旧文档冲突项；不额外生成无实际调用的框架/抽象层。

### 21.3 上线前仍需做出的业务选择

这些项在资料里没有可靠答案。开发按既定接口继续，相关生产功能在配置完整并验证后开放：

1. **用户地区/数据地域**：决定适用隐私文本、备案、邮箱/推送/模型供应商区域和费用。不要默认“界面香港时间”就代表数据部署香港。
2. **移动与 Web 框架**：没有现成生产前端工程证据；选团队熟悉技术后按 pageKey/契约实施，首期不引入 Unity。
3. **真实邮件域名与发送额度**：个人 SMTP 先验证送达/退信，生产需评估域名认证、限速与服务可靠性。
4. **移动推送通道**：根据 iOS/Android 目标平台与地区选择并真机验证；只有站内消息不能宣称具备后台到时提醒。
5. **免费点数/空间策略**：注册赠送多少、周期/到期、模型折算与平台故障补偿，需形成 policyVersion，不能开发 AI 自行决定商业收费。
