## 2. 实现链路与事务

### 2.1 建宠

```text
Gateway 清理伪造头 → Biz 验移动会话
→ 开启事务、重查并锁当前用户 → 校验幂等键/请求摘要
→ 校验昵称、物种、品种和用户时区中的日期
→ 创建 pet → 必要时设置当前/默认选择
→ 保存安全的幂等响应 → 一起提交 → bootstrap 返回 HOME
```

同一主人的写操作先锁账号，资源写入仍校验本资源 version。唯一键、锁与事务保证并发重试不重复创建。宠物 PATCH 省略不改、clearFields 显式清空；偏好 PUT 省略/空值清除选择。

归档无删除期限，资料只读。归档/删除申请会清除当前和默认选择，恢复不自动复活旧偏好或暂停任务。删除申请记录 previousStatus、deleteAfter，撤回恢复原 ACTIVE/ARCHIVED；到期后拒绝撤回。当前没有后续领域真实数据，不伪造通知取消或媒体清理成功。

### 2.2 额度

```text
可信 Java 用例 reserve → 锁账号 → 检查 available
→ 预占记录 + reserved + RESERVE 流水同事务提交
→ 校验真实结果后 settle：used 增加、释放全部本次预占、SETTLE 流水
→ 取消/过期 release：释放预占、RELEASE 流水
```

账户键 user_id+bucket，流水按 operationId+entryType 唯一。available=granted-used-reserved；数据库 CHECK 保护非负与不超额。字节采用 long 与溢出检查，对外使用十进制字符串。初始赠送默认 0，正数政策首次初始化时同步记账。

预占/结算是内部应用端口，不允许 APP 自报金额结算。WP04 仍需对象真实性、引用关系、删除后的已用字节释放；当前不能宣称上传已完成。

### 2.3 管理审批

```text
管理员认证/RBAC → Admin 提交 PENDING 审计
→ 签名 Dubbo → Biz 验方法、权限、载荷、时间和签名
→ 占用唯一操作 ID → 锁用户再锁申请
→ 赠送 + 唯一账本 + 审批 + 结果收据同事务提交
→ Admin 写 COMPLETED 审计
```

断网时记录 UNKNOWN，不推断 Biz 未提交；同键同内容重试复用业务 ID，由 Biz 重放结果。不同操作重复审批已决申请会冲突。账号限制/恢复推进 authVersion，旧令牌不会因恢复而复活。

Admin 数据库账号没有 Biz 表权限。密码使用 Argon2id，管理令牌仅存 SHA-256 摘要；操作审计与收据不存登录令牌、验证码和明文密码。

### 2.4 数据库隔离

Biz/Admin Hikari 显式 READ_COMMITTED。身份校验先普通读再等待用户写锁时，MySQL 重复读快照可能看不到前一事务刚提交的幂等结果；因此读已提交配合行锁，同时保留数据库唯一约束，不以 Redis 锁或先查后插代替。

| 环境变量 | 说明 |
|---|---|
| FAFA_MYSQL_HOST / FAFA_MYSQL_PORT | `common.properties` 使用的数据库主机和端口；验收默认指向独立 WP02 schema |
| FAFA_BIZ_DB_NAME / FAFA_DB_USERNAME / FAFA_DB_PASSWORD | Biz schema 与专用账号；JDBC URL 从公共主机/端口拼装并配置 UTC |
| FAFA_ADMIN_DB_NAME / FAFA_ADMIN_DB_USERNAME / FAFA_ADMIN_DB_PASSWORD | Admin 独立管理库与专用账号 |
| FAFA_REDIS_HOST / PORT / PASSWORD | 真实移动会话和限流 |
| FAFA_AUTH_HMAC_SECRET | 至少 32 字符的验证码独立密钥 |
| FAFA_INTERNAL_RPC_SECRET | 双方相同、至少 32 字符的独立 RPC 密钥 |
| FAFA_INITIAL_STORAGE_BYTES | 默认 0，首次初始化按政策赠送 |
| FAFA_MAIL_FROM、FAFA_SMTP_* | 邮件配置，实际收信仍待补测 |
| DUBBO_PORT | Biz Triple 协议监听端口；Admin/Biz 服务通过 `fafa` 命名空间内的 Nacos 注册发现 |
| NACOS_SERVER_ADDR / USERNAME / PASSWORD / NAMESPACE | `fafa` 命名空间中的配置/注册中心；配置 Data ID 在 `docs/nacos`，分组 `FAFA_GROUP` |

Java 服务默认使用 `nacos` profile。各 `application.yml` 只保留 Nacos 引导信息，并必需导入 `common.properties` 与本服务 Data ID；启动前先把 `docs/nacos` 下四个文件发布到 Nacos 的 `fafa` namespace、`FAFA_GROUP` 分组。管理库密码、业务库密码、Redis 密码、SMTP 密码、验证码 HMAC 密钥和 RPC 密钥只通过进程环境注入。生产环境使用 `prod,nacos` 并将 `NACOS_NAMESPACE` 指向生产专用 namespace。

### 3.1 一次性初始化管理员

配置管理库和密钥后，通过本地环境提供实际值：

```powershell
$env:FAFA_ADMIN_INIT_USERNAME = '填写实际管理员名'
$env:FAFA_ADMIN_INIT_PASSWORD = '填写独立强密码'
java -jar .\fafa-java\fafa-admin\target\fafa-admin-0.1.0-SNAPSHOT.jar --spring.profiles.active=nacos,admin-init
Remove-Item Env:FAFA_ADMIN_INIT_PASSWORD
Remove-Item Env:FAFA_ADMIN_INIT_USERNAME
```

初始化从 Nacos 读取 Admin 数据库和后台策略配置，但关闭 Web、服务发现和 Dubbo；成功后退出。已有账号拒绝再次创建/重置。用户名 3—64 位，密码 12—128 位且含字母数字。初始角色 SUPER_ADMIN，普通运行去掉 admin-init。

Compose 已增加 fafa_admin 专用用户与空卷初始化脚本；已有卷不会重跑，应迁移权限，不能删卷重置。YAML/脚本检查不等于重新部署整套 Compose。
