# AI

标准对话界面分为Chat和Agent两种模式

## Chat模式

只能进行文化，我会将一些关键的互联网上的宠物只是，解析为markdown，然后使用RAG技术存储到Qdrant中

标准Chat模式，技术实现，我们会参照Codex的实现，使用ReAct架构，每轮只有一次模型调用，会有系统提示词，以及会记录历史对话内容

会索引Qdrant中的信息，以及会创建MCP工具，来辅助调用查询宠物基本信息和日记，以及各种记录内容。每轮对话会再次更新提示词，并记录已完成内容，让模型知道下一步做什么

最终展现形式是Markdown流式输出，会附带图片，视频，文件等以及图表（趋势图，饼图以及表格），会主动询问用户确认关键信息

## Agent模式

会根据用户问题，不只是有Chat模式的功能，还会根据用户问题，来调用MCP工具去主动帮用户生成各种记录内容，生成的记录草稿会先让用户确认，没有问题之后，才会存储到对应的记录里面去

以上两种模式都会生成推荐问题，推荐问题，点击后不会立刻发送，会先在发送框，等待用户再次编辑发送

# 用户模块

社区和宠物管理模块都从这里面进入，其余的包括头像，默认宠物，提醒偏好，比如提前多少时间进行提醒，可以按照具体的提醒类型进行提醒，比如，喂食你总不能前几天你就提醒了，因为喂食是每天都会进行的，打疫苗你肯定要提前几天提醒，不然，宠物主来不及准备。可以修改邮箱修改密码，修改签名，修改昵称，修改头像。查看用量(主要是token用量以及存储空间用量，因为我们最终肯定是要收费的嘛，所以需要限定token用量积分和存储空间，具体用量我们后台可以给每个用户配置，测试期间，由用户自己申请，我们免费赠送，暂时不接入支付和订购会员，所以上面的设计要考虑到用量限制问题，比如上传素材和AI生成，都要在代码层面检测，用量不足，要给用户提醒。并终止任务)

另外我们可能也会根据宠物三视图，生成宠物3D形象，放到首页。会使用unity3D引擎来实现。开发者可以推送最新的3D动效效果到APP，用户也可以自行下载喜欢的3D动效，可以交互，比如点一下，宠物会用一样的表情反馈，或者根据具体的喂食时间等等，展示宠物当前正在做什么，这是高级功能，测试功能，我们先完场上面的，再看下面的能不能实现。
