# 认证

## 登陆接口

```
com.fafa.interfaces.controller.AuthController#login
```
微信code登陆，第一次登陆会注册为新用户，但是信息基本为空，后续登陆会检查MySQL数据库是否存在该用户。

### 设计理念

用户从小程序登陆后，第一次需要授权登陆，之后只要能获得code，就可以直接登陆，跳过用户点击进入。

如果无法实现，则每次小程序登陆界面只预留微信登录按钮，不存在其余登陆方式

## 登出接口

```
com.fafa.interfaces.controller.AuthController#logout
```
用户点击登出后，会清除本地的token，用户需要重新登陆。


# 用户

## 更新用户资料

```
com.fafa.interfaces.controller.UserController#updateProfile
```
用户可以更新自己的昵称、手机号、性别、年龄、城市

初次登陆,昵称暂时为空，昵称应该使用比较亲昵的称呼，eg：小主一号或者铲屎官等。手机号、年龄可以不强制填写，性别，城市强制填写。

所以需要小程序页面引导第一次登陆的用户更新自己的资料。填写完必要信息后，用户可以继续使用FaFa服务。


## 上传头像

```
com.fafa.interfaces.controller.UserController#uploadAvatar
```
初次登陆时，没有头像，需要设置一个可爱的默认头像。用户支持自己上传头像，开发阶段huishangchuandao测试使用的Minio存储。生产环境使用阿里云OSS存储

## 升级为会员

```
com.fafa.interfaces.controller.UserController#upgradeToVip
```
暂时未接入微信支付，后续需要配合微信支付

默认一月会员授权持续时间为32天。如果当前会员未过期，续费的话，从当前会员结束时间开始计算32天。

后续接入支付功能，要考虑做对账功能。

## 续费会员

```
com.fafa.interfaces.controller.UserController#renewVip
```
用户可以续费自己的会员，需要根据前端选择续费一个月还是一个季度，还是一年。每个月按照32天计算，一个季度按照95天计算，一年按照366天计算。

## 获取当前用户信息

```
com.fafa.interfaces.controller.UserController#getCurrentUserInfo
```
查看用户详情，包括昵称、头像、手机号、性别、年龄、城市、会员状态等。

# 宠物管理

## 创建宠物

```
com.fafa.interfaces.controller.PetController#createPet
```
宠物基本信息包括：

必填：宠物名称、宠物类型（猫、狗或其他）、品种（需要后期单独给出接口，根据宠物类型给前端展示常见的宠物品种，当然要给用户一个选择未知的出口）、性别（男、女、未知）、绝育状态
可选: 到家日期、当前体重

同一个用户可以创建多个宠物，但是名称不能相同。另外需要检查用户当前是否是会员，如果是会员，允许创建不限制数量的宠物(其实有上限，暂时设置为10只吧)，非会员只能创建2只宠物。

## 更新宠物信息

```
com.fafa.interfaces.controller.PetController#updatePet
```
可以更新宠物名称（注意同一个用户下不能出现相同的宠物名称）、品种、性别、出生日期、是否绝育、到家日期、当前体重

## 上传宠物头像&上传三视图照片

```
com.fafa.interfaces.controller.PetController#uploadAvatar
com.fafa.interfaces.controller.PetController#uploadProfilePhotos
```
### 需要后期修正

暂时是两个接口，但是实际上我认为应该是一个接口。这样前端也不会显得很突兀，不然用户会很奇怪，为什么我上传了头像，还要上传三视图。这是很难理解的。

我打算把上传三视图改为一个接口。小程序前端控制，只允许最多有三张图片，作为宠物的三视图。排在第一位的自动作为宠物的头像。前端可以控制头像的位序。

在创建宠物时，必须上传三张图片，这是创建宠物的关键，后期更新宠物信息时，也必须校验是否有三张图片。

每次修改这三张图片时，要删除之前的图片，从OSS存储中。

上传图片最好做成并行。上传完即可返回成功。不要让用户持续等。后续Python向量化，可以异步处理，可以使用RocketMQ，但是要在发送到Python做向量化处理之前记录状态，Python处理完成后，更新数据库状态，

并存储到Qdrant向量数据库中，开发阶段，暂时使用接口调用的方式，让Python项目来处理
