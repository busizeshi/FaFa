# 软删除功能说明

## 概述

FaFa 项目现已实现软删除功能。所有数据删除操作都是**逻辑删除**（标记删除），而非物理删除，数据仍保留在数据库中，便于后续恢复。

## 数据库迁移

### 执行步骤

在使用注销用户等删除功能前，**必须先执行数据库迁移脚本**，为所有表添加 `is_deleted` 字段。

1. **备份数据库**（强烈建议）

```bash
mysqldump -u root -p fafa > fafa_backup_$(date +%Y%m%d_%H%M%S).sql
```

2. **执行迁移脚本**

```bash
mysql -u root -p fafa < docs/add-soft-delete-fields.sql
```

或在 MySQL 客户端中执行：

```sql
source /path/to/docs/add-soft-delete-fields.sql;
```

### 影响的表

以下表将添加 `is_deleted` 字段：

- `user` - 用户表
- `pet` - 宠物表
- `photo` - 照片表
- `feed_record` - 喂食记录表
- `water_record` - 饮水记录表
- `excretion_record` - 排便记录表
- `weight_record` - 体重记录表
- `event_record` - 事件记录表
- `reminder` - 提醒表
- `user_settings` - 用户设置表
- `feedback` - 反馈表
- `ai_conversation` - AI对话表
- `ai_message` - AI消息表
- `ai_discovery` - AI发现表
- `diary` - 日记表
- `report` - 报告表
- `pet_profile_history` - 宠物档案历史表

### 字段说明

- **字段名**: `is_deleted`
- **类型**: `TINYINT`
- **默认值**: `0`
- **取值**: 
  - `0` - 未删除（正常）
  - `1` - 已删除（软删除）
- **索引**: 已为 `is_deleted` 字段添加索引，提升查询性能

## 实现的功能

### 1. 用户注销（软删除）

**接口**: `DELETE /user/account`

当用户注销账号时，会软删除：
- 用户基础信息
- 用户的所有宠物
- 宠物的所有照片
- 宠物的所有记录（喂食、饮水、排便、体重、事件）
- 宠物的所有提醒

**注意**：
- OSS 中的文件（头像、照片）不会被删除
- 数据仍保留在数据库中，只是标记为已删除
- 应用查询时会自动过滤已删除的数据

## 后续开发注意事项

### 1. Repository 查询需要过滤已删除数据

所有查询方法都需要添加 `AND is_deleted = 0` 条件：

```xml
<!-- 示例：查询宠物 -->
<select id="findByUserId" resultMap="PetResultMap">
    SELECT * FROM pet 
    WHERE user_id = #{userId} 
    AND is_deleted = 0
    ORDER BY sort_order
</select>
```

### 2. 删除操作改为更新 is_deleted

所有 `delete` 方法实际执行 `UPDATE` 操作：

```xml
<!-- 示例：删除宠物 -->
<update id="deleteById">
    UPDATE pet 
    SET is_deleted = 1, updated_at = NOW()
    WHERE id = #{id}
</update>
```

### 3. MyBatis-Plus 配置

如果使用 MyBatis-Plus，可以配置全局逻辑删除：

```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 添加逻辑删除插件
        // ...
        return interceptor;
    }
}
```

在实体类上标注：

```java
@TableLogic(value = "0", delval = "1")
private Integer isDeleted;
```

## 数据恢复

如需恢复已删除的数据，可以执行以下 SQL：

```sql
-- 恢复用户
UPDATE user SET is_deleted = 0, updated_at = NOW() WHERE id = ?;

-- 恢复用户的所有宠物
UPDATE pet SET is_deleted = 0, updated_at = NOW() WHERE user_id = ?;

-- 恢复宠物的所有记录
UPDATE feed_record SET is_deleted = 0, updated_at = NOW() WHERE pet_id = ?;
-- ... 其他表同理
```

## 清理已删除数据

如需永久删除已标记删除的数据（谨慎操作）：

```sql
-- 清理30天前删除的数据
DELETE FROM user WHERE is_deleted = 1 AND updated_at < DATE_SUB(NOW(), INTERVAL 30 DAY);
```

建议：
1. 定期（如每月）清理超过一定时间（如90天）的已删除数据
2. 清理前做好数据备份
3. 同时清理相关的 OSS 文件

## 注意事项

1. **执行迁移脚本前务必备份数据库**
2. **现有查询语句需要逐步添加 `is_deleted = 0` 过滤条件**
3. **删除方法需要改为更新 `is_deleted` 字段**
4. **OSS 文件不会自动删除，需要定期清理或保留**
5. **建议在测试环境充分测试后再部署到生产环境**
