# FaFa 微信小程序开发规划

> 状态：待产品确认，当前文档只定义实施方案，不包含小程序代码变更。  
> 规划基准：产品文档、Java 后端接口模块、`fafa-app-design` 中的主原型。  
> 编制日期：2026-10-07

## 1. 目标与规划结论

本项目采用微信原生小程序技术栈，按产品主流程分阶段交付。界面以现有 Warm Sage 原型为视觉基准，将 HTML 原型的页面层级、布局、配色、控件状态和交互映射到 WXML、WXSS 与小程序原生 API；原型中的演示数据替换为 Java 后端数据。项目通过统一的 `config.js` 管理服务环境、接口路径、请求策略和路由等静态配置，业务参数由各领域 service 组装。

实施目标：

1. 覆盖已设计的 38 个页面，落地四个主 Tab 和六个业务分包。
2. 按后端已有 REST 接口分域封装服务，覆盖登录、宠物、日常照护、喂养、相册、医疗、提醒、AI、家庭协作与费用等流程。
3. 在开发首阶段补齐小程序运行骨架、统一请求层、认证、导航和设计令牌，再逐个打通业务纵向流程。
4. 适配 iPhone 与 Android 的不同屏宽、状态栏、底部安全区、键盘和长内容滚动。
5. 将无原型页面、接口契约差异、尚未接通的支付/推送能力作为明确的产品决策项，不伪装成已经具备的能力。

## 3. 技术选型

| 层次 | 选型 | 用途与理由 |
|---|---|---|
| 小程序客户端 | 微信原生小程序：WXML、WXSS、JavaScript（ES 模块按开发者工具构建配置） | 原生能力覆盖微信登录、文件上传、分享、导航和授权；避免为了单端小程序引入额外跨端运行时。 |
| IDE/调试 | 微信开发者工具、真机预览与体验版 | 验证小程序路由、基础库能力、合法域名、iOS/Android 安全区和微信交互。 |
| 页面布局 | Flexbox 为主、少量 Grid；尺寸优先使用 `rpx`，文本保留合适的系统字体回退 | 对应 375px 原型宽度并适配主流屏宽；避免将 Web 页面布局假定直接带入 WXSS。 |
| 组件 | 原生自定义组件 | 共享顶栏、宠物选择、提示、空态、底部安全区等；保持轻量并符合小程序生命周期。 |
| 图标/图片 | 仓库内静态 SVG/PNG 等本地资源，必要时将 SVG 转为受支持的本地图像资源 | 不运行时依赖 CDN；控制资源可用性与首屏加载。 |
| 图表 | 小型趋势图优先用 Canvas 2D 自绘组件；静态比例图可用 WXSS | 避免为少量体重/统计图表引入重型图表库；封装坐标、空数据和无障碍文本。 |
| 网络 | `wx.request`、`wx.uploadFile` 的统一薄封装 | 与现有 REST API 对接；统一 token、错误、超时、重试边界与上传处理。 |
| 服务端 | 现有 Spring Boot 3.5 / Java 21 REST 服务 | 小程序只连接公开 Java 接口；Python AI 服务继续由 Java 后端内部调用。 |

原型中的 webview、HTML/CSS 和组件库 CDN 不作为主实现架构。所有静态图像、字体和图标要先核查使用许可、体积、清晰度和小程序支持情况。

## 4. 目录结构设计

建议保留仓库根目录现有微信开发者工具项目配置，并将其 `miniprogramRoot` 指向 `fafa-miniapp/`；在该目录内建立小程序应用文件。这样 Java、Python 后端继续留在当前仓库，前端构建与运行边界清晰。

```text
D:\dev\Java\FaFa\
├─ project.config.json              # 微信开发者工具项目配置；miniprogramRoot=fafa-miniapp/
├─ project.private.config.json      # 本机私有开发设置，不提交密钥
├─ fafa-miniapp/
│  ├─ app.js
│  ├─ app.json                       # 页面注册、分包、窗口、权限描述
│  ├─ app.wxss                       # 全局设计令牌、基础排版、通用辅助类
│  ├─ config.js                      # 唯一静态配置入口：环境、接口、请求、路由等
│  ├─ sitemap.json
│  ├─ custom-tab-bar/
│  │  ├─ index.js / index.json / index.wxml / index.wxss
│  ├─ pages/                         # 主包：登录 + 四个 Tab 页
│  │  ├─ login/index.{js,json,wxml,wxss}
│  │  ├─ home/index.{js,json,wxml,wxss}
│  │  ├─ album/index.{js,json,wxml,wxss}
│  │  ├─ chat/index.{js,json,wxml,wxss}
│  │  └─ me/index.{js,json,wxml,wxss}
│  ├─ packages/
│  │  ├─ pet/pages/                  # 宠物档案、标签
│  │  ├─ daily/pages/                # 打卡、历史、体重
│  │  ├─ feeding/pages/              # 喂养、食物、识别、换粮
│  │  ├─ media/pages/                # 上传、照片详情、搜索
│  │  ├─ medical/pages/              # 就诊、用药、提醒、健康时间线
```

页面文件采用每页一个目录和标准四件套。公共视图状态使用组件；跨页面的业务规则放 `services/` 或 `behaviors/`，避免页面间互相引用。当前宠物 ID 等临时业务状态通过轻量 store 管理，持久化 token 等认证信息使用小程序本地存储；服务端仍是数据真源。

## 6. 公共组件划分

### 6.1 设计与导航组件

- `custom-tab-bar`：四个 Tab 图标、选中态、切换行为与安全区背景。
- `nav-bar`：返回/标题/右侧操作，自适应状态栏和胶囊按钮区域。
- `safe-bottom`：底部固定操作区的安全区占位与间距。
- `icon`：统一本地线性图标尺寸、颜色和可访问文本。
- `chip`：宠物标签、过滤条件和轻量状态标签。
- `pet-picker`：家庭宠物切换器；无宠物、单宠物、多宠物状态一致。

### 6.2 通用业务组件

- `empty-state`：空列表、无搜索结果、无权限/无宠物等不同文案与 CTA。
- `loading`/`skeleton`：首屏和局部加载，保留布局避免跳动。
- `error-state`/`toast`：可重试错误与轻提示；不展示原始堆栈或内部错误。
- `confirm-dialog`：删除、退出、覆盖等不可逆操作的二次确认。
- `image-picker`/`media-preview`：图片选择、预览、上传进度和失败重试。
- `date-picker`、`form-field`、`upload-list`：统一表单标签、校验错误和辅助说明。
- `quota-hint`、`permission-gate`：展示服务端配额或权限限制，组件只控制展示，后端仍执行最终授权。
- `disclaimer`：AI、健康预警、报告和食品安全分值旁的限制说明。
- `trend-chart`：体重趋势等小型图表，支持空数据和触屏读数。

在原型同名组件/资产存在时优先复用；由于当前小程序源码目录为空，具体实现前须从设计源与已有图像资产重新核对文件格式、尺寸和授权。

## 7. 后端接口对接方案

### 7.1 配置入口 `fafa-miniapp/config.js`

这是小程序客户端唯一的静态配置入口，至少集中管理：

- 环境选择和不同环境的 `apiBaseUrl`（开发/测试/生产）；发布环境只使用已备案、可通过 HTTPS 访问并已配置到小程序后台的域名。
- 公开 Java REST 接口路径常量；兼容 `/auth`、`/user` 与大多数 `/api/...` 接口前缀。
- 默认请求头、请求/上传超时策略、单次认证恢复上限、分页默认值与上传大小提示。
- 页面路由名、Tab 页集合和通用请求策略开关。
- 产品可调的非敏感常量，如页面分页大小；实际限制/权益优先通过服务端 quota 接口读取。

不把 AppSecret、服务端 token、COS 长期密钥、生产凭据或任何私密配置放进小程序包。接口参数由领域 service 按具体 DTO 构造，不把用户输入或动态业务数据写进全局 config。

### 7.2 服务层及代表性接口

页面只调用领域 service，不直接拼接 URL 或自行处理 token。建议按后端领域拆分 `auth`、`user`、`pet`、`daily`、`weight`、`feeding`、`food`、`media`、`medical`、`reminder`、`chat`、`report`、`expense`、`family`、`quota` 等 service。

| 领域 | 主要接口范围 | 对应页面 |
|---|---|---|
| 登录/用户 | `wx.login()` code -> `POST /auth/wechat/login`；`/auth/logout`；`GET /user/me`、`PUT /user/profile`、`POST /user/avatar` | 登录、个人资料、我的 |
| 宠物/权限 | `/api/pets` CRUD、标签 `/api/tags`、宠物访问 `/api/pets/{petId}/access`、邀请接受 `/api/pet-invitations/accept`、配额 `/api/quota` | 宠物列表/编辑/详情/标签、家庭、邀请、首页 |
| 日常/体重 | `/api/daily-records`（按日读取/更新、复制上次、全正常等）；`/api/weight-records`（新增、最新、趋势、删除） | 打卡、历史、体重录入/趋势 |
| 喂养/食品 | `/api/feeding-plans`、`/api/feeding-records`、`/api/feeding-analysis`；`/api/foods`、安全评分、`/api/foods/recognitions`、`/api/food-transitions` | 今日喂养、计划、分析、食物库、识别、换粮 |
| 照片/媒体 | `POST /api/photos/upload` multipart；`/api/photos/search`；`/api/photos/{id}` 更新、重新分析、确认宠物、删除 | 相册、上传、详情、搜索 |
| 医疗/提醒/事件 | `/api/medical/visits`、附件、时间线、用药计划/记录、`/api/medical/summaries`；`/api/health-alerts`；`/api/reminders`；`/api/event-records` | 医疗、用药、提醒、健康预警、成长时间线 |
| AI | `/api/chat/sessions`、消息、推荐；`/api/reports` 生成/列表/详情/删除；内容草稿/排期 | AI 助手、报告、（待产品确认的）内容页 |
| 家庭/费用/会员 | 宠物成员、邀请、访问审计；`/api/expenses` CRUD、分类、统计；`/user/vip` 相关接口 | 家庭、费用、会员 |

### 7.3 请求、认证和错误处理

1. 登录由小程序调用 `wx.login()` 取得一次性 code，再将 code 发给 Java 后端换取用户态和 Sa-Token；AppSecret 仅由服务端使用。token 按后端约定写入本地安全存储，并由请求层统一写入 `Authorization` 请求头（具体 token 前缀以 `fafa-java` 当前配置/集成为准）。
2. 统一解析 HTTP 状态与 `Result<T>` 业务包装；业务 `code=0` 视为成功。页面收到领域化错误对象后展示可读提示和重试操作，不自行解释后端异常文本。
3. 对约定的 token 过期码（文档当前约定为 1002），请求层只做一次登录态恢复；并发失效请求共享同一个恢复过程，避免重复登录；恢复失败则清理用户态并回登录页。非幂等写入不做自动盲重试。
4. `wx.uploadFile` 单独封装进度、取消/失败态、文件校验和服务器返回解析。产品资料提到照片最大 10MB、视频最大 50MB、单次最多 20 项；上线前需对齐 Java 当前限制、微信端能力和压缩策略，并在选择文件前提示。
5. AI 聊天接口可能同步等待较久（资料中约 45 秒）。页面要显示发送中状态、阻止重复点击、使用 `clientMessageId` 做幂等关联，提供明确超时后的重试/消息状态恢复策略。不要在客户端将超时自动重发成新消息。
6. 根据 `/api/pets/{petId}/access` 返回的权限集合控制入口显示，并处理服务端拒绝；不能只依据“主人/成员/照护者”角色字符串作客户端授权判断。配额、会员容量和搜索/识别额度优先请求 `/api/quota`，不从页面硬编码宣传值。
7. 后端统一回包、DTO 字段与部分产品文档存在差异风险。每个开发阶段开始前都要以当前 Controller、DTO 和返回样例校验字段、分页、日期/时区、上传字段名和错误码，页面完成后用测试环境接口走通真实数据。

### 7.4 微信平台配置与隐私合规

微信小程序网络请求、上传、下载和 WebSocket 只能使用已配置的服务器域名；普通网络接口采用 HTTPS，域名需符合微信平台要求。小程序不能直接请求 `api.weixin.qq.com` 获取 access token，也不能将 AppSecret 放在客户端。开发前由平台管理员配置并校验服务域名、业务域名（如确实需要 web-view）、隐私保护指引和用户授权说明。见[微信支付小程序场景的服务器配置要求](https://pay.wechatpay.cn/doc/v3/partner/4012088031)。

仅在具体功能需要时申请系统权限；使用前说明用途，拒绝授权后仍提供可理解的替代路径。头像、相册、相机、位置等涉及个人信息的操作按最小必要原则处理，并依据小程序隐私接口清单要求配置授权与撤回入口。照片/健康资料的前端展示遵守服务端访问控制，不把原始文件或用户隐私写入日志。

## 8. 适配与视觉还原策略

- 将原型 375px 画布作为视觉比对基准；使用 `rpx` 表达主要布局与间距，必要时读取窗口尺寸对少数固定元素做适配，不按某一手机的 px 硬编码。
- 安全区：基于设备窗口/安全区信息处理顶部状态栏、右上胶囊、底部 Home Indicator；自定义 TabBar 和固定底部按钮在 iPhone 全面屏、Android 手势导航/虚拟键模式下都留出安全区。提供旧基础库兼容回退。
- 页面滚动：长列表用 `scroll-view`/页面原生滚动；固定操作栏与列表内容分层，确保最后一行不会被 TabBar 或安全区遮挡。
- 键盘：聊天/表单输入按键盘高度调整滚动和焦点位置；避免底部输入栏遮住最后一条消息或提交按钮。
- 动态内容：按系统字体缩放观察标题、按钮、数字和表单；文案允许换行，不用固定高度卡住多语言/长宠物名称。
- 图片：按 DPR 提供清晰资源；优先缩略图，设置宽高和占位图，失败时有本地 fallback。上传前进行类型/尺寸校验，视频预览根据支持能力选择。
- 样式：复用颜色/字号/间距/圆角令牌，逐屏对应原型；纯 CSS 渐变/半透明效果设置不透明 fallback，避免仅依赖毛玻璃等平台差异明显效果。禁用原型依赖的网页 CDN 和浏览器 API。
- 图表和状态标签提供文字摘要；按钮、图标和表单项使用清楚的可读提示和点击区域，重要信息不能只靠颜色区分。

验收时以微信开发者工具模拟器、iOS 真机、Android 真机各检查一次主流程；覆盖窄屏/常见比例、全面屏安全区、键盘弹出、空数据、超长文本、弱网、上传失败和网络恢复。具体机型清单在第一阶段确定后记录到交付验收表。

## 10. 重点风险与待产品确认项

1. **小程序运行基线缺失**：当前小程序入口文件不在工作区；需先确认是否有意删除/是否有其他分支或备份。获批后以现状为准建立基线，不在规划阶段恢复文件。
2. **产品文档与接口可能漂移**：接口前缀不统一，个别请求 DTO 和资料字段名可能变化；每个领域开发前核对 Java 当前实现，必要时在该阶段列接口差异并确认是否需要后端调整。
3. **环境域名未固化**：开发/测试/生产 HTTPS 域名与小程序后台白名单尚需产品/运维提供，不能将 localhost、裸 IP 或本地调试地址作为发布配置。
4. **会员支付**：现有 VIP 接口缺少支付校验，应先做权益只读展示或暂不开放购买按钮；支付范围需后端提供完整下单、回调验签和查询闭环后另行纳入。
5. **提醒推送**：现有能力是占位/服务端日志，不等于微信订阅消息推送；若产品要系统通知，需要增加订阅消息模板、用户授权和后端发送闭环。
6. **无原型新增流程**：邀请接受、急救卡、医疗摘要和内容排期需产品确认首发范围；建议先确定页面行为和字段，再按现有视觉系统补足原型。
7. **AI/健康信息边界**：聊天、报告、健康提醒和食品安全评分都需在适当位置说明局限，不能承诺诊断、认证或治疗效果。
8. **隐私与密钥**：仓库文档/开发配置可能包含敏感项；实施时不将任何后端密钥复制到 `config.js`、小程序包或日志，发布前轮换已暴露的凭据由服务端/运维单独处理。
