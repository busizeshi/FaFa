# 阶段五：提醒系统 - 实现文档

## 一、实现概述

### 1.1 实现目标
实现提醒的创建、查询、完成，以及定时推送功能，支持重复提醒自动生成下一次。

### 1.2 技术架构
- **Java 服务**：提醒 CRUD、定时任务、微信订阅消息推送
- **Python 服务**：提醒数据查询接口（供 AI 使用）
- **数据库**：MySQL reminder 表
- **定时任务**：Spring @Scheduled
- **消息推送**：微信小程序订阅消息

### 2.3 应用服务层

#### 2.3.1 ReminderApplicationService
**文件路径**: `com.fafa.application.service.ReminderApplicationService`

**核心功能**:

   - 验证归属
   - 返回完整信息

4. **更新提醒**: `updateReminder(Long userId, Long reminderId, UpdateReminderRequest request)`
   - 验证归属

5. **删除提醒**: `deleteReminder(Long userId, Long reminderId)`
   - 验证归属
   - 删除记录

6. **完成提醒**: `completeReminder(Long userId, Long reminderId, CompleteReminderRequest request)`
   - 标记完成

7. **取消提醒**: `cancelReminder(Long userId, Long reminderId)`

8. **统计提醒数量**: `countReminders(Long userId, Long petId, String status)`

**重复提醒逻辑**:
```java
private LocalDateTime calculateNextRemindTime(Reminder reminder) {
    LocalDateTime currentTime = reminder.getRemindTime();
    String repeatType = reminder.getRepeatType();
    
    switch (repeatType) {
        case "daily":
            return currentTime.plusDays(1);
        case "weekly":
            return currentTime.plusWeeks(1);
        case "monthly":
            return currentTime.plusMonths(1);
        case "custom":
            // 解析 repeatConfig JSON
            // 例如: {"weekdays": [1, 3, 5]} 表示每周一、三、五
            return calculateCustomNextTime(currentTime, reminder.getRepeatConfig());
        default:
            return null;
    }
}
```

#### 2.5.1 ReminderScheduledTask

**两个定时任务**:

1. **扫描待推送提醒（每5分钟）**:
```java
@Scheduled(cron = "0 */5 * * * ?")
@Transactional
public void scanPendingReminders() {
    LocalDateTime now = LocalDateTime.now();
    LocalDateTime endTime = now.plusHours(1); // 查询未来1小时内
    
    List<Reminder> reminders = reminderRepository.findPendingNotifications(now, endTime);
    
    for (Reminder reminder : reminders) {
        try {
            pushReminder(reminder); // 推送提醒
        } catch (Exception e) {
            log.error("推送提醒失败，reminderId: {}", reminder.getReminderId().getValue(), e);
        }
    }
}
```

## 五、核心业务流程

### 5.1 创建提醒流程
1. 用户调用 `POST /api/reminders` 接口
2. Controller 获取当前用户 ID
3. ApplicationService 验证 petId 归属
4. 创建 Reminder 聚合根
5. 保存到数据库
6. 返回提醒 ID

### 5.2 完成提醒流程
1. 用户调用 `PUT /api/reminders/{id}/complete` 接口
2. Controller 获取当前用户 ID
3. ApplicationService 验证提醒归属
4. 调用 `reminder.complete()` 标记完成
5. **判断是否为重复提醒**:
   - 如果是，计算下一次提醒时间
   - 创建新的 Reminder 聚合根
   - 保存到数据库
6. 返回成功

### 5.3 定时推送流程
1. 定时任务每5分钟执行一次
2. 查询未来1小时内待推送的提醒（状态为 pending，未通知，时间在范围内）
3. 遍历提醒列表：
   - 获取用户 openid（通过 userId 查询）
   - 获取宠物信息（通过 petId 查询）
   - 调用微信订阅消息 API 推送
   - 标记 `is_notified = 1`
4. 记录日志

### 5.4 重复提醒计算逻辑

#### 5.4.1 daily（每天）
```java
return currentTime.plusDays(1);
```

#### 5.4.2 weekly（每周）
```java
return currentTime.plusWeeks(1);
```

#### 5.4.3 monthly（每月）
```java
return currentTime.plusMonths(1);
```

#### 5.4.4 custom（自定义）
解析 `repeatConfig` JSON，例如：
```json
{
  "weekdays": [1, 3, 5]  // 每周一、三、五
}
```

计算下一个符合条件的日期。

## 六、技术要点

### 6.1 DDD 领域驱动设计
- 使用聚合根（Reminder）封装业务逻辑
- 使用值对象（ReminderId）表示标识
- 使用仓储模式（ReminderRepository）隔离数据访问
- 使用应用服务（ReminderApplicationService）编排业务流程

### 6.2 定时任务
- 使用 Spring `@Scheduled` 注解
- 每5分钟扫描一次待推送提醒
- 查询范围：未来1小时内
- 事务保证：使用 `@Transactional` 注解

### 6.3 微信订阅消息
- Access Token 缓存到 Redis，提前5分钟过期
- 消息发送失败记录日志，不影响其他提醒
- 使用 Hutool 的 HttpUtil 和 JSONUtil

### 6.4 重复提醒
- 完成提醒时判断 `repeatType`
- 根据不同类型计算下一次时间
- 自动创建新提醒记录
- 新提醒的 `is_notified` 为 0
