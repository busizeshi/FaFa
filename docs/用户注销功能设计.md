# 用户注销功能设计方案

## 设计理念

采用**软删除 + 冷静期**机制，在用户体验和数据安全之间取得平衡。

## 核心特性

### 1. 冷静期机制（7天）
- 用户申请注销后，账号进入"待注销"状态
- 在 7 天内，用户可以随时取消注销，恢复账号
- 7 天后，定时任务自动清理过期的待注销用户数据

### 2. 自动恢复
- 如果用户在冷静期内重新登录，系统自动恢复账号为正常状态
- 无需手动操作，提升用户体验

### 3. 状态流转

```
正常(NORMAL) ──注销申请──> 待注销(PENDING_DELETION) ──7天后──> 软删除
       ↑                              │
       └──────────登录/手动恢复─────────┘
```

## API 接口

### 1. 申请注销
```http
DELETE /user/account
Authorization: Bearer {token}
```

**响应**
```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

### 2. 取消注销（恢复账号）
```http
POST /user/account/restore
Authorization: Bearer {token}
```

**响应**
```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

## 数据库变更

### 1. user 表新增字段
- `deletion_requested_at`: 注销请求时间（DATETIME）
- `status`: 扩展状态枚举，新增 2-待注销

### 2. 索引优化
```sql
CREATE INDEX idx_status_deletion_time ON user (status, deletion_requested_at);
```

## 定时任务

**执行时间**: 每天凌晨 2:00

**任务内容**:
1. 查询所有 `status=2` 且 `deletion_requested_at <= NOW() - 7天` 的用户
2. 删除用户的所有数据：宠物、照片、记录、提醒等
3. 软删除用户记录（`deleted=1`）

## 实现细节

### 1. 用户状态枚举
```java
public enum UserStatus {
    DISABLED(0, "禁用"),
    NORMAL(1, "正常"),
    PENDING_DELETION(2, "待注销");
}
```

### 2. 领域模型方法
```java
// User.java
public void requestDeletion()  // 申请注销
public void cancelDeletion()   // 取消注销
public boolean isPendingDeletion()  // 是否待注销
```

### 3. 登录时自动恢复
```java
if (user.isPendingDeletion()) {
    log.info("用户在注销冷静期内重新登录，自动恢复账号");
    user.cancelDeletion();
}
```

## 优势

1. **防止误操作**: 7天冷静期给用户反悔的机会
2. **用户友好**: 重新登录自动恢复，无需联系客服
3. **数据安全**: 软删除机制，可追溯历史
4. **合规性**: 符合用户数据管理的最佳实践

## 测试建议

### 测试场景 1: 申请注销
1. 调用 `DELETE /user/account`
2. 验证用户状态变为 `PENDING_DELETION`
3. 验证 `deletion_requested_at` 字段已设置

### 测试场景 2: 重新登录自动恢复
1. 申请注销后重新登录
2. 验证用户状态恢复为 `NORMAL`
3. 验证 `deletion_requested_at` 字段被清空

### 测试场景 3: 手动恢复
1. 申请注销后调用 `POST /user/account/restore`
2. 验证用户状态恢复为 `NORMAL`

### 测试场景 4: 定时任务清理（建议在测试环境验证）
1. 修改冷静期为 1 分钟（仅测试用）
2. 申请注销并等待定时任务执行
3. 验证用户数据被软删除

## 注意事项

1. **冷静期调整**: 如需修改冷静期天数，修改 `UserDeletionScheduler` 中的 `.minusDays(7)`
2. **定时任务时间**: 如需修改执行时间，修改 `@Scheduled(cron = "0 0 2 * * ?")` 的 cron 表达式
3. **通知机制**: 建议在注销申请时发送通知（短信/邮件），提醒用户冷静期和恢复方式
