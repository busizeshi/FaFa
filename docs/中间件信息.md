#### Nacos 配置文件与配置项

Nacos 容器的部署配置由服务器 `/home/busizeshi/docker/middleware/docker-compose.yml` 管理，仓库对应模板为 [`middleware.yml`](../deploy/docker-compose/middleware.yml)。该服务以 `standalone` 模式运行，外部 MySQL `nacos_config` 保存 Nacos 配置数据；服务注册由 Nacos 运行时管理。服务器目录 `middleware/nacos/data`、`middleware/nacos/logs` 分别挂载到容器 `/home/nacos/data`、`/home/nacos/logs`。Compose 没有额外挂载自定义的 Nacos `application.properties`，启动参数通过 Compose 环境变量传入，敏感值从服务器私有文件 `/home/busizeshi/docker/middleware/.env.middleware` 读取。

| 配置项 | 当前设置/作用 | 来源 |
|---|---|---|
| 运行模式 | `MODE=standalone`；MySQL 平台，数据库 `nacos_config` | `middleware.yml` 的 `fafa-nacos.environment` |
| 数据库连接 | 主机 `mysql:3306`（Compose 网络）；用户 `nacos`；数据库连接参数在 `MYSQL_SERVICE_DB_PARAM` | Compose 环境变量；数据库密码由 `NACOS_DB_PASSWORD` 注入 |
| 认证 | 控制台/API、管理员认证均开启；token 和身份校验键值从环境文件注入 | `NACOS_AUTH_ENABLE`、`NACOS_AUTH_ADMIN_ENABLE`、`NACOS_AUTH_CONSOLE_ENABLE`、`NACOS_AUTH_TOKEN`、`NACOS_AUTH_IDENTITY_KEY`、`NACOS_AUTH_IDENTITY_VALUE` |
| JVM 与时区 | `Xms=512m`、`Xmx=512m`、`Xmn=256m`；`Asia/Shanghai` | `JVM_XMS`、`JVM_XMX`、`JVM_XMN`、`TZ` |
| 端口 | 控制台 `8080`、HTTP API `8848`、gRPC `9848`/`9849` | Compose 端口映射 |
| 持久化 | 配置数据保存在外部 MySQL；本机挂载 Nacos data 与 logs | `./nacos/data`、`./nacos/logs` |

Nacos 应用已切换到专用 `fafa` 命名空间，配置分组为 `FAFA_GROUP`。Data ID 文件保存在仓库 [`docs/nacos`](nacos/README.md)，文件名就是 Data ID；修改文件后仍需在 Nacos 控制台/API 发布对应配置，单改本地文件不会更新服务器。

| Data ID | 仓库配置文件 | 使用方 | 当前用途 |
|---|---|---|---|
| `common.properties` | [`common.properties`](nacos/common.properties) | Gateway、Admin、Biz | 通用 Spring 配置、健康检查、共享数据库/Redis 地址与连接池参数；不含账号密码 |
| `fafa-gateway.properties` | [`fafa-gateway.properties`](nacos/fafa-gateway.properties) | Gateway | 监听端口和 Admin、Biz、Python 下游地址 |
| `fafa-admin.properties` | [`fafa-admin.properties`](nacos/fafa-admin.properties) | Admin | 独立管理库连接、Dubbo、后台策略 |
| `fafa-biz.properties` | [`fafa-biz.properties`](nacos/fafa-biz.properties) | Biz | 业务库、Redis、SMTP、Dubbo、认证和业务策略 |

各服务的唯一 Nacos 引导文件是本地 `application.yml`：它只提供服务名、Nacos 地址/认证/namespace 和 `common.properties` 加本服务 Data ID 的必需导入。Java Properties 配置刷新仍开启。namespace 默认 ID 为 `fafa`，若 Nacos 控制台显示的 ID 不同，应通过 `NACOS_NAMESPACE` 注入实际 ID。数据库、Redis、SMTP、HMAC 和 RPC 密码通过应用运行环境注入；不要把明文凭证写进 Nacos Data ID 或仓库。

#### RabbitMQ 配置文件与配置项

RabbitMQ 部署配置由服务器 `/home/busizeshi/docker/middleware/docker-compose.yml` 管理，仓库对应模板为 [`middleware.yml`](../deploy/docker-compose/middleware.yml) 中的 `fafa-rabbitmq` 服务。目前没有单独的 `rabbitmq.conf`、`advanced.config` 或 `definitions.json` 文件挂载到容器；启动配置来自 Compose 环境变量，其余使用该镜像的默认配置。

| 配置项 | 当前设置/作用 | 来源 |
|---|---|---|
| 镜像、主机名 | `rabbitmq:4.3.6-management`；容器名/主机名 `fafa-rabbitmq` | Compose `fafa-rabbitmq` |
| 初始账号 | 用户 `fafa`；密码由 `RABBITMQ_PASSWORD` 注入 | 服务器 `.env.middleware`，不在仓库模板保存真实值 |
| 初始 vhost | `/fafa` | `RABBITMQ_DEFAULT_VHOST` |
| 端口 | AMQP `5672`；管理台/API `15672` | Compose 端口映射 |
| 数据与日志 | 宿主机 `middleware/rabbitmq/data` → 容器 `/var/lib/rabbitmq`；另映射 `middleware/rabbitmq/logs` → `/var/log/rabbitmq`。镜像默认日志也可通过 Docker 容器日志查看 | Compose bind mount |
| 健康检查 | 每 15 秒执行 `rabbitmq-diagnostics -q ping`，超时 5 秒，最多重试 10 次 | Compose `healthcheck` |
| 时区、重启 | `Asia/Shanghai`；`unless-stopped` | `TZ`、`restart` |

注意：官方镜像的 `RABBITMQ_DEFAULT_USER`、`RABBITMQ_DEFAULT_PASS` 和 `RABBITMQ_DEFAULT_VHOST` 仅在 RabbitMQ 数据目录首次初始化时创建账号/vhost。现有数据目录已持久化，之后只改 `.env.middleware` 并重建容器不会自动修改已存在账号的密码或 vhost；密码轮换需要在 RabbitMQ 自身的用户管理中执行，并同步更新受控环境文件。若以后需要 `rabbitmq.conf` 或 definitions 文件，应先把文件纳入仓库和部署挂载，再按配置变更流程应用；当前部署没有这些文件。
