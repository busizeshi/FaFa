## 1. 文档目标

本文档定义 FaFa 的自动化测试范围、测试分层、环境、数据、关键用例、执行命令、质量门禁和发布验收标准。

测试目标不是只验证接口能返回 200，而是验证以下完整闭环：

```text
用户登录
  → 宠物档案
  → 日常记录 / 素材 / 提醒 / 医疗 / 食品 / 费用
  → Java 事实查询
  → Python AI 理解与表达
  → 报告、内容草稿、预警和自然语言问答
  → 用户确认后继续沉淀数据
```

自动化测试必须同时覆盖：

- 业务正确性：CRUD、状态机、统计、规则、幂等和数据关联。
- 产品原则：宠物是数据核心、记录成本低、AI 基于真实事实、AI 不越权写入。
- 安全性：认证、资源归属、家庭协同角色和服务间令牌隔离。
- 稳定性：异步分析、回调重试、超时、降级、重复请求和失败恢复。
- 合规边界：健康预警和摘要只能表达已记录事实，不得生成诊断、处方或治疗结论。

## 2. 测试基线与冲突处理

### 2.1 接口基线

自动化测试以当前仓库中的 Controller、Python Router 和 [接口文档.md](D:/dev/Java/FaFa/docs/接口文档.md) 为准。

分阶段计划中早期出现过 `/api/v1/**` 的示例，而当前实际实现使用 `/auth/**`、`/user/**`、`/api/**` 和 `/internal/ai/**`。测试脚本不得继续使用旧的 `/api/v1/**` 地址。

### 2.2 Java 版本基线

分阶段计划描述为 JDK 17，当前 `fafa-java/pom.xml` 的 `java.version` 为 21。自动化执行环境按当前 Maven 配置使用 JDK 21；如果需要降回 JDK 17，必须先统一 `pom.xml`、代码语法和 CI 镜像，再调整测试文档。

### 2.3 测试数据原则

- 测试账号、宠物、素材和业务记录必须使用独立测试数据。
- 不得直接对开发库中的真实用户、真实照片和真实视频执行清理型测试。
- 每个测试运行生成 `runId`，数据库、Redis、对象存储和 Qdrant 资源使用该 `runId` 隔离。
- 测试使用固定时钟或可注入时钟，禁止依赖执行机器当前时间来判断周期和预警。
- 外部 AI 默认使用 Mock/Stub；真实百炼调用只允许在受控联调或夜间回归中执行。

## 3. 系统与测试环境

### 3.1 服务清单

| 组件 | 默认地址 | 测试用途 | 是否允许在 PR 测试中使用真实服务 |
|---|---|---|---|
| fafa-java | `http://localhost:8080` | 用户、宠物、记录、业务事实和公开接口 | 可使用本地测试实例 |
| fafa-python | `http://localhost:8000` | AI、向量、媒体分析和表达层 | PR 使用 Stub；联调使用隔离实例 |
| MySQL 8 | 配置文件地址 | 业务数据、迁移、事务和统计 | 必须是隔离库 |
| Redis | 配置文件地址 | 会话、限流、幂等键和缓存 | 必须使用独立 database 或 key 前缀 |
| MinIO/OSS | 配置文件地址 | 图片、视频、头像和附件 | 使用测试 bucket |
| Qdrant | 配置文件地址 | 宠物三视图、媒体和文本向量 | 使用测试 collection 前缀 |
| RocketMQ | 生产/类生产环境 | 异步投递和消费者链路 | Windows 开发可使用 HTTP 直推替代 |
| 百炼/Qwen | 云端 | 真实视觉、Embedding、Agent 和表达层 | 不作为普通 PR 的必需依赖 |

### 3.2 环境配置要求

当前 `fafa-java/src/main/resources/application-test.yml` 仍指向内网 MySQL、Redis 和 RocketMQ。正式接入自动化测试前，应使用以下任一种方式隔离：

1. 为自动化测试创建独立数据库 `fafa_automation`、独立 Redis database 和独立 MinIO bucket。
2. 通过环境变量覆盖测试地址，不改写开发配置。
3. 使用 Testcontainers 启动 MySQL、Redis、MinIO 和 Qdrant；需要真实消息队列时单独启动测试 RocketMQ。

测试启动前必须输出并校验以下配置，但禁止输出密码、API Key、内部令牌和 Authorization：

```text
SPRING_PROFILES_ACTIVE=test
FAFA_PYTHON_URL=http://localhost:8000
INTERNAL_TOKEN=<automation-only-token>
TEST_DB_NAME=fafa_automation_<runId>
TEST_REDIS_PREFIX=fafa:test:<runId>:
TEST_MINIO_BUCKET=fafa-automation-<runId>
TEST_QDRANT_PREFIX=fafa_automation_<runId>_
```

Python 测试环境至少需要：

```text
JAVA_BASE_URL=http://localhost:8080
INTERNAL_TOKEN=<automation-only-token>
QDRANT_URL=<isolated-qdrant>
DASHSCOPE_API_KEY=<only-for-real-ai-suite>
CONSUMER_ENABLED=false
```

### 3.3 服务健康检查

执行测试前按以下顺序检查：

1. `GET http://localhost:8080/api/ping` 返回 Java 成功响应。
2. `GET http://localhost:8000/health` 返回 Python `status=ok` 或明确可接受的 `degraded`。
3. MySQL 执行 `SELECT 1`，并确认 Flyway 已完成。
4. Redis 可写入和删除测试 key。
5. MinIO 测试 bucket 可创建、上传和删除对象。
6. Qdrant 测试 collection 可创建、写入、查询和删除向量。
7. 若执行异步套件，确认回调地址、内部令牌和消费者模式已经配置。

## 4. 测试分层

### 4.1 L0：静态与契约检查

触发时机：每次提交。

检查内容：

- Java 编译、格式、Maven 依赖和 Flyway 脚本命名。
- Python 模块导入和路由启动。
- Controller/Router 地址与接口文档一致。
- OpenAPI 文档可生成，路径、方法、请求体和响应结构没有重复或冲突。
- 文档中的 JSON 示例可解析。
- 禁止把真实 API Key、数据库密码、Authorization、内部令牌提交到仓库。

### 4.2 L1：领域模型与纯函数单元测试

不启动数据库、Redis、对象存储、Qdrant 或真实 AI，目标是快速验证规则和状态转换。

重点包括：

- 用户会员状态和配额策略。
- 宠物档案校验、数量限制和软删除。
- 每日状态六维度、物种配置、异常维度识别和 `upsert` 规则。
- 喂食、体重、成长事件领域行为。
- 提醒周期计算、完成状态、下次提醒时间和重试状态。
- 健康规则引擎及红黄预警等级。
- 食品安全评分、换粮状态机和喂食计划状态机。
- 费用金额、分类、日期范围和月度/年度统计。
- 报告周期、事实快照版本和内容生成契约。
- 家庭成员、邀请、照护期限、应急资料版本和权限集合。
- Python Agent 意图分类、日期解析、结构化输出和降级响应。

### 4.3 L2：应用服务与适配器集成测试

使用 Mockito、Fake Repository、Mock HTTP 服务或本地中间件，验证应用服务编排，不依赖真实百炼。

重点包括：

- 事务边界和跨表写入。
- Java → Python 的请求字段、超时、错误映射和 TraceId 透传。
- Python → Java 内部事实查询的参数和权限校验。
- 媒体上传后任务投递、回调处理和重复回调幂等。
- 就诊创建后医疗费用自动同步到费用表。
- 提醒完成后生成成长事件和下一次提醒。
- 报告/内容生成失败时返回事实降级结果，不产生半成品脏数据。
- 协同成员变更后共享提醒投递和审计记录。

### 4.4 L3：接口和契约自动化测试

以 `http://localhost:8080` 和 `http://localhost:8000` 的真实 HTTP 服务为对象，逐个执行 [接口文档.md](D:/dev/Java/FaFa/docs/接口文档.md) 中的接口。

每个接口至少验证：

- HTTP 方法和状态码。
- 必要请求头、Query、Path、Multipart 和 JSON 字段。
- 成功响应结构、类型、必填字段和枚举值。
- Java 成功响应的 `code/message/data` 封装。
- Python 原始 JSON 响应和 `X-Trace-Id`。
- 错误响应结构、错误码和不泄漏敏感信息。
- 数据库、对象存储、向量库和审计副作用。

### 4.5 L4：跨服务端到端测试

只覆盖高价值业务链路，不追求把所有接口重复执行一遍。重点是数据是否能从用户操作一路进入事实层、AI 层和展示层。

### 4.6 L5：性能、可靠性和安全测试

在隔离环境执行，不作为每次提交的阻塞项，但必须在发布候选版本前通过：

- 30 天记录查询小于 1 秒。
- 打卡首页数据加载小于 500ms（按 Phase 2 目标）。
- AI 查询、报告生成和食品识别的超时、重试、限流和降级符合配置。
- 重复请求、并发更新、越权访问和令牌泄漏检查通过。

## 5. 测试工具与目录约定

### 5.1 当前可直接复用的基础

- Java：`spring-boot-starter-test`、JUnit 5、Mockito、Spring Test。

- Java 已有领域和应用测试，优先扩展现有包结构，不重建平行领域模型。

## 6. 标准测试数据

### 6.1 账号与角色

| 数据标识 | 角色 | 会员 | 用途 |
|---|---|---|---|
| `user-owner-normal` | 宠物主人 | 否 | 普通配额、宠物数量和权限基线 |
| `user-owner-vip` | 宠物主人 | 是 | VIP 配额、协同成员上限 |
| `user-member` | 长期成员 | 不适用 | 共享查看、记录和非管理操作 |
| `user-caregiver` | 临时照护者 | 不适用 | 限时权限、到期和记录操作 |
| `user-outsider` | 无关用户 | 不适用 | 越权和资源隔离 |
| `user-second-owner` | 另一个宠物空间主人 | 否 | 跨宠物、跨用户隔离 |

每次运行动态生成 token；禁止在测试代码中固定使用真实开发 token。

### 6.2 宠物和事实数据

至少准备以下宠物：

| 宠物 | 类型 | 用途 |
|---|---|---|
| `pet-cat-1` | `cat` | 排尿维度、饮水预警、猫粮和猫三视图 |
| `pet-dog-1` | `dog` | 狗的物种维度、喂食和提醒 |
| `pet-other-1` | 其他 | 默认配置复用和边界值 |
| `pet-outsider-1` | 其他用户 | 越权访问 |

猫宠物至少准备：

- 一条正常每日状态。
- 一条拒食 + 多次呕吐状态，用于红色健康预警。
- 连续两天食欲下降 + 精神低迷，用于黄色预警。
- 连续三天饮水偏多，用于饮水趋势规则。
- 连续两天腹泻和一条漏记日期，用于规则和时间轴。
- 多条喂食记录、至少三条体重记录和至少一条成长事件。

### 6.3 媒体与 AI fixture

准备脱敏且可公开在测试环境使用的 fixture：

- `cat-normal.jpg`：普通照片，验证上传、标签和识别。
- `cat-balcony.jpg`：用于“阳台晒太阳”“逗猫棒”等语义检索。
- `cat-profile-front.jpg`、`cat-profile-side.jpg`、`cat-profile-avatar.jpg`：三视图。
- `cat-play.mp4`：视频素材，验证视频解析、视频向量和文件类型。
- `food-package.jpg`：食品包装图片，验证食品识别草稿。
- `invalid.txt`、超大图片、超大视频：格式和大小限制。

AI fixture 的响应必须包含 `traceId`、模型/提示词版本、结构化字段和降级标识，不能只返回一段无法断言的自然语言。

## 7. Phase 0～10 自动化覆盖矩阵

| Phase | 核心自动化范围 | 关键验收断言 |
|---|---|---|
| 0 用户系统 | 登录、登出、用户资料、头像、会员、配额 | 首次登录自动注册；token 生效/失效；会员续期在原到期时间上追加；配额按普通/VIP区分 |
| 1 宠物档案 | 宠物 CRUD、数量限制、头像、三视图、排序 | 普通用户第 3 只宠物失败；软删除后不可见；三视图任务字段完整；跨用户不可读 |
| 2 日常记录 | 维度配置、每日状态、同上次、一键正常、喂食、体重 | 同宠物同日覆盖；猫狗配置不同；漏记不伪造数据；喂食可一天多条；体重趋势正确 |
| 3 提醒系统 | 创建、周期、今日、完成、暂停、恢复、历史 | 完成后写事件并计算下一次；暂停不出现在待办；周期边界、闰月和月底正确；重复完成幂等 |
| 4 素材与 AI 摄入 | 图片/视频上传、识别、回调、标签、语义搜索、配额 | 视频进入分析链路；回调重复不重复写入；搜索支持宠物/时间过滤；对象与向量清理一致 |
| 5 AI 对话 | 会话、消息、推荐问题、Agent 工具、自然语言记录 | Agent 只读事实；记录解析返回待确认草稿；证据可追溯；模型失败返回降级；不会直接写业务表 |
| 6 健康管理 | 就医、用药、执行记录、预警、摘要 | 用药重复提交幂等；红黄规则准确；就诊费用自动同步；摘要有免责声明；AI 不输出诊断结论 |
| 7 食品饮食 | 食品卡、包装识别、评分、换粮、喂食计划、动态分析 | 识别先草稿后确认；配额生效；归档使用 `PATCH`；建议不直接保存；反应和完成状态正确 |
| 8 养宠记账 | 费用 CRUD、分类、统计、医疗自动同步、Agent 查询 | 月/年统计金额和分类占比正确；医疗费用只同步一次；无权限不能查看他人支出 |
| 9 报告创作 | 周/月/季/年报告、事实快照、内容草稿、周期配置 | 同事实快照复用；降级可读；生成只读事实；内容只生成不发布；配额和任务状态正确 |
| 10 协同上线 | 角色、邀请、限时照护、并发版本、审计、应急卡 | owner/member/caregiver/viewer 权限隔离；邀请一次性；过期失效；审计脱敏；应急资料版本冲突可检测 |

## 8. 各阶段关键自动化用例

### 8.1 Phase 0：用户和会员

| 用例 | 前置 | 操作 | 断言 |
|---|---|---|---|
| `API-P0-01` | 有效微信 code stub | 调用登录两次 | 首次 `newUser=true`，第二次复用用户；token 可调用 `/user/me` |
| `API-P0-02` | 无效 code | 登录 | 返回业务错误；不创建用户、不创建会话 |
| `API-P0-03` | 有效 token | 更新资料和头像 | 资料更新；旧头像对象被清理；新 URL 可访问 |
| `API-P0-04` | 普通用户 | 查询、开通、续费会员 | 状态和到期时间正确，续费不覆盖原到期时间 |
| `SEC-P0-01` | 无 token/过期 token | 调用业务接口 | 返回未认证错误，不返回业务数据 |
| `API-P0-05` | 普通/VIP账号 | 查询 `/api/quota` | 各项上限和使用量符合配置；计数不跨用户污染 |

### 8.2 Phase 1：宠物档案

- 创建宠物必填字段、日期、性别、类型和非法值校验。
- 普通用户创建第 1、2 只成功，第 3 只返回宠物数量配额错误；VIP 不受普通上限影响。
- 修改、详情、列表、排序和逻辑删除形成完整 CRUD；删除后不能通过详情和列表读取。
- 上传三视图时分别验证 avatar/front/side 的对象存储 key 和 Python 请求字段；单张为空时验证“不更新该视图”的语义。
- Python 三视图向量化成功、部分失败和 Qdrant 异常分别验证；失败不得留下半套成功状态。
- `user-outsider` 访问 `pet-cat-1` 的详情、头像和三视图接口必须失败。

### 8.3 Phase 2：日常记录

- `GET /api/daily-records/dimensions?petId=...&species=cat` 与 dog 返回不同维度权重。
- 同一宠物同一日期连续保存两次，数据库只保留一条最新事实。
- `record-normal` 一键生成全正常值；重复调用不产生重复日记录。
- `copy-last` 只复制上一条记录的业务字段，日期必须是目标日期。
- 漏记日期在范围查询中显示为空缺或未记录标识，不能生成默认正常记录。
- 同一天提交多条喂食记录全部保留；更新、删除不影响其他记录。
- 体重趋势按日期升序，`totalChange = latest - first`，空数据和单条数据有稳定响应。
- 用户只能读写自己有权限的宠物记录，成员权限遵循 Phase 10 的最终矩阵。

### 8.4 Phase 3：提醒系统

- 覆盖一次性、每周、每月、每 N 天、每 N 月和每年提醒。
- 测试月末、闰年、跨年、夏令时不适用区域和时区转换边界。
- 完成周期提醒后：写入完成历史、生成成长事件、更新上次完成时间、计算下一次时间。
- 同一个完成请求携带相同幂等键重复提交，不能产生两条完成历史或两个事件。
- 暂停提醒不出现在今日列表；恢复后按原周期继续；删除后历史记录按产品约定保留或不可见。
- 推送失败时按配置重试，达到最大次数后进入失败状态并保留失败原因。

### 8.5 Phase 4：素材库、照片和视频

- Multipart 批量上传使用同一组 tags，文件数量、单文件大小、总配额和 MIME 类型全部校验。
- 图片和视频都必须创建素材记录；`mediaType`、文件名、大小、URL 和状态正确。
- 视频素材必须进入 `video` 分析分支，不能被静默标记为 `skipped`；Python 接收到 `media_type=video` 和可访问的临时 URL。
- Java 投递 Python `/api/photos/analyze` 时验证 `X-Internal-Token`、`X-Trace-Id` 和 `message_id`。
- Python 202 受理、后台成功、AI 失败、回调重复、回调乱序和超时分别验证。
- 识别结果低于阈值进入待确认；用户确认宠物、修正宠物、取消归属后状态、标签和向量 metadata 一致。
- 语义搜索验证自然语言、petId、startDate、endDate、limit、会员配额、无结果和降级结果。
- 删除素材必须同时验证数据库逻辑删除、对象存储清理和向量清理；重复删除可安全返回。
- 普通用户达到每月 AI 检索次数后返回稳定配额错误；VIP 不受普通上限限制。

### 8.6 Phase 5：AI 对话和 Agent

- 会话创建、列表、消息分页、发送、删除和推荐问题的分页/归属验证。
- Agent 调用 Java 内部只读接口时，验证 `userId + petId` 资源归属，不能查询其他用户事实。
- “记录一下今天饮食正常”只返回结构化待确认草稿；在用户未确认前，daily_status、feeding_record 等业务表不得改变。
- “找去年夏天在阳台晒太阳的照片”验证工具调用参数、媒体过滤、证据引用和返回素材。
- 体重、饮食、费用和报告类问题验证回答中的数值来自事实快照，而不是模型臆造。
- 工具超时、工具返回 401、模型不可用、Qdrant 不可用和超过最大工具调用次数时，返回可解释降级结果。
- 生成内容不得包含诊断、处方、治疗结论；医疗问题返回事实摘要和兽医咨询提示。
- Agent 输出 JSON 的 `blocks`、`citations`、`suggestedQuestions`、`recordDraft` 和 `usage` 字段必须通过结构化契约校验。

### 8.7 Phase 6：医疗、用药和健康预警

- 就医档案创建、查询、修改、删除、附件关联和医疗时间线。
- 就诊日期不能晚于今天；日期范围超过配置上限必须失败。
- 固定频次用药计划自动生成提醒；按需用药不自动生成周期提醒。
- 同一计划、同一 `scheduledAt` 重复提交实际用药记录，必须返回同一业务记录而不是新增。
- 用药计划暂停、恢复、完成和删除验证未来提醒处理，历史实际用药记录不被误删。
- 健康规则最少覆盖：
  - 拒食 + 多次呕吐：红色。
  - 食欲下降 + 精神低迷连续两天：黄色。
  - 猫饮水偏多连续三天：黄色。
  - 腹泻连续两天：黄色。
  - 多次呕吐：黄色。
  - 重复跳过/漏记用药：黄色。
- 预警重复评估要更新同一条开放预警，而不是重复创建；已不满足条件的本轮预警按实现约定关闭。
- 就诊费用自动创建费用记录，重试或重复保存不重复记账。
- AI 就诊摘要失败时返回事实摘要；响应必须含免责声明，不能出现诊断、处方和治疗建议。

### 8.8 Phase 7：食品与饮食

- 食品卡创建、列表、详情、更新、`PATCH /api/foods/{id}/archive`、激活和逻辑删除。
- 食品识别任务创建后状态为 pending/running/completed/failed 的转换可追踪。
- 识别结果只能形成草稿；确认后才写入食品卡，拒绝后不创建食品卡。
- 普通用户食品识别达到 5 次/月，VIP 达到配置上限；失败任务是否消耗配额按产品约定固定并测试。
- 安全评分验证蛋白质来源、争议添加剂、钙磷比和宠物适配度边界；评分版本写入响应。
- 换粮计划覆盖创建、列表、详情、反应更新、完成、取消和非法状态转换。
- 喂食建议返回可编辑预览，不得直接写入正式计划；保存后才能出现在今日清单。
- 喂食计划暂停、恢复、完成和今日清单按日期正确；动态分析使用喂食量、体重和时间范围事实。

### 8.9 Phase 8：养宠记账

- 支出金额大于 0、金额上限、币种、分类、日期和备注校验。
- 支出创建、分页查询、详情、更新、逻辑删除、分类和统计。
- 月度统计按 `expenseDate` 的自然月计算；年度统计按自然年计算；边界日期不能串月/串年。
- 分类占比、总额、趋势、空数据、单笔数据和小数精度分别验证。
- 医疗费用自动同步必须具有来源关联和幂等键；修改/删除就诊费用时，自动费用行为符合实现约定。
- Agent 只能读取费用和统计接口，不能通过内部接口创建、修改或删除开支。

### 8.10 Phase 9：报告与内容创作

- 周、月、季、年周期的开始/结束日期和最大范围校验。
- Java 先组装事实快照并保存版本，Python 只负责表达层；快照中不能缺少来源键。
- 同一宠物、周期类型、日期范围和事实版本重复生成时验证复用或幂等策略。
- Python 正常生成、结构化输出不完整、超时、模型异常和降级全部验证。
- 报告查询列表、详情、重新生成和删除；删除后不能继续被 Agent 查询为有效报告。
- 内容草稿只生成标题、正文、话题和素材顺序；不得调用外部平台发布接口。
- 草稿编辑、重新生成和删除验证用户修改内容不被无条件覆盖。
- 周期配置查询、保存、启用、停用和删除；扫描任务重复执行不能重复生成草稿。
- 普通/VIP 报告与内容生成配额分别验证，失败和重复请求的扣次规则固定。

### 8.11 Phase 10：家庭协同和上线质量

- owner、member、caregiver、viewer 四类角色分别验证读取、记录、编辑、成员管理、应急资料和审计权限。
- owner 可邀请 member/caregiver；普通用户成员上限、VIP 成员上限和功能开关分别验证。
- 邀请 token 只返回一次、服务端只保存摘要、过期失败、撤销失败、重复接受失败、跨宠物失败。
- caregiver 到期后立即失去受限权限，不能通过旧 token 或旧会话继续操作。
- 同一邀请并发接受只能成功一次；同一成员并发撤销和写入按最终状态处理。
- 应急资料使用 `version` 乐观锁；旧版本更新返回稳定冲突错误，不覆盖新版本。
- 审计日志验证成功/失败、operatorId、resourceType、resourceId、reason 和时间；禁止出现 Authorization、raw token、完整医疗原文和完整请求体。
- 共享提醒投递验证去重、失败重试、最大重试次数、撤销后停止新投递和历史投递保留。
- 协同功能关闭时，主人旧流程继续工作，成员接口返回文档约定的稳定错误码。

## 10. 通用负向和异常测试

### 10.1 请求层

- 无 `Authorization`、空 token、过期 token、伪造 token。
- Python 无 `X-Internal-Token`、错误 token、缺失 `X-Trace-Id`。
- JSON 空体、非法 JSON、未知字段、字段类型错误、枚举错误、日期错误。
- Path ID 不存在、负数、超大数；Query limit 为 0、负数、超过上限。
- Multipart 缺文件、错误 MIME、空文件、超大文件、重复文件名。

### 10.2 业务层

- 访问其他用户的宠物、媒体、医疗、费用、报告和会话。
- 修改已删除、已归档、已完成、已取消或已过期资源。
- 重复提交、并发提交、重复回调、乱序回调。
- 日期范围倒置、超过配置上限、未来日期和跨时区边界。
- 超过普通/VIP配额、存储空间不足、限流阈值和工具调用阈值。

### 10.3 外部依赖层

- MySQL 事务回滚和连接中断。
- Redis 不可用、锁超时、缓存脏数据和幂等键过期。
- MinIO 上传成功但数据库失败，以及数据库成功但对象上传失败。
- Qdrant 查询超时、collection 不存在、向量维度错误。
- Python 服务 401/500/503、连接超时、结构化响应不完整。
- 百炼调用超时、模型限流、返回敏感或越界文本。
- RocketMQ 投递失败、重复消费和消费后回调失败。

每个异常用例都必须验证：用户可见错误、日志 traceId、数据库状态、重试状态和是否可安全重试。

## 11. 关键端到端场景

### 11.1 `E2E-lifecycle-01`：宠物数据长期闭环

1. 普通用户登录并创建猫宠物。
2. 上传三视图，Mock Python 完成向量化。
3. 保存每日状态、喂食和体重记录。
4. 创建驱虫提醒并完成一次，验证成长事件和下次提醒。
5. 上传图片和视频，等待分析回调，确认素材归属。
6. 创建就医档案、用药计划和实际用药记录。
7. 创建食品卡和换粮计划，保存喂食计划。
8. 记录费用，验证医疗费用同步和月度统计。
9. 生成月报和分享草稿，验证事实来源键。
10. 调用 AI 问“最近有什么变化”，验证答案引用上述事实但不新增业务数据。

验收重点：各模块通过 `petId` 关联；时间轴、报告和 Agent 读到的是同一批事实；任何 AI 调用都没有绕过用户确认写入业务表。

### 11.2 `E2E-media-01`：照片/视频异步分析闭环

```text
上传照片/视频
  → media_asset=pending
  → Java 投递 /api/photos/analyze
  → Python 返回 202
  → Python 视觉分析和 Embedding
  → POST /api/callback/photo-analysis
  → Java 更新识别字段和向量状态
  → 用户确认宠物归属
  → 语义检索命中
```

验证成功、失败、超时、回调重复、回调签名/令牌错误、视频类型、临时 URL 过期和删除清理。

### 11.3 `E2E-health-01`：健康规则和就诊摘要

1. 写入拒食和呕吐事实。
2. 调用立即评估接口。
3. 验证红色开放预警和证据字段。
4. 生成就诊摘要，Mock Python 返回结构化摘要。
5. 使 Python 超时，验证 Java 事实降级。
6. 检查摘要包含免责声明、来源事实和兽医咨询提示。

验收重点：预警由规则引擎产生；AI 只负责表达；不得出现“已确诊”“应使用某药”等结论。

### 11.4 `E2E-collaboration-01`：邀请、临时照护和审计

1. owner 创建 caregiver 邀请。
2. caregiver 接受并读取宠物、写入喂食记录。
3. 校验 `operatorId` 记录为 caregiver。
4. caregiver 到期后再次读取和写入，均被拒绝。
5. owner 撤销成员，验证新共享提醒停止。
6. owner 查询审计日志，验证 token 和敏感请求体已脱敏。

## 13. CI/CD 流水线

### 13.1 Pull Request 阶段

```text
检出代码
  → 静态检查和文档 JSON 校验
  → Java 编译 + JUnit
  → Python unittest
  → Mock 外部依赖的应用服务测试
  → OpenAPI/接口契约校验
  → 上传测试报告
```

PR 阻断条件：

- 编译失败。
- 任一 L1/L2 测试失败。
- 关键 API 契约失败。
- 新增接口没有文档或方法/地址不一致。
- 发现敏感配置、真实 token 或越权漏洞。

### 13.2 Nightly 回归

```text
启动隔离 MySQL/Redis/MinIO/Qdrant
  → 执行 Flyway
  → 启动 Java/Python
  → 执行全量 API 契约
  → 执行 E2E 闭环
  → 执行异步重试和权限矩阵
  → 生成 JUnit/HTML/失败数据快照
  → 清理 runId 资源
```

真实 AI 回归可以单独标记为 `real-ai`，失败时必须区分“业务代码失败”和“外部模型/网络失败”，不能把外部服务波动误判为业务通过。

### 13.3 发布候选版本

必须额外执行：

- 全量接口和权限矩阵。
- 迁移脚本从空库执行和从上一版本升级执行。
- 重复回调、重复消费、并发更新和服务重启恢复。
- 30 天数据查询、报告生成、媒体语义检索和统计性能。
- 敏感日志扫描、错误信息扫描和 AI 合规词扫描。

### 14.1 必须通过

|---|---:|
| 领域模型和纯函数 | 行覆盖率 ≥ 80% |
| 应用服务 | 行覆盖率 ≥ 70%，关键分支 ≥ 80% |
| Controller/API | 每个公开接口至少 1 个成功 + 1 个失败用例 |
| 权限矩阵 | 每个资源至少覆盖允许和拒绝两类角色 |
| 健康规则 | 每条规则覆盖触发、未触发、重复评估 |
| 异步流程 | 成功、失败、超时、重试、重复回调 |

### 14.3 缺陷等级

| 等级 | 定义 | 发布要求 |
|---|---|---|
| P0 | 数据泄漏、越权、重复扣费、无法登录、数据库损坏 | 必须为 0 |
| P1 | 核心闭环失败、AI 越权写入、医疗表达越界、异步数据丢失 | 必须为 0 |
| P2 | 单接口功能错误、统计边界错误、非核心降级异常 | 不得影响主流程，有修复计划 |
| P3 | 文案、日志、非关键展示问题 | 可带入后续版本 |

## 15. 测试报告要求

每次完整测试至少保存：

- `runId`、代码 commit、Java/Python 版本和配置摘要。
- 用例总数、通过、失败、跳过和耗时。
- 失败接口、HTTP 状态、错误码、traceId 和脱敏请求摘要。
- 数据库迁移版本、异步任务 ID、回调次数和最终状态。
- AI 测试的模型名、提示词版本、是否真实调用和降级原因；不得保存完整敏感输入。
- 失败后保留最小复现 fixture，不保留真实用户文件和完整令牌。

建议报告目录：

```text
tests/reports/<yyyyMMdd-HHmmss>-<runId>/
├── junit.xml
├── api-contract.json
├── e2e-summary.html
├── failed-cases.md
├── sanitized-logs/
└── fixtures-used.json
```

## 17. 完成定义

自动化测试体系达到以下状态，才视为测试建设完成：

1. 三份设计/接口文档中的 Phase 0～10 核心功能都有可追踪的自动化用例。
2. 每个公开接口都有成功、参数错误和权限错误测试；关键异步接口额外覆盖超时、重试和重复回调。
3. Java、Python、MySQL、Redis、对象存储和 Qdrant 的测试隔离策略可重复执行。
4. AI 相关测试默认确定性、可离线运行；真实 AI 只作为受控联调套件。
5. 产品核心红线有自动化防护：不越权、不诊断、不自动发布、不绕过用户确认写入。
6. PR、Nightly、发布候选三个阶段都有明确命令、报告和阻断标准。
