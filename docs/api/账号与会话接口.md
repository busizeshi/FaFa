## 查询已发布协议（listLegalDocuments）

接口定义：`GET /api/v1/legal-documents`。按协议类型和可选版本读取已生效的正式发布内容。省略类型时返回各类型最新发布版本。

认证：匿名。成功 HTTP 状态：`200`。

页面关联：`auth.legal`、`auth.welcome`。

- version 必须与 type 一起传；开发夹具不代表正式法律协议。

### 传参 JSON 示例

```json
{
  "query": {
    "type": "TERMS",
    "version": "v1"
  }
}
```

本接口没有 JSON 请求体。上方 `path`、`query` 仅解释路径和查询参数，实际按 URL 传递。

### 传参字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `X-Request-ID` | 请求头 / string | 否 | 安全关联标识，最多 80 位字母、数字、点、下划线、连字符；非法或缺失时生成新值。 |
| `type` | query / string | 否 | 协议类型，TERMS 或 PRIVACY。 |
| `version` | query / string | 否 | 正整数乐观锁版本；写入时提交最近读取的对应资源版本，冲突需重新读取。 |

### 响应 JSON 示例

```json
{
  "code": "0",
  "message": "OK",
  "data": [
    {
      "type": "TERMS",
      "version": "v1",
      "title": "用户服务协议",
      "body": "示意正文；以实际发布文本为准。",
      "contentHash": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "effectiveAt": "2026-10-22T00:00:00Z"
    }
  ],
  "requestId": "example-request-001"
}
```

示例使用虚构标识和凭证，表示一种成功状态；调用时以实际返回的 ID、版本、时间和令牌为准。

### 响应字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | — | 稳定业务编码；成功为字符串 0，失败按 FAFA-* 分支。验证码字段例外，见请求用途。 |
| `message` | string | — | 可展示的安全提示；客户端不得解析消息文本判断业务状态。 |
| `data` | array / null | — | 本接口的业务数据；无返回数据或部分失败时为 null。 |
| `data[].type` | string | — | 协议类型，TERMS 或 PRIVACY。 枚举：TERMS、PRIVACY。 |
| `data[].version` | string | — | 正整数乐观锁版本；写入时提交最近读取的对应资源版本，冲突需重新读取。 |
| `data[].title` | string | — | 已发布协议的标题。 |
| `data[].body` | string | — | 协议正文；以实际发布内容为准。 |
| `data[].contentHash` | string | — | 协议内容摘要，用于核对发布内容。 |
| `data[].effectiveAt` | string | — | 协议生效时刻，UTC ISO-8601。 |
| `requestId` | string | — | 请求关联标识，用于串联 Gateway、服务与审计；不包含敏感凭证。 最大长度 80。 |

## 发送邮箱验证码（createEmailChallenge）

接口定义：`POST /api/v1/auth/email-challenges`。为注册或找回密码创建独立用途的邮件挑战。服务端保存验证码摘要，发送成功后才允许验证。

认证：匿名。成功 HTTP 状态：`202`。

页面关联：`auth.register`、`auth.forgot`。

- REGISTER、RESET_PASSWORD 不可混用；默认 6 位、10 分钟、重发间隔 60 秒、最多 5 次错误。
- 找回不存在邮箱时返回相同结构但不实际发送；SMTP 未配置时，实际需要发信的请求返回 503。
- 响应从不返回验证码。示例验证码仅用于说明 JSON 结构。

### 传参 JSON 示例

```json
{
  "purpose": "REGISTER",
  "email": "owner@example.com"
}
```

### 传参字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `X-Request-ID` | 请求头 / string | 否 | 安全关联标识，最多 80 位字母、数字、点、下划线、连字符；非法或缺失时生成新值。 |
| `purpose` | string | 是 | 验证码用途：REGISTER 注册、RESET_PASSWORD 找回密码。 枚举：REGISTER、RESET_PASSWORD。 |
| `email` | string | 是 | 邮箱，最多 254 字符；服务端去首尾空白并规范化，所有账号入口规则一致。 最大长度 254。 |

### 响应 JSON 示例

```json
{
  "code": "0",
  "message": "OK",
  "data": {
    "challengeId": "55000000-0000-4000-8000-000000000001",
    "expiresAt": "2026-10-22T04:10:00Z",
    "resendAfter": 60
  },
  "requestId": "example-request-001"
}
```

示例使用虚构标识和凭证，表示一种成功状态；调用时以实际返回的 ID、版本、时间和令牌为准。

### 响应字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | — | 稳定业务编码；成功为字符串 0，失败按 FAFA-* 分支。验证码字段例外，见请求用途。 |
| `message` | string | — | 可展示的安全提示；客户端不得解析消息文本判断业务状态。 |
| `data` | object / null | — | 本接口的业务数据；无返回数据或部分失败时为 null。 |
| `data.challengeId` | string | — | 服务端创建的邮件挑战标识，必须与邮箱、用途及验证码对应。 |
| `data.expiresAt` | string | — | UTC ISO-8601 过期时刻；不得按服务器本地时区推断。 |
| `data.resendAfter` | integer | — | 建议再次发送验证码前等待的秒数。 最小值 1。 |
| `requestId` | string | — | 请求关联标识，用于串联 Gateway、服务与审计；不包含敏感凭证。 最大长度 80。 |

### 示例 curl（Bash / Git Bash / WSL）

  --header "X-Request-ID: example-request-001" \

## 验证码注册账号（registerAccount）

接口定义：`POST /api/v1/auth/registrations`。校验协议、邮箱和验证码，在一个数据库事务中创建账号、资料和同意记录并消费挑战；提交后建立移动会话。

认证：匿名。成功 HTTP 状态：`201`。

页面关联：`auth.verify`。

- 密码按 Unicode 码点计数，8—128 个字符，必须同时含字母和数字；不保存确认密码。
- legalVersions 必须恰好包含 TERMS、PRIVACY，版本来自协议查询。
- 账号已提交但会话存储不可用时，仍返回 201，session=null、nextAction=LOGIN；客户端直接进入登录恢复。
- 响应丢失后使用刚设置的密码登录，不重复注册。

### 传参 JSON 示例

```json
{
  "email": "owner@example.com",
  "password": "ExamplePassword123",
  "confirmedPassword": "ExamplePassword123",
  "challengeId": "55000000-0000-4000-8000-000000000001",
  "code": "123456",
  "legalVersions": {
    "TERMS": "v1",
    "PRIVACY": "v1"
  },
  "device": {
    "deviceId": "android-example-001",
    "deviceName": "安卓测试设备"
  }
}
```

### 传参字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `X-Request-ID` | 请求头 / string | 否 | 安全关联标识，最多 80 位字母、数字、点、下划线、连字符；非法或缺失时生成新值。 |
| `email` | string | 是 | 邮箱，最多 254 字符；服务端去首尾空白并规范化，所有账号入口规则一致。 最大长度 254。 |
| `password` | string | 是 | 明文密码仅通过受保护的请求传输，服务端只保存 Argon2id 摘要；移动端新密码为 8—128 码点且含字母和数字。 最大长度 256；最小长度 8。 |
| `confirmedPassword` | string | 是 | 再次输入的新密码，必须与 password 完全一致，不持久化。 最大长度 256。 |
| `challengeId` | string | 是 | 服务端创建的邮件挑战标识，必须与邮箱、用途及验证码对应。 最大长度 36。 |
| `code` | string | 是 | 本 challenge 对应邮件中的 6 位数字验证码；示例值不可用于真实环境。 |
| `legalVersions` | object | 是 | 实际同意的协议版本，必须包含 TERMS、PRIVACY 两项。 |
| `legalVersions.TERMS` | string | 是 | 已发布且生效的用户协议版本。 最大长度 64。 |
| `legalVersions.PRIVACY` | string | 是 | 已发布且生效的隐私政策版本。 最大长度 64。 |
| `device` | object | 是 | 本次登录的移动设备摘要。 |
| `device.deviceId` | string | 是 | 客户端持久化的设备标识，必填，最多 100 字符。 最大长度 100；最小长度 1。 |
| `device.deviceName` | string | 是 | 供用户识别的设备名称，必填，最多 100 字符。 最大长度 100；最小长度 1。 |

页面关联：`auth.login`。

- 邮箱统一去除首尾空白并按既有邮箱规范化规则查询。
- 旧设备后续请求返回 FAFA-40102 或撤销相关的 401 编码，应清除会话并进入登录页。

## 退出移动会话（logout）

接口定义：`DELETE /api/v1/auth/session`。撤销当前账号会话代际并退出当前令牌。

认证：移动端 Bearer 令牌。成功 HTTP 状态：`200`。

页面关联：`me.logout`。

- 请求不含 JSON 请求体；需要有效移动端令牌。

### 传参 JSON 示例

```json
{}
```

本接口没有 JSON 请求体或业务参数；实际只发送认证等必要请求头。

### 传参字段说明

| 字段 | 类型 | 必填 | 说明 |

| `Authorization` | 请求头 / string | 是 | `Bearer <实际令牌>`；移动端 Bearer 令牌。 |

### 响应 JSON 示例
