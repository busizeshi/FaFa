## 2. 地址与认证

移动端经 Gateway 使用 `/api/v1`，Gateway 去掉 `/api` 后访问 Biz 的 `/v1`。管理端使用 `/api/admin/v1`，Gateway 去掉 `/api/admin` 后访问 Admin 的 `/v1`。

curl 示例按 Bash/Git Bash/WSL 编写，先设置：

```bash
export FAFA_BASE_URL='http://localhost:8080'
export FAFA_USER_TOKEN='替换为移动登录实际返回的令牌'
export FAFA_ADMIN_TOKEN='替换为管理员登录实际返回的令牌'
```

服务器中间件地址不是业务 API 地址；目前验收脚本使用本机 Gateway `18080`、Biz `18082`、Admin `18081`，脚本退出后关闭自己启动的应用。正式运行端口和网络入口由部署环境决定。

认证头为 `Authorization: Bearer <token>`。移动端与管理端令牌隔离，客户端不传 `X-User-ID`、`X-Operator-ID` 来指定身份。Gateway 清理不可信身份头，业务从自己的认证上下文取身份。生产环境由 TLS 入口承载这些接口。

## 3. 参数、响应与并发

- JSON 字段保持英文标识。未知字段返回 400；不要把尚未实现的头像、初始体重、到期赠送字段提前塞入请求。
- 枚举使用声明的字符串，不能传数字序号；版本等整数不能传小数，服务端不会截断后接受。
- GET 的参数放在 URL；文档中的 `path`、`query` JSON 只帮助解释参数位置，不能作为 GET 请求体发送。
- 成功包装为 `code`、`message`、`data`、`requestId`，成功 `code` 为字符串 `0`。无数据时 `data=null`，集合为空时返回 `[]`。
- `version` 是对应资源自己的正整数版本；宠物、偏好、账号、个人资料、申请、字典的版本互不通用。写入冲突返回 409，重新读取后由用户核对，不能盲目覆盖。
- 标注幂等的请求必须提供 `Idempotency-Key`：1—128 位字母、数字、点、下划线、冒号或连字符。网络结果未知时复用同键同内容；同键不同内容返回 409。幂等成功重放可返回首次结果快照。
- 分页默认 20、上限 100；传 `0` 使用默认值。本期游标按稳定 ID 升序，末页 `nextCursor=null`。不承诺按创建时间排序，也不返回伪造总数。
- 时间戳采用 UTC ISO-8601；日期为 `YYYY-MM-DD`，估算月份为 `YYYY-MM`。宠物日期校验使用用户的 IANA 时区。
- 存储字节通过十进制字符串传输；`available=granted-used-reserved`。初始赠送默认为 0，按部署政策配置；当前赠送为永久空间，暂不支持过期额度、AI 消费、支付或负数调整。
- 详情中的 `null`、未知与数值 0 含义不同。客户端不能把未知出生日期、头像、未审批金额渲染成虚构事实。

## 4. 失败响应

字段校验失败示例：

```json
{
  "code": "FAFA-40000",
  "message": "Request parameters are invalid",
  "data": {
    "fieldErrors": [
      {"field": "nickname", "code": "INVALID_VALUE", "message": "昵称不能为空"}
    ]
  },
  "requestId": "example-request-001"
}
```

上例说明字段结构。实际 `message` 受现有服务安全消息与校验器语言影响，不保证逐字一致；客户端仅按稳定业务码及字段码分支。业务异常的 `data` 也可能为 null，不应强行读取 `fieldErrors`。

| 字段 | 说明 |
|---|---|
| code | 稳定错误码字符串；不使用 message 作为程序分支 |
| message | 不泄露基础设施、密码或验证码的安全说明 |
| data.fieldErrors | 可选字段错误数组 |
| data.fieldErrors[].field | 参数字段路径 |
| data.fieldErrors[].code | 字段错误编码，当前使用 INVALID_VALUE |
| data.fieldErrors[].message | 字段级提示，不包含提交的敏感值 |
| requestId | 向开发/运维报告问题时提供的关联标识 |

| HTTP / 错误码 | 含义及客户端处理 |
|---|---|
| 400 / FAFA-40000 | 参数、日期、物种或字段格式错误，按字段提示修正 |
| 401 / FAFA-40101 | 移动端邮箱或密码不正确 |
| 401 / FAFA-40102、FAFA-40103 | 旧设备会话被替换或撤销，重新登录 |
| 401 / FAFA-40110、FAFA-40111 | 管理员凭证错误或管理会话失效 |
| 403 / FAFA-40300、FAFA-40301 | 缺少权限或业务账号被限制 |
| 404 / FAFA-40400 | 资源不存在或当前账号无权读取；不要据此探测归属 |
| 409 / FAFA-40901 | 邮箱已注册，进入登录恢复 |
| 409 / FAFA-40902 | 协议版本已更新，重新阅读并同意 |
| 409 / FAFA-40910 | 资源版本冲突，重新读取并核对 |
| 409 / FAFA-40911 | 幂等键被用于不同请求内容 |
| 409 / FAFA-40912 | 宠物状态不允许该操作 |
| 409 / FAFA-40913 | 可用存储额度不足 |
| 409 / FAFA-40914 | 操作状态冲突或参数不匹配 |
| 410 / FAFA-41001、FAFA-41002 | 验证码挑战或重置票据过期/失效 |
| 429 / FAFA-42900、FAFA-42910 | 请求或管理员登录过于频繁，遵守 Retry-After |
| 503 / FAFA-50300、FAFA-50301 | 数据库、RPC、Redis 或邮件依赖不可用；保留输入和幂等键，按明确状态重试 |
| 500 / FAFA-50000 | 未预期异常，保留 requestId 排查 |

注册验证码错误还会返回 `FAFA-40001`，密码策略错误为 `FAFA-40002`。重置票据和验证码用途隔离，不能反复尝试或跨用途使用。

## 5. 同步文档的交付流程

1. 新增或变更接口时，同步修改类型、权限、状态机、operationId、pageKey 和测试。
2. 执行 Maven 契约测试，将真实 SpringDoc 导出到各模块 `target/*-openapi.json`。
3. 更新 `deploy/verification/api_examples.py` 的业务示例、定义和业务限制；新增字段必须补充 `document_api.py` 中的中文说明。
4. 在仓库根目录执行：

```bash
python deploy/verification/export_contracts.py
python deploy/verification/document_api.py
python deploy/verification/check_api_docs.py
```

5. 检查每个接口的必填、条件必填、可空、成功和错误分支，并执行适用的真实联调。只有代码、OpenAPI、JSON 示例、中文文档和验证记录同步后，才视为该步交付完成。

Python 文档工具依赖 `PyYAML`；真实联调工具另需 `requests`、`PyMySQL`。工具不会读取或提交真实 API Token；验收临时凭证只存放在 Git 忽略的 `target/wp02-verification/private.json`。
