# 内部调用与运维接口

> 更新日期：2026-10-22。以下能力只用于内网服务与运维，不是安卓 APP 可调用的额外入口。

## 1. Admin → Biz 的业务 RPC

契约为 `com.fafa.common.rpc.AdminBusinessRpc`。Admin 使用自己的认证、RBAC 与审计库；业务读取/写入由 Biz 完成，Admin 数据库账号没有 Biz 库权限。HTTP 调用链为：

```text
管理客户端 → Gateway → Admin 认证/权限
→ 写入 PENDING 审计并提交
→ 签名 Dubbo 调用 → Biz 验签
→ 业务事务 + 唯一操作收据 + 账本 → RPC 返回
→ Admin 审计 COMPLETED → HTTP 响应
```

网络故障时不能推断 Biz 是否已提交，Admin 将审计标记为 `UNKNOWN`。调用方复用原 `Idempotency-Key`、相同目标和请求内容重试，生成相同业务操作 ID；Biz 返回首次事务结果，避免重复赠送。

### 1.1 通用请求 JSON 结构示意

```json
{
  "operatorId": "33000000-0000-4000-8000-000000000001",
  "permission": "QUOTA_WRITE",
  "requestId": "example-request-001",
  "issuedAt": 1792641600,
  "payload": {
    "operationId": "admin:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "userId": "11000000-0000-4000-8000-000000000001",
    "bucket": "STORAGE_BYTES",
    "amount": "1000",
    "reason": "开发测试赠送"
  },
  "signature": "示意值；实际由服务端计算，不能手工填写"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| operatorId | string | Admin 从自身认证上下文取得的管理员标识 |
| permission | string | 方法固定权限；例如 grantQuota 必须为 QUOTA_WRITE |
| requestId | string | 安全请求关联标识，不以它代替幂等操作 ID |
| issuedAt | long | 签发时的 Unix 秒数；Biz 默认允许正负 120 秒时钟窗口 |
| payload | 类型化 record | 与方法一一对应的请求，不接受任意 SQL、脚本或外部 URL |
| signature | string | HMAC-SHA256 签名，绑定方法名、操作者、权限、requestId、时间与完整载荷 |

签名消息是 `RpcAuthentication.SignedContent` 以当前固定的 Jackson 排序配置序列化后的 UTF-8 字节；使用双方注入的 `FAFA_INTERNAL_RPC_SECRET`。时钟窗口、常量时间比较和方法绑定防止串改/跨方法重放；业务写入还依赖数据库操作 ID 去重。密钥至少 32 字符，Admin 与 Biz 必须一致，与验证码 HMAC 密钥分别生成。部署应限制内部 RPC 网络并使用受保护的服务网络/TLS 入口。

### 1.2 通用响应 JSON

```json
{
  "code": "0",
  "message": "成功",
  "status": 200,
  "data": {
    "bucket": "STORAGE_BYTES",
    "granted": "1000",
    "used": "0",
    "reserved": "0",
    "available": "1000",
    "version": 2
  }
}
```

| 字段 | 说明 |
|---|---|
| code | 成功为字符串 0；失败使用稳定业务错误码 |
| message | 安全说明，不返回 SQL、密码或服务原始错误 |
| status | Admin 转换为 HTTP 的状态；不是 Dubbo 网络协议状态 |
| data | 对应方法的类型化结果；业务失败时为空 |

### 1.3 方法和 HTTP 消费方

| RPC 方法 / 接口名称 | payload 字段 | data 类型 / 响应字段 | 权限 | 对应管理 HTTP 接口和 curl |
|---|---|---|---|---|
| breeds / 查询字典 | species、query、cursor、limit、includeInactive | CursorPage：items、nextCursor；item 为 id/species/name/status/version | BREED_READ | [后台查询品种字典](管理端接口.md)：GET /dictionaries/pet-breeds |
| saveBreed / 创建或修改字典 | operationId、id、species、name、status、version；新增 version=null | Breed：id、species、name、status、version | BREED_WRITE | [品种维护接口](管理端接口.md)：POST /pet-breeds、PATCH /pet-breeds/{id} |
| users / 查询用户 | cursor、limit | CursorPage；item 为 id/maskedEmail/nickname/status/version | USER_READ | [查询脱敏用户列表](管理端接口.md)：GET /users |
| user / 查询单用户 | id | UserSummary：id、maskedEmail、nickname、status、version | USER_READ | [查询脱敏用户详情](管理端接口.md)：GET /users/{id} |
| setUserStatus / 修改账号状态 | operationId、userId、status、reason、version | UserSummary | USER_WRITE | [账号状态接口](管理端接口.md)：POST /users/{id}:set-status |
| quotaRequests / 查询申请 | state、cursor、limit | CursorPage；item 为额度申请详情 | QUOTA_READ | [查询额度申请列表](管理端接口.md)：GET /quota-grant-requests |
| decideQuota / 审批申请 | operationId、requestId、approved、amount、reason、version | QuotaRequest：id、userId、bucket、amount、reason、state、grantedAmount、decisionReason、operatorId、version | QUOTA_WRITE | [额度审批接口](管理端接口.md)：POST /quota-grant-requests/{id}:decide |
| grantQuota / 直接赠送 | operationId、userId、bucket、amount、reason | QuotaView：bucket、granted、used、reserved、available、version | QUOTA_WRITE | [直接赠送接口](管理端接口.md)：POST /users/{id}/quota-adjustments |

这些是 Dubbo record 契约，不能编造一个 HTTP URL 用 curl 直接调用。各管理 HTTP 文档已给出完整请求/响应 JSON、逐字段说明和 curl；它们是验收同一实现链的入口。验签失败返回 `FAFA-40310`，客户端不能通过移动端令牌调用这些 RPC。

## 2. 后续媒体模块复用的额度应用端口

`StorageQuota` 是同一 Biz 进程内的 Java 应用服务，不暴露客户端可伪造的预占/结算 HTTP 接口。

| 方法 | 输入说明 | 输出 / 行为 |
|---|---|---|
| view(owner) | 已确认的业务账号 ID | QuotaView；首次读取按配置初始化 |
| reserve(owner, operationId, bytes) | 可信业务用例生成的唯一操作 ID、正整数预占字节 | 账号行锁下检查可用量、增加 reserved、写 RESERVE 流水 |
| settle(owner, operationId, actualBytes) | 实际校验后的真实字节；0 ≤ actualBytes ≤ 预占 | 减少全部本次 reserved、增加 used、写 SETTLE，剩余预占同步释放 |
| release(owner, operationId) | 原预占操作 ID | 取消/过期时释放预占并写 RELEASE；重复释放不重复记账 |
| grant(owner, operationId, amount, operator, reason) | 仅由已有后台幂等用例调用 | 增加 granted 与 GRANT 流水；对外幂等由 AdminBusinessService 的操作收据保护 |

预占重试仅在仍为 RESERVED 且参数一致时返回当前余额；结算后的相同 actualBytes 重试成功，改结算量或跨状态操作返回冲突。操作 ID 全局唯一，已释放操作不能重新预占。每次状态变化与额度、流水在同一事务提交。

预占示意输入为 `{"owner":"用户标识","operationId":"upload:唯一标识","bytes":700}`，结算示意为 `{"owner":"用户标识","operationId":"同一标识","actualBytes":600}`；输出字段与 QuotaView 相同。它们是 Java 参数的解释 JSON，不是可发送的 HTTP 请求，因此没有独立 curl。WP04 接入真实上传、对象核验和删除释放已用空间时，还需补齐资源引用与计量核对，不能只调用 reserve 就宣称上传完成。

## 3. 现有私有连通性接口

以下接口只在服务私有地址可用，Gateway 的 v1 业务路由不转发它们。认证为部署网络的访问边界；不得将服务端口直接作为公网入口。

### 3.1 Biz 存活示例

- 接口名称：Biz 私有存活查询。
- 接口定义：`GET http://127.0.0.1:8082/internal/biz/ping`。
- 传参 JSON：`{}`；没有请求体或业务字段。
- 响应 JSON：

```json
{"code":"0","message":"OK","data":"fafa-biz is UP","requestId":"example-request-001"}
```

响应字段 `code/message/requestId` 与统一包装相同；`data` 为存活描述字符串，不证明数据库、邮件或全部业务功能通过。

```bash
curl 'http://127.0.0.1:8082/internal/biz/ping' --header 'X-Request-ID: example-request-001'
```

### 3.2 Admin 存活示例

- 接口名称：Admin 私有存活查询。
- 接口定义：`GET http://127.0.0.1:8081/internal/admin/ping`。
- 传参 JSON：`{}`；没有请求体或业务字段。
- 响应 JSON：

```json
{"code":"0","message":"OK","data":"fafa-admin is UP","requestId":"example-request-001"}
```

响应字段 `code/message/requestId` 同上；`data` 为 Admin 存活描述字符串。

```bash
curl 'http://127.0.0.1:8081/internal/admin/ping' --header 'X-Request-ID: example-request-001'
```

### 3.3 Admin → Biz 示例 RPC 连通性

- 接口名称：Admin 到 Biz 的示例 RPC 查询。
- 接口定义：`GET http://127.0.0.1:8081/internal/admin/biz-ping`。
- 传参 JSON：`{}`；没有请求体或业务字段。
- 响应 JSON：

```json
{"code":"0","message":"OK","data":{"serviceName":"fafa-biz","status":"UP","checkedAt":"2026-10-22T04:00:00Z"},"requestId":"example-request-001"}
```

`data.serviceName` 为响应服务名称，`data.status` 为示例状态，`data.checkedAt` 为检查时刻；其余字段同统一响应。该接口不替代带签名业务 RPC 的完整验收。

```bash
curl 'http://127.0.0.1:8081/internal/admin/biz-ping' --header 'X-Request-ID: example-request-001'
```

## 4. 健康探针

`/actuator/health/liveness` 用于进程存活，`/actuator/health/readiness` 用于就绪；根 `/actuator/health` 可包含邮件等依赖。当前 SMTP 未部署时 Biz 根健康项可能为 DOWN，不能忽略成全绿，也不能把 liveness=UP 当成真实邮件送达验收。SpringDoc 与健康探针属于框架运维入口，不纳入 40 个业务接口目录。
