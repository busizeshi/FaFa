# 11 消费记账

- 文档日期：2026-10-07
- 对应 Controller：`ExpenseController`（路由前缀 `/api/expenses`）

## 1 模块定位

用户为每只宠物记录日常花钱的项目——猫粮、看病、用品、美容、保险等，系统按分类和日期汇总，回答"这个月在这只宠物身上花了多少、花在哪"。账单有两个人账来源：用户手记的，和就医档案自动生成的；后者跟随就医档案变化，用户不能直接改。所有金额以人民币计，统计口径固定为"未删除的记录"。

## 2 手动记账

### 2.1 用户路径

记账页 → 选宠物 → 选分类 → 填金额、日期、标题（可选备注、关联小票照片、关联食品卡）→ 保存。新建一条账单共 5 步、1 次请求；编辑与删除在账单列表长按或点开后完成，各 1 次请求。

### 2.2 创建与更新

- 创建：`POST /api/expenses`
- 更新：`PUT /api/expenses/{id}`（请求体与创建完全一致，**全量替换**语义：未提交的可选字段视为清空）

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| petId | 是 | 所属宠物；校验归属于当前用户。更新时**不允许变更**，改动报"开支所属宠物不能修改" |
| category | 是 | 分类编码，见第 2.5 节；忽略大小写与首尾空格，非法值报"开支分类无效" |
| amount | 是 | 必须大于 0；上限 1,000,000.00；最多两位小数，超出直接报错不做四舍五入；0.01 为最小合法值 |
| currency | 否 | 缺省按 CNY 处理；填写其他币种报"当前仅支持人民币 CNY" |
| expenseDate | 是 | 开支发生日期，**不能晚于今天** |
| title | 是 | 标题，≤100 字符 |
| notes | 否 | 备注，≤500 字符 |
| receiptMediaId | 否 | 关联小票素材；必须是当前用户名下、且归属同一宠物的素材，否则报"小票素材不存在或不属于当前宠物" |
| foodCardId | 否 | 关联食品卡；必须属于同一宠物，保存时生成食品名称快照供列表展示 |

### 2.3 查询与详情

- 分页列表：`GET /api/expenses?petId&startDate&endDate&category&page&size`。petId、startDate、endDate 必填；category 可选做分类过滤；page 默认 1（小于 1 按 1 处理）；size 默认 20，超出 1~50 范围时夹取。
- 日期范围规则：开始日不得晚于结束日，结束日不得晚于今天，跨度不超过 3660 天，违反任一条报"开支统计日期范围无效"。
- 详情：`GET /api/expenses/{id}`，仅记录归属人可读。

### 2.4 删除

`DELETE /api/expenses/{id}` 仅对手动账单可用；删除后该记录不再出现在列表与一切统计中。

### 2.5 分类清单

`GET /api/expenses/categories` 返回固定 6 个分类，列表与统计均按此顺序排列：

| 编码 | 名称 | 排序 |
| --- | --- | --- |
| food | 食品 | 1 |
| medical | 医疗 | 2 |
| supplies | 用品 | 3 |
| grooming | 美容护理 | 4 |
| insurance | 保险 | 5 |
| other | 其他 | 6 |

## 3 系统生成的医疗支出

### 3.1 自动生成规则

用户在就医档案里填写总费用后，系统自动生成一条对应账单，与就医档案在同一事务内保持一致：

| 项目 | 取值 |
| --- | --- |
| 金额 | 就医档案总费用，自动四舍五入到两位小数；超过单笔上限 1,000,000.00 时同步失败并提示"医疗费用同步失败" |
| 分类 | 固定为 medical，不随用户选择 |
| 日期 | 就医日期 |
| 标题 | `就诊费用 - {医院名}`，超 100 字符截断 |
| 备注 | 固定"由就医档案自动同步" |

### 3.2 不可变性

医疗来源账单对用户**只读**：响应中 `sourceType=medical_visit`、`systemGenerated=true`、`editable=false`；前端应据此隐藏编辑与删除入口。用户尝试 PUT/DELETE 时报"系统生成的医疗开支不可直接修改"（错误码 70006）。要修正金额，去改对应的就医档案。

### 3.3 跟随就医档案自动恢复与消失

自动账单的生命周期完全挂在就医档案上，用户不需要也不能手动补记：

| 就医档案变化 | 自动账单行为 |
| --- | --- |
| 新建且总费用大于 0 | 生成一条医疗账单 |
| 费用/日期/医院名修改 | 同一账单就地更新，不产生新记录 |
| 费用改为 0 或清空 | 对应账单自动删除（从列表与统计消失） |
| 删除就医档案 | 对应账单自动删除 |
| 费用从 0/空改回非 0 | 此前被自动删除的账单**自动恢复**，恢复为原账单而非新建，历史 ID 不变 |

该联动受系统开关 `autoSyncMedical` 控制，当前默认开启。同一就医档案始终只对应一条账单，重复保存不会产生重复记录。

## 4 来源标记

每条账单带三个来源相关字段，供前端区分展示：

| 字段 | manual（手动） | medical_visit（医疗同步） |
| --- | --- | --- |
| sourceType | `manual` | `medical_visit` |
| systemGenerated | false | true |
| editable | true | false |
| medicalVisitId | 空 | 关联的就医档案ID |

列表页可给医疗账单加"自动"角标并禁用编辑删除；点开详情可经 medicalVisitId 跳回就医档案。

## 5 开支统计

### 5.1 用户路径

统计页 → 选宠物 → 切"月/年" →（通常停留在当期）→ 查看总金额、分类占比、趋势图。1 次请求返回全部数据：`GET /api/expenses/statistics?petId&period&anchorDate`，period 默认 month，anchorDate 必填。

### 5.2 锚定日期与周期边界

统计范围由锚定日期 anchorDate 推出，**anchorDate 不能晚于今天**，否则报"统计锚点不能晚于今天"：

| period | 统计范围 |
| --- | --- |
| month | anchorDate 所在月的 1 日至月末 |
| year | anchorDate 所在年的 1 月 1 日至 12 月 31 日 |

范围的结束日取"周期真实月末/年末"与"anchorDate"中较早者。因此把 anchorDate 设为今天查询本月，得到的是"本月 1 日至今天"的账单——系统据此给出数据状态（见 5.5）。

统计只包含当前用户在该宠物下未删除的记录；宠物归属校验失败报"宠物不存在或无权访问"。协同成员的统计可见范围 [待确认]。

### 5.3 分类合计与占比

分类行按固定 sortOrder 排序，只输出有数据的分类。占比 = 分类金额 ÷ 总金额 × 100，四舍五入保留两位小数。逐行独立舍入会出现合计不足或超过 100% 的残差，系统把**全部残差归到最后一个分类**，保证占比合计恰为 100.00。

数值示例一（存在残差）：总金额 30.00，三个分类金额均为 10.00。

| 分类 | 金额 | 逐行舍入占比 | 调整后占比 |
| --- | --- | --- | --- |
| 食品 | 10.00 | 33.33 | 33.33 |
| 医疗 | 10.00 | 33.33 | 33.33 |
| 用品 | 10.00 | 33.33 | **33.34**（吸收残差 +0.01） |
| 合计 | 30.00 | 99.99 | 100.00 |

数值示例二（无残差）：总金额 60.00，分类 10.00 / 20.00 / 30.00 → 16.67 / 33.33 / 50.00，合计恰 100.00，不调整。"尾类"由排序决定而非金额大小决定；用户如需按金额降序展示，占比值不受展示顺序影响。

### 5.4 趋势点

趋势序列由后端补齐零值，前端直接绘图，不需要处理缺失：

| period | 趋势粒度 | 取值范围 |
| --- | --- | --- |
| month | 按日一个点（如 `2026-08-17`） | 统计开始日至结束日逐日生成，无记录的日子金额为 0.00、笔数为 0 |
| year | 按月一个点（如 `2026-08`） | 统计覆盖的每个月一个点，同样含零值月 |

### 5.5 数据状态与口径输出

响应携带三个口径字段，前端应如实展示而不是隐藏：

| 字段 | 取值规则 |
| --- | --- |
| dataStatus | `complete`：统计范围覆盖完整周期；`partial`：anchorDate 落在周期中间，周期尚未结束 |
| limitations | complete 时输出"仅统计未删除的开支记录"；partial 时输出"当前统计周期尚未结束，未来日期不纳入统计" |
| calculationVersion | 统计口径版本号，当前为 `v1`；口径变更时版本递增，历史截图与数据可据此对账 |

partial 状态下趋势图的最后一个点即 anchorDate 当天；前端展示"本月至今"之类的文案时应读取 dataStatus 判断，而非自行猜测周期是否完整。

## 6 用户可见提示与错误码

| 错误码 | 触发场景 | 用户提示 |
| --- | --- | --- |
| 70001 EXPENSE_NOT_FOUND | 账单不存在或不属于当前用户；宠物不存在/无权访问 | 开支记录不存在 / 宠物不存在或无权访问 |
| 70002 EXPENSE_FIELD_INVALID | 金额 ≤0 或超上限、小数超两位、日期晚于今天、标题超长、宠物为空、改宠物、小票/食品卡不匹配 | 按具体校验消息提示，如"金额最多保留两位小数" |
| 70003 EXPENSE_CATEGORY_INVALID | 分类编码不在 6 类之内 | 开支分类无效 |
| 70004 EXPENSE_CURRENCY_UNSUPPORTED | currency 填了 CNY 以外的币种 | 当前仅支持人民币 CNY |
| 70006 EXPENSE_AUTO_RECORD_IMMUTABLE | 编辑或删除医疗来源账单 | 系统生成的医疗开支不可直接修改 |
| 70007 EXPENSE_RANGE_INVALID | 列表或统计的日期范围非法、锚点晚于今天、周期参数非 month/year | 开支统计日期范围无效 |
| 70008 EXPENSE_MEDICAL_SYNC_FAILED | 就医档案费用超单笔上限等原因导致自动同步失败 | 医疗费用同步失败 |
