# FaFa 微信小程序视觉探索

> 2026-10-07 · 三套可交互 HTML demo · 基于现有 `fafa-app-design` 的鼠尾草绿、新魏字体、白色卡片与胶囊控件

## 设计依据

- 产品定位：面向宠物主的生命周期管理，重点是日常健康、喂养与提醒、照片/视频素材、AI 助手。资料来自 `docs/project-analysis.md`、`fafa-java` 接口层及现有 `fafa-app-design`。
- 现有视觉基线：`#5C9E71` 鼠尾草绿、`#F5FAF6` 页面底、`#FFFFFF` 卡片、`#2E3B32` 主文字、`STXinwei/华文新魏` 字体，以及轻阴影和胶囊按钮。新方案延续这些核心特征。
- 真实功能映射：健康页对应日常记录、体重、喂养、驱虫/疫苗提醒；素材页对应照片/视频、分类和语义搜索；AI 页对应宠物绑定会话、带记录来源的回答。demo 中的宠物与数据是演示样例，不连接服务端。

## 三套方向

| 方向 | 气质 | 主要变化 | 适用判断 |
| --- | --- | --- | --- |
| 晴日陪伴 | 温暖、亲近、轻快 | 薄荷绿和杏橘柔和过渡，真实宠物照片做主角 | 建议作为默认方向，健康与日常氛围最平衡 |
| 柔光气泡 | 精致、轻盈、科技感 | 云紫/珊瑚低饱和渐变、局部毛玻璃 | 适合突出 AI 与影像能力，低端机需降级玻璃模糊 |
| 跳跳日记 | 年轻、编辑感、活力 | 更清楚的色块和布局节奏，番茄红/天蓝用于次级强调 | 适合素材与内容表达；医疗信息仍保持克制 |

### 颜色使用比例

- **70% 中性色和留白**：页面底、白卡和文字，让健康数据有秩序。
- **20% 鼠尾草绿**：主操作、选中、正向状态和品牌标记。一个页面最多一个高对比主按钮。
- **10% 辅助色**：提醒、素材标签、AI 渐变等。不能用颜色单独表达健康风险；同时配文案与图标。
- 渐变只放在首页宠物主视觉、健康状态区和 AI 欢迎区。长列表、表单及医疗记录维持纯色，避免阅读干扰。

## 视觉元素与组件规范

| 元素 | 建议 |
| --- | --- |
| 字体 | 三套 demo 统一 `STXinwei, 华文新魏`。标题 28–32px、区块标题 18px、正文 13–14px、辅助信息 11–12px。上线前确认新魏字体的移动端授权与包体方案，并在真机检查中英文数字混排。 |
| 圆角 | 卡片 16–19px，主视觉 21–23px，图标容器 12–17px；按钮/筛选胶囊 `999px`。比现有 4/8/12px 刻度略柔和，但维持同一圆角体系。 |
| 阴影 | 静态卡片轻阴影；仅悬浮导航和主要 CTA 用较明显层级。优先通过留白和底色区分，不做卡片套卡片。 |
| 插画/照片 | 宠物照片为主。新增插画宜采用简洁的柔软轮廓、少量纸张纹理与柔和体积光；与真实照片色温一致。健康页避免卡通化病症表达。 |
| 图标 | 统一 Lucide 风格线性图标，建议 20–22px、约 2px 线宽、圆角端点。绿色为默认强调，辅助色仅出现在对应功能入口。 |
| 爪印/剪影 | 爪印保留在品牌标记、空状态或成功反馈；单屏最多 1–2 处。宠物剪影可做 3–5% 透明度的背景水印，不与记录文本重叠。 |
| 玻璃质感 | 柔光气泡仅在导航、AI 输入区和少量卡片使用 `backdrop-filter`。若客户端不支持，回退到高不透明度白底与实色边框。 |

## 四个核心页面

### 首页

沿用现有顶部品牌与快捷入口，先展示“今天的团子”宠物主视觉，再给健康状态、体重、素材数量三项摘要。四个快捷入口对齐真实高频行为：健康打卡、喂养计划、记录瞬间、问问发发。提醒在首屏下部，避免抢过宠物主视觉。

### 宠物健康页

宠物切换和健康状态在顶部；体重与本周记录提供一眼可读的数字。今日照护清单采用轻分隔行，不堆叠大卡片。提醒用暖色，健康正向状态用绿。异常告警落地时另设明确的红/黄语义色与文字，不要沿用“状态良好”视觉。

### 素材页

自然语言搜索在上，全部/照片/视频的筛选紧随其后，双列影像网格作为内容主角。真实素材优先于插画。视频在角落显示播放标记；上传入口保持清楚。AI 搜索的可用次数与结果状态在真实实现中由配额接口提供，不在视觉稿中虚构。

### AI 助手页

顶部用简短服务说明和三条建议问题降低空白页门槛。对话气泡尺寸克制，回答下方保留“引用记录来源”的小区域；健康相关回答应提供清楚的就医边界。输入区可以用轻玻璃层，但内容气泡保持实色，保证阅读。

## 小程序落地

1. 此处是 HTML 视觉原型。接入原生小程序时，建议把颜色和间距转为全局 WXSS token，复用原有页面结构与接口调用。
2. 现有正式导航是“首页／相册／聊天／我的”。本 demo 为评审四个核心页面，临时采用“首页／健康／素材／发发”四项直达。实际迁移可保留原导航，并由首页快捷入口进入健康页。
3. 把底部导航、按钮和输入区避开设备安全区域；真机检查不同屏宽、微信顶部原生导航、键盘弹出和长文字截断。交互目标建议至少约 44px；此 demo 已将顶部图标按钮调整为 44px。
4. 图片使用现有 `fafa-app-design/assets`；正式发布时压缩尺寸并配合懒加载。渐变、毛玻璃和大图需要在低端安卓设备检查渲染表现。
5. 这批 demo 的“打卡”“搜索”“发送”是本地演示状态。服务端接入应分别对接记录、媒体、聊天与提醒接口，处理加载、空状态、失败和配额信息。
